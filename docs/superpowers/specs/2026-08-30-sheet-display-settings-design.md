## 1. 目的

配置図の表（以下「配置表」）の文字が 10px 固定で、現場で読みにくい。
文字サイズと太字を設定で変えられるようにし、あわせて欄からはみ出す文字を
水平に圧縮して1行に収める仕組みを入れる。

この2つを1件にまとめる理由は、**文字サイズを可変にした時点で圧縮が必須になる**ため。
16px を選べば品名も注釈も欄幅を超える。片方だけでは成立しない。

散らばっている表示まわりの設定も、このタイミングで設定タブに集約する。

---

## 2. 決定事項

ブレインストーミングで確定した方針。

1. **文字サイズは6項目に分ける** — 品名・ロット・P数・注釈・月日・総P。
   モックが同じ構成で現物合わせ済み
2. **太字は4項目** — 品名・ロット・P数・注釈のオン/オフ。月日・総P は対象外
3. **初期値は 品名16 / ロット13 / P数16 / 注釈13px** — モックで現場感に近いと確認済み。
   月日20 / 総P30 は現状維持
4. **注釈も圧縮の対象に含める** — 常に1行に収める。折り返して行が伸びると
   `bd0deea` で決めた「注記行は他の行より低く」が崩れるため
5. **圧縮の下限は 40% 固定** — モックで可読性を確認済み。全セル共通。設定項目にはしない
6. **下限まで縮めても入らない欄は折り返しに落とす** — 情報を欠けさせない。
   画面に警告を出し、紙には出さない。
   **折り返す前に span の幅を `avail / 0.4` へ広げる**（3-7）。広げないと
   欄幅で折り返してから 40% に潰れ、6行・118px の読めない塊になる
7. **文字サイズの上限は 24px** — 32px まで許すと印刷が用紙の147%になる（3-8）。
   それでも用紙をはみ出したら警告を出す
8. **バージョン不一致では既定値へマージする** — 利用者が紙合わせで決めた値なので、
   スペース設定のように丸ごと捨てない
9. **設定タブをサブタブ3枚にする** — 品目マスタ／配置マス／表示設定
10. **表示倍率は配置表タブに残す** — 「今この画面をどう見るか」の操作で性質が違う。
   矢印の先・角の丸み・端数「半」は表示設定へ移す
11. **「満杯時に混載を許可」は入力タブに残す** — 配置アルゴリズムの入力であって表示設定ではない

## 3. 技術制約（実測で確認済み）

### 3-1 `translateX` の補正は不要（メモ 2-5 の記述は表には当てはまらない）

メモ 2-5 は「`transform-origin:left center` に固定し、縮んだぶんを `translateX` で
中央へ戻す必要がある」と書いているが、**これは CSS Grid の `justify-items:center` で
踏んだ話**であり、配置表の `table-cell` ＋ `text-align:center` には当てはまらない。

実測（`td.slot` 実効93px、`エキゾーストマニホールド` @16px、自然幅187.7px）:

| 方式 | 左余白 | 右余白 |
|---|---|---|
| `scaleX(k)` のみ | 2.0 | 1.0 |
| `scaleX(k) translateX(...)` | 48.8 | **-45.8**（右へはみ出す） |

自然幅がセル幅を超えた時点でブラウザは要素を左端基準に置くため、
`transform-origin:left center` の `scaleX(k)` だけで中央に収まる。
縮まない欄（k=1）は通常の中央寄せがそのまま効く（左25.8 / 右26.3）。

**補正を入れてはいけない。**

### 3-2 `zoom` を変えても圧縮率は変わらない

`.sheet` は画面で `--sheet-zoom`、印刷で `zoom:1.4` が掛かる。
実測で `zoom:1` と `zoom:1.4` の k が完全に一致した（どちらも 0.496）。

- `clientWidth` は zoom の影響を受けない CSS px を返す → 使える幅の計算に使う
- `getBoundingClientRect().width` は **zoom 込みの値**を返す。
  `getComputedStyle(sheet).zoom` で割って CSS px に直してから比を取る。
  割らずに `clientWidth` と混ぜると、zoom が 1 でない画面で圧縮率が狂う

したがって **`beforeprint` での再計算は不要**。画面で決めた圧縮率がそのまま紙にも効く。

### 3-3 非表示タブでは幅が測れない

`getBoundingClientRect()` / `clientWidth` は `display:none` の祖先を持つ要素で 0 を返す
（lessons.md 2026-08-23、2026-08-30）。

`run(goMap)` は `showMapState()`（この中で `renderSheet()`）を呼んでから
`switchTab("map")` を呼ぶので、主動線では配置表タブが非表示のまま `renderSheet()` が走る。

**このアプリには既に対処が入っている。** `switchTab()` は

```js
if(name==="sheet"){ if(hasResult) renderSheet(); else applySheetZoom(); }
```

で、配置表タブに来たときに表を描き直す。`fitSheetText()` を `renderSheet()` の末尾に
置けば、この経路で自動的に再計算される。**タブ切替用の特別な呼び出しは要らない。**

ただし `fitSheetText()` 自身にも「幅が 0 なら何もしない」ガードを入れる
（`drawLeaders()` の `if(!base.width) return;` と同じ流儀）。

### 3-4 `@media print` の宣言は `getComputedStyle` で読めない

印刷まわりを検証するときは CSSOM を走査する
（`document.styleSheets` → `CSSRule.MEDIA_RULE` → `conditionText.includes("print")`）。
lessons.md 2026-08-30 の指摘。**検証スクリプトの書き方をこれに統一する。**

### 3-5 computed style に値が入ることは描画の証明にならない

`transform` は computed style に必ず値が入る。実際に縮んで見えるかは
セルの左右余白の実測（対称か）とスクリーンショットで確かめる。
lessons.md 2026-08-23（`border-radius`）の指摘と同型。

### 3-6 日本語は太字でも幅が変わらない

実測: `部品部品部品` @16px は通常も太字も 96.0px。幅が変わるのは数字だけで、
`1111-2222` @13px は 73.0 → 79.4px（+8%）。
圧縮は実測ベースなので自動で吸収されるが、**ロットの太字をオンにすると
圧縮率が下がる**ことは設定のヒントに書く。

### 3-7 折り返す前に span の幅を広げないと6行になる（実測）

`white-space:normal` に戻すだけだと、span は td の幅（93px）で折り返してから
`scaleX(0.4)` で 37px に潰れる。実測（16px 太字、`avail=93px`）:

| 文字列 | 自然幅 | k | セル高 | インク幅 |
|---|---|---|---|---|
| 部品部品部品 | 96.0 | 0.969 | 26px | 93px |
| エキゾーストマニホールド | 188.6 | 0.493 | 26px | 93px |
| …用ブラケット取付台座金具一式（25文字） | 412.6 | 0.400 | **118.2px** | **37.2px** |

セルが 26 → 118px に伸び、表全体では 474 → 566px。印刷で 792px となり
A4 横の 733px を超えて、`page-break-inside:avoid` で表ごと2ページ目へ落ちる。
**情報を守るための処理が、いちばん壊れた見た目を作る。**

対策は1行。`white-space:normal` にする前に、折り返しの基準幅を
**縮めた後にちょうど欄へ収まる幅**へ広げる。

```js
sp.style.width = (avail / FIT_MIN_SCALE) + "px";
```

実測: 2行・41.4px・インク幅 93px（欄いっぱい）。50文字でも2行に収まる。
**ループの先頭で `sp.style.width=""` に戻すこと**（前回の値が残ると自然幅が測れない）。

### 3-8 `autoSheetZoom()` は 1 倍を下回らない

`autoSheetZoom()` は `Math.max(1, Math.floor(s*100)/100)` を返す
（`files/index.html:2409`）。**縮小は一切しない。**
「文字を大きくして表がはみ出しても自動で倍率が下がる」は成り立たない。

文字サイズを振って測った表の高さ（実データ9ロット、`zoom:1`）:

| 設定 | 表の高さ | ×1.4 | A4横 733px に対して |
|---|---|---|---|
| 現行 10px | 470.1 | 658 | 89.8% |
| 初期値（16/13/16/13/20/30） | 474.3 | 664 | 90.6% |
| 注釈だけ 20px | 491.1 | 688 | 93.8% |
| 品名だけ 24px | 504.1 | 706 | 96.3% |
| 全項目 32px | 768.4 | 1076 | **147%** |

品名 25px 前後で 100% を超える。したがって
**文字サイズの上限を 24px にし、それでも用紙をはみ出したら警告を出す**（7-3）。

## 4. 設定タブのサブタブ化

現在の設定タブは2カード構成（品目マスタ `files/index.html:456` 付近、
スペース設定 同 `:470` 付近）。これをサブタブ3枚にする。

| サブタブ | 中身 |
|---|---|
| 品目マスタ | 既存カードをそのまま |
| 配置マス | 既存のスペース設定カードをそのまま |
| 表示設定 | 新規 |

タブの見た目は既存のメインタブ（`.tabs`）とは別物にする。
メインタブと同じ見た目にすると階層が分からなくなるため、小さめのボタン列にする。

既存カードは中身を変えない。**サブタブの器に入れるだけ**にして、
品目マスタ・配置マスの動作に影響を出さない。

### 4-1 案内文が埋もれる問題

`#cfgNote`（`files/index.html:474` 付近）はスペース設定カードの中にある。
サブタブ化すると、起動時に `showCfgNote()` が呼ばれても、開いているサブタブが
「品目マスタ」なら利用者の目に入らない。表示設定の案内文（6章）も同じ問題を持つ。

**サブタブのボタンに印を付ける。** `showCfgNote()` は配置マスのボタンに、
表示設定用の `showDisplayNote()` は表示設定のボタンに `.alert` クラスを足す。
そのサブタブを開いたら外す（`switchCfgTab()` の中で、開いたペインの印を落とす）。

`.alert` は既存の `.dot`（設定タブのバッジ `#regDot`）とは別物にする。
`.dot` は件数を出すバッジで、こちらは「見てほしい知らせがある」の印。
ボタンの右上に小さな橙色の丸を出す（`::after` で描く）。

## 5. 表示設定の項目

### 5-1 新規（10項目）

| 項目 | CSS 変数 | 初期値 |
|---|---|---|
| 品名の文字サイズ | `--fs-name` | 16px |
| ロットの文字サイズ | `--fs-lot` | 13px |
| P数の文字サイズ | `--fs-pal` | 16px |
| 注釈の文字サイズ | `--fs-note` | 13px |
| 月日の文字サイズ | `--fs-date` | 20px |
| 総P数の文字サイズ | `--fs-total` | 30px |
| 品名を太字 | `--fw-name` | オン |
| ロットを太字 | `--fw-lot` | オフ |
| P数を太字 | `--fw-pal` | オン |
| 注釈を太字 | `--fw-note` | オフ |

文字サイズは数値入力（`<input type="number">`）。範囲は **8〜24px**（3-8）。
範囲外は既存の入力検証と同じ流儀で弾き、既定値に戻す。

太字はチェックボックス。`--fw-*` には `700` / `400` を入れる。
初期値の太字はメモ 2-1 の「品名行と P数行を bold にする」に合わせた。
ロットと注釈は既定オフ。ロットを太字にすると数字が +8% 広がり圧縮率が下がるため
（3-6）。この初期値は実機の紙で確定させる。

「既定に戻す」ボタンを表示設定に置く（スペース設定の `resetConfig()` と同じ流儀）。

### 5-2 移設（3項目）

UI の置き場所だけを表示設定へ移す。**保存キーと関数はそのまま**。

- 矢印の先（`STORE_KEY.arrow`）— 配置表タブから
- 角の丸み（`STORE_KEY.corner`）— 配置表タブから
- 端数を「半」で表示（`STORE_KEY.frac`）— 入力タブから

### 5-3 移さないもの

- 表示倍率（配置表タブに残す）
- 満杯時に混載を許可（入力タブに残す）
- マスの大きさ `STORE_KEY.cell`（配置編集タブの表示。表とは別物）

## 6. データと保存

新規10項目は1つのキーにまとめる。

```js
STORE_KEY.display = "palletApp.display"
const DISPLAY_SAVE_VERSION = 1;
const DEFAULT_DISPLAY = {
  fsName:16, fsLot:13, fsPal:16, fsNote:13, fsDate:20, fsTotal:30,
  fwName:true, fwLot:false, fwPal:true, fwNote:false,
};
```

保存は `{v:DISPLAY_SAVE_VERSION, display:{...}}`。
スペース設定と同じ流儀で、復元時に検証して壊れていたら既定に戻し、案内文を出す。

- バージョン不一致 … **既定値へマージする**。新しい既定値に足りないキーだけを補い、
  利用者が入れた値は残す。範囲外になった値だけ既定値に直す。
  「表示設定に項目が増えたので、足りない分を初期値で補いました」と知らせる
- 中身が不正 … 既定に戻して「保存されていた表示設定を読み込めなかったので、初期値に戻しました」

スペース設定と扱いを変える理由は、**表示設定が「利用者が紙合わせで決めた値」**だから。
`DEFAULT_SPACES` は倉庫の実測なのでこちらが正しいが、文字の大きさは現場の目が正しい。

検証（`validDisplay()`）の内容は「10個のキーが揃っている」「文字サイズが 8〜24 の数値」
「太字が真偽値」の3点。マージ後の値でこれを通らなければ既定に戻す。

**手動配置の指紋 `inputFingerprint()` には入れない。** 表示設定は配置結果を変えないため。

## 7. 適用の仕組み

### 7-1 CSS 変数

全項目を `:root` の CSS 変数として当て、表の CSS がそれを読む。

```css
.sheet td.slot.c-name { font-size:var(--fs-name); font-weight:var(--fw-name) }
.sheet td.slot.c-lot  { font-size:var(--fs-lot);  font-weight:var(--fw-lot) }
.sheet td.slot.c-pal  { font-size:var(--fs-pal);  font-weight:var(--fw-pal) }
.sheet td.snote       { font-size:var(--fs-note); font-weight:var(--fw-note) }
.sheet .fldrow.c5     { font-size:var(--fs-date) }
.sheet .fldrow.c3     { font-size:var(--fs-total) }
```

`slotCells()` が `kind` に応じて `c-name` / `c-lot` / `c-pal` のクラスを付ける。
注釈は既存の `snote` をそのまま使う。

表を描き直さずに反映できるので、設定を触るたびに `renderSheet()` を呼ぶ必要はない。
ただし**文字サイズと太字は圧縮率を変える**ので、変更時に `fitSheetText()` だけを呼ぶ。

### 7-2 圧縮 `fitSheetText()`

`slotCells()` が出力する各セルの中身を `<span class="fit">` で包む。
対象は品名・ロット・P数・注釈の4種。空欄は包まない。

```css
.sheet .fit{display:inline-block;white-space:nowrap;transform-origin:left center}
```

`renderSheet()` の末尾、`drawLeaders()` の**前**に `fitSheetText()` を呼ぶ。
折り返しに落ちた欄は行の高さを変えるので、線を引く前に確定させる必要がある。

各 `.fit` に対して:

1. **幅が測れるか先に確かめる。** `avail = td.clientWidth - 2` が 0 以下なら
   何もせず次へ（非表示タブ。3-3）。**前回の結果を消す前に判定する**
   ── 消してから抜けると、非表示のときに圧縮が外れたまま残る
2. `transform:none` / `white-space:nowrap` / `width:""` に戻して自然幅 `natural` を測る
3. `k = min(1, avail / natural)`
4. `k >= 0.4` … `transform: scaleX(k)` を当てる
5. `k < 0.4` … `k = 0.4` にし、**`width` を `avail / 0.4` へ広げてから**
   `white-space:normal` に戻して折り返させ、この欄を警告リストに積む（3-7）

`translateX` の補正は入れない（3-1）。

### 7-3 警告

下限に達した欄があれば、配置表タブに `.msg.warn` を1本出す。

> ⚠ 文字が入りきらない欄があります：品名2件

**器は新設する。** 既存の `#messages`（`files/index.html:423`）は**配置編集タブの中**にあり、
`renderResult()` が `m.innerHTML=warnHtml+...` で毎回全置換する。圧縮は `renderSheet()` の
たびに走るので、同じ器を使うと互いの警告を消し合う。

配置表タブの `#sheetView` の直前に `<div id="sheetMsg"></div>` を置き、
`fitSheetText()` がここだけを書き換える（毎回 `innerHTML` を作り直す。
下限に達した欄が無ければ空文字）。見た目は既存の `.msg.warn` をそのまま使う。

紙には出さない。印刷CSSの非表示リスト（`files/index.html:299` 付近の
`header,.tabs,.actionbar,#updateBar,.sizectl,#messages,...`）に `#sheetMsg` を足す。

**縦のはみ出しも同じ器で知らせる。** 文字を大きくすると表が伸びるが、
`autoSheetZoom()` は縮小しない（3-8）ので自動では救われない。
`fitSheetText()` の末尾で表の高さを測り、

```
表の高さ（CSS px） × 1.4 > 733.2 × 0.98
```

なら警告をもう1本出す。

> ⚠ 文字が大きくて印刷が1ページに収まりません（用紙の高さの103%）。表示設定で文字を小さくしてください。

98% を閾値にするのはブラウザごとの余白差を見込むため。前案件の印刷確認でも
同じ 98% をゲートにしている。

### 7-4 再計算の契機

3つだけ。

- `renderSheet()` の末尾（配置表を描いたとき。`switchTab("sheet")` 経由もここに合流する）
- 表示設定で文字サイズ・太字を変えたとき（`fitSheetText()` だけ呼ぶ）
- 「既定に戻す」を押したとき

表示倍率の変更・ウィンドウリサイズ・印刷では走らせない。
表は固定幅 672px で、欄幅が変わらないため（3-2 で実測）。

## 8. 高さと印刷への波及

### 8-1 行の高さは増えない

品名・ロット・P数の行は `height:26px` 指定で、16px フォントでも
`16 × 1.2 ＋ padding 2 ＝ 21.2px` に収まる。

### 8-2 注釈行だけ 1.6px 伸びる

13px フォントで `13 × 1.2 ＋ 2 ＝ 17.6px`。`bd0deea` で入れた `height:16px` を超える。
余白 8px と合わせて 25.6px で、上下段の各行（26px）よりわずかに低い状態は保たれる。
**余裕なしで進める**（ユーザー合意済み）。

### 8-3 表の高さと印刷倍率

470.1 → 約473px（注釈行 +1.6px × 2箇所）。印刷（`zoom:1.4`）で 89.8% → 約90.4%。
A4 横・余白8mm の 733.2px に対して余裕がある。

**`SHEET_H` は文字サイズが初期値のときの実測値に合わせる。** これまでは
「注釈が2行に折り返した最悪ケース」を入れていたが、圧縮で常に1行になるので前提が変わる。

**`autoSheetZoom()` は救ってくれない。** `Math.max(1, ...)` で 1 倍を下回らないので
（3-8）、文字を大きくして表が伸びても倍率は下がらない。しかも `SHEET_H` は定数なので、
文字を大きくすると実寸より低い高さを前提に過大な倍率を選ぶ。
**画面の倍率がずれるだけで紙には影響しない**（印刷は `zoom:1.4` 固定）が、
縦の余裕を使い切ったかどうかは 7-3 の警告で知らせる。

### 8-4 実測で確認済みの圧縮率（現行7欄・実効93px）

| 内容 | フォント | 自然幅 | k |
|---|---|---|---|
| 品名6文字 | 16px | 96.0 | 0.969 |
| 品名「エキゾーストマニホールド」 | 16px | 187.7 | 0.496 |
| 注釈「※軒下②・出庫口横・5棟壁際」 | 13px | 177.5 | 0.524 |
| ロット `1111-2222` | 13px | 73.0 | 1.0 |
| P数 `25P 半2` | 16px 太字 | 66.9 | 1.0 |

初期値では**品名がわずかに圧縮される**（k=0.969）。6文字の品名が常時 97% で描かれる。

## 11. 検証

このプロジェクトにはテストランナーが無い。`javascript_tool` で数値を取って判定する。
`applyConfig()` は `alert()` を呼ぶので、検証スクリプトの先頭で必ず `window.alert` を
差し替える。

**検証スクリプトを実行計画に埋め込むときは、計画を確定する前に改修前のコードに対して
一度走らせる**（lessons.md 2026-08-30）。参照するセレクタは実装の読解のついでではなく、
単独で grep して実在を確かめる。

### 11-1 コードで確認する項目

1. 設定タブのサブタブが3枚に切り替わる。品目マスタ・配置マスが従来どおり動く
2. 文字サイズ6項目・太字4項目が CSS 変数として当たり、`getComputedStyle` で期待値が取れる
3. 圧縮 — 品名6文字@16px で k≒0.97、長い品名で k≒0.50、注釈4エリアで k≒0.52。
   左右余白が対称（差 ±2px 以内）
4. 下限 — `natural > avail / 0.4` になる文字列で k が 0.4 で止まり、折り返しに落ち、
   警告が1本出る。実効93px なら閾値は 232.5px で、16px の全角なら15文字以上が該当する
   （例「エキゾーストマニホールド用ブラケット」＝18文字・288px）
4-2. 折り返しに落ちた欄が **2行・42px 以内**に収まり、インク幅が欄いっぱい（90px 以上）で
   あること。`width` を広げ忘れると 6行・118px・インク幅37px になる（3-7）。
   **`k` と `whiteSpace` だけを見る検証ではこの失敗を見逃す**
4-3. 文字を大きくして表を伸ばすと、用紙の98%を超えた時点で高さの警告が出る（7-3）
5. `.sheet` の `zoom` を 1.4 にしても k が変わらない
6. 表示設定を変更 → 配置表が開いていれば `fitSheetText()` だけで k が更新される。
   **設定タブを開いたまま変えたときは配置表が `display:none` なので何も起きず、
   `switchTab("sheet")` の `renderSheet()` が反映を担う**（3-3）。実利用の動線はこちら
7. リロードで設定が復元される。**バージョン不一致では既定値へマージして
   利用者の値が残る**。壊れた保存では既定に戻る。それぞれ別の案内文が出る
8. 表の高さ・印刷比・引き出し線の本数・`sheetLen` の新基準値を記録する
   （`.fit` を挟むので現在の 8778 は使えない）
9. 矢印の先・角の丸み・端数「半」が移設先で従来どおり効く
10. 主動線（「▶ 自動配置を作成」ボタン）から入っても圧縮が効いている
    （非表示タブで `renderSheet()` が走る経路。3-3）

### 11-2 実機で確認する項目（Pixel 9a）

コードでは代替できないもの。

1. 印刷プレビューで 16px の品名が紙で読めるか。現物合わせで初期値を確定させる
2. 圧縮のかかった欄（k≒0.5）が紙で読めるか。下限40%の妥当性
3. 設定タブのサブタブがスマホ幅で扱えるか
