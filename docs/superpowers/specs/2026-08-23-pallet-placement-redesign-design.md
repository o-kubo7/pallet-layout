# パレット自動配置の再設計と配置図の表の集約

作成日: 2026-08-23
対象: `files/index.html`

## 背景

現場でのパレット管理は、入庫時にパレットごとの管理番号をスキャンして登録する運用になっている。
そのため同一ロットのパレットはまとまって隣接配置されている必要がある。

現状のアプリには次の問題がある。

1. **同一ロットが分散する** — 部品A 28P がメインの通路列と通常列3列に分かれて配置される
2. **1ロットが複数エリアに分かれる** — 製品W 30P がメイン・PC横・EV横の3エリアに分散する
3. **配置図の表に同じロットが複数回現れる** — エリアごとに欄を作っているため、製品Wが2欄に出る
4. **現場の優先順と合わない** — 種別で行き先が固定されているため、仕掛品しかない日は軒下が使われない

## 現場の運用ルール

- 同一ロットはまとまって・隣接して配置する
- エリアの優先順は「メイン ＞ 軒下 ＞ PC横・EV横（少量の場合や調査する場合）」
- 軒下は①で溢れた分を②に置く。運用上は①②で1つの「軒下」
- 仕掛品と商品が競合した場合は、仕掛品を倉庫内（メイン）に優先的に配置する

```js

```

問題の原因は次の3つ。

- `tgt()` の種別分岐により、仕掛品は軒下を候補にすらしない
- `block:3` により1ロットは最大3列（21P）まで。28Pは必ず溢れる
- 「入る所から順に詰める」ため、丸ごと入るエリアがあっても分割される

## 設計

### 1. 配置エンジン

配置ロジックを3つの関数に分割する。

#### `areaCandidates()` — 候補リストの生成

エリア優先順に候補を並べたリストを返す。

```
1. メイン（通常列のみ）
2. メイン（通路列も含む）
3. 軒下（①②を連結、38P）
4. PC横（12P）
5. EV横（10P）
```

- 各エリアについて「通常列のみ」と「通路列も含む」の2段を、エリア順に展開する。
  軒下・PC横・EV横には通路列がないため、実質的に上記5候補になる
- この並びにより「メインを使い切ったら、軒下に行く前にメインの通路を使う」が成立する
- 優先順は `SPACES` の配列順に従う。`DEFAULT_SPACES` の並びを
  メイン → 軒下① → 軒下② → PC横 → EV横 に変更する

#### `findRun(cols, rem, useAisle)` — 連続窓の探索

連続した空き列で `rem` パレットが丸ごと入る窓を探し、開始インデックスを返す。入らなければ `null`。

- 「連続」とは列インデックスが途切れず、かつすべて未使用（`fills.length === 0`）であること
- 列の容量は列ごとに異なる（メインは全列7P、軒下①は 11/11/8、軒下②は 4/4）ため、
  窓に含まれる列の容量合計で判定する
- `useAisle` が false のとき、通路列は窓に含めない。通路列は窓を分断する
- 最初に見つかった窓を返す（左詰め）

#### `placeLot(lot, candidates)` — 1ロットの割り当て

1. 候補を優先順に見て、`findRun()` が窓を返した最初の場所に確定する。
   窓の先頭列から順に `min(残り, 列容量)` を詰める
2. どの候補でも丸ごと入らなければ、**同じ候補リストを頭からもう一度たどり**、
   各候補の空き列へ入るだけ詰めていく（分割）。
   通路列は候補リスト上で「通路も含む」段に達したときだけ対象になる。
   各エリアで先頭の空き列から詰めるため、エリア内での隣接は保たれる
3. それでも余り、「満杯時に混載を許可」がONなら、既存の混載処理で空きに押し込む
4. なお余ればあふれとして警告する（既存動作）

#### 処理順

`lots` を次の順に並べ替えてから処理する。

1. 仕掛品をパレット数の多い順
2. 商品をパレット数の多い順

仕掛品が先にメインを確保することで「競合時は仕掛品が倉庫内優先」が成立する。
大口を先に処理することで、連続した列を確保しやすくなる。

#### 軒下の連結

軒下①と軒下②は、配置の判定上は列を連結した1つの仮想エリアとして扱う。

```js
const AREA_GROUPS = [["軒下①","軒下②"]];
```

軒下① `[11,11,8]` ＋ 軒下② `[4,4]` を連結した `[11,11,8,4,4]`（38P）に対して
連続窓を探すことで、①の途中から②に跨る配置も自然に扱える。
描画と表への反映時には、列インデックスから元のスペースに戻す。

設定でスペース名を変更した場合、この連結は外れて別エリア扱いになる。

### 2. 配置図の表の集約

エリア単位ではなくロット単位で欄を作る。

1. 各ロットの配置先を「上段グループ（軒下①②）」と「下段グループ（メイン/PC横/EV横）」に振り分ける
2. **段ごとに1欄**。同じ段で複数エリアにまたがっても1欄にまとめる
3. パレット数はその段での合計
4. 注釈は、その段で使ったエリアのうちメイン以外を「・」で連結する
   - メインのみ → 注釈なし
   - PC横とEV横 → `※PC横・EV横`
   - メイン＋PC横 → `※PC横`
   - 上段（軒下）→ 注釈なし
5. 上段と下段の両方に分かれた場合は、上下段それぞれに1欄ずつ出す。
   品名・ロットは同じで、パレット数はそれぞれの振り分け数に対応させる

欄の並び順は配置された順（上段は軒下①→②、下段はメイン→PC横→EV横で先に現れた順）。

**欄数の超過**: 下段7欄・上段4欄を超えるロットがある場合、現状は黙って表示されない。
超過したロットがある旨を警告メッセージに出す。

### 3. 既存部分への波及

#### 廃止するルール

- `block:3`（1ロット最大3列）— 配置の制限としては使わない
- 「1ブロックを埋め切った大口の余りだけ通路を使う」— 候補リストの優先順に置き換える
- 種別（仕掛品/商品）による倉庫内・倉庫外の固定

#### 維持するもの

- `zone`（near/far）— ブロック図の描画グループ（倉庫外/倉庫内）として維持。配置の分岐には使わない
- `block`（3）— ブロック図の島区切り（`blockgap`）の描画に使う。配置には使わない
- 混載処理（`fillMix`）— 丸ごと配置と分割が失敗した後の最終手段として維持
- 設定タブのテキスト形式 `名前 | zone | orient | block | 列` — 変更しない

#### 文言の修正

- ヘッダの「仕掛品=倉庫内・商品=倉庫外」
- 入力タブ下部の「ルール: 仕掛品→倉庫内 / 商品→倉庫外」「④の通路は大口の余りのみ使用」

### 4. 期待される動作

添付例（仕掛品5件、合計83P）での配置結果。

処理順は仕掛品を大口順（全件が仕掛品のため）。

| 順 | ロット | P数 | 行き先 |
|---|---|---|---|
| 1 | 製品W 6666 | 30P | メイン通常列（空9列=63P）の連続5列（35P）に丸ごと。残り4列 |
| 2 | 部品A 111 | 28P | メイン残4列＝28P にちょうど丸ごと。メイン通常列が満杯 |
| 3 | 製品X 5555 | 20P | メイン通路は左6P・右5Pが分断されており20Pは入らない → 軒下の連続2列（11+11=22P）に丸ごと |
| 4 | 部品B 333 | 3P | メイン通常列が満杯のため、メインの通路列（左6P）に丸ごと |
| 5 | 部品C 222 | 2P | 左6Pの通路列は部品Bで埋まっているため、右5Pの通路列に丸ごと |

全ロットが連続配置され、表にも各ロットが1回ずつ現れる。
表では製品W・部品A・部品B・部品Cが下段（メイン、注釈なし）、製品Xのみが上段（軒下）に出る。

## 検証

Git管理下に置いたが自動テストの仕組みはないため、ブラウザで実データを流して確認する。

1. 添付例（仕掛品5件 83P）→ 全ロットが連続配置、製品Xが軒下①、表に製品Xが1回だけ
2. 既存の「基本サンプル」「混載デモ」→ 破綻しないこと
3. 全部入りきらないケース → 分割・混載・あふれ警告が動くこと
4. 上段4欄／下段7欄を超えるケース → 警告が出ること
5. 設定タブでスペース定義を変更 → 優先順が配列順に従って変わること

## スコープ外

- PC横・EV横を「調査用」として手動指定する機能。優先順の最後に置くだけで、容量が小さいため自然と少量ロットの受け皿になる
- 総当たりによる最適配置の探索。ロット数は高々10件程度で、現場の「大口から順に埋める」直感と結果がずれるため採らない
- ブロック図でEV横の上段4マスを2×2に折り返す表現（データモデルが「列＝1本の連続した並び」のため表現できない）
