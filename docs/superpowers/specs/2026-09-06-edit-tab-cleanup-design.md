- 作成: 2026-09-06
- 対象ファイル: `files/index.html`（単一ファイルの PWA）／ `files/sw.js`（CACHE_VERSION）
- 前提となる機能: `docs/superpowers/specs/2026-09-03-stash-space-and-sweep-select-design.md`
- 状態: 設計承認済み。未実装

## 1. 背景と目的

配置編集タブは機能を足すたびにボタンと説明が増え、盤を見る前に読むものが多くなった。
いま盤より上にあるのは、見出し1つ・ボタン2つ・説明2つ・設定3組である。

利用者の指摘は5点。

1. 「ロットを移動」「移動を終了」ボタンが不要。**タブを開いた時点で編集できる**方が操作が少ない。
   「指の使い方：なぞる」を既定にして、指の使い方の項目は廃止する
2. 案内・退避スペースの位置・マスの大きさの3点は、タブ内の設定ボタンから開くようにして画面の情報を削る
3. 「通路編集」が初見では意味不明なので廃止する
4. 「配置不可エリアの設定」を新設する（前日の荷物で使えないエリアをなぞって選び、自動配置・配置編集から外す）
5. タブ内トップの「配置編集」という見出しはタブ名と二重なので廃止する

**この設計書は 1・2・3・5 だけを扱う。** 4 は `place()`・保存・配置図の表にまで届く新機能なので、
第2弾として別の設計書・別の計画で扱う。1・2・3・5 は画面だけで閉じており、
配置のモデルにも紙にも触らない。先に画面を空けておくと、4 を素直に載せられる。

## 2. 技術制約

`~/claude-lessons/lessons.md` を読み、該当する教訓を反映した。

### 2-1. 実機は Pixel 9a（Android Chrome）

本アプリの実機検証は **Pixel 9a / Android Chrome**、PWA としてホーム画面に追加した
スタンドアロン表示で行う。iOS Safari は現時点の対象外。

`docs/memos/2026-09-03-stash-space-and-sweep-select-progress.md` に
「実機（iPhone）でも確認済み」とあるが、これは前セッションの誤記である。

### 2-2. なぞる常時オンでもスクロールできる（実機確認済み）

`#mapBody.sweep .cell[data-lot]{touch-action:none}`（`files/index.html:180`）があるため、
なぞるモードのあいだは**指がマスの上にあるとスクロールしない**。
`touch-action` は指が触れた瞬間に評価されるので、なぞり始めてから付けても間に合わず、
先付けするしかない（この知見は既存コードのコメントにある）。

一見すると「盤を眺めるだけのときに困る」ように読めるが、**そうならない**。

- **今すでに 🖐 なぞる を選べば、まったく同じ状態になる。** item 1 は新しい状態を作るのではなく、
  既に実機で使われている状態を既定にするだけである
- 2026-09-06 に利用者が「スマホではなぞる方式でスクロール含めて何も問題ない」と報告している
- 縦スクロールの当たりは、列と列の隙間（`.spaces{gap:16px 26px}`）・列の下の数字・
  エリアの余白・`.floor` の padding・盤の外に十分ある。横は `.scroller{overflow-x:auto}`

したがって item 1 に**新しい技術リスクは無い**。この点は今後蒸し返さない。

### 2-3. `edgeScroll()` は選択中しか動かない

端に指を寄せたときの自動スクロール（`edgeTick()`、`files/index.html:2428`）は
`drag.started` か `sweep.started` のあいだだけ回る。
ただ盤を眺めているときの助けにはならない。§2-2 のとおり隙間で足りるので、
今回この挙動は変えない。

### 2-4. PWA のキャッシュ

`files/index.html` を変更するので `files/sw.js` の `CACHE_VERSION` を
v28 → v29 に上げる（lessons.md `[2026-07-09]` の教訓。README の手順にも明記されている）。
検証を `localhost` で行う場合、Service Worker が登録されるので、
確認の前に登録解除と Cache Storage のクリアを行う。

### 2-5. 検証の制約（合成イベント）

`dispatchEvent` した PointerEvent は `isTrusted:false` で既定動作を持たない。
タップ・なぞり・スクロールはブラウザ上では原理的に再現できない。
ハンドラ関数を直接呼ぶ形で検証し、指の操作は実機に送る（プロジェクトの既知の罠）。

## 4. 編集を常時オンにする

### 4-1. 何を固定するか

- `moveMode` は常に真。変数は残すが、切り替える関数と入口を消す
- `tool` は常に `"sweep"`。`#mapBody` に `sweep` クラスを常時付ける

`setMoveMode()` はボタンの文言と `#moveHint` / `#toolCtl` の出し分けを持っていたが、
その3つが消えるので関数ごと不要になる。初期化時に `moveMode=true` を立て、
`#mapBody` に `sweep` を付けるだけでよい。

### 4-2. タブを離れるとき

いまは `switchTab()` が `setMoveMode(false)` と `setEditMode(false)` を呼び、
`redraw()` で `editable` クラスを落としている（`files/index.html:2040-2042`）。

- `setMoveMode(false)` の実質は `clearSel()` と `setTool("scroll")` である。
  戻す先が無くなるので、**`clearSel()` だけを残す**
- `redraw()` は不要になる。`editable` は `editMode` 専用で、
  `drawZone()` が他に `moveMode` 由来のクラスを焼き込んでいないため

タブへ戻ったときに選択が残っていない挙動は今までどおりである。

### 4-3. 連動して単純になる箇所

- `updateFlag()`（`files/index.html:2742`）の表示条件から `moveMode` を落とす。
  `else if(moveMode) msg="👆 マスをタップすると選べます"` は
  `tool==="sweep"` の分岐に必ず先取りされる死に枝なので消す
- なぞりの `pointerdown`（`files/index.html:2893`）の
  `if(e.pointerType!=="mouse" && tool!=="sweep" && !onSel) return;` は
  `tool` が常に `"sweep"` なので常に偽になる。条件ごと消す
- `toggleCell()` によるタップ1マス選択は残す。なぞるモードでもタップは効く

## 5. タブ上部と ⚙ 表示設定（item 2・5）

`<h2>` が丸ごと消えるので、その位置に右寄せの ⚙ ボタンを1つだけ置く。
押すと直下にアコーディオンが開く。

```
[                                   ⚙ 表示設定 ]
  ├ 案内             表示 / 非表示
  ├ 退避スペースの位置   左上 / 右上 / 下
  └ マスの大きさ       小 / 中 / 大
```

- 中身は既存の `#dockCtl` と `#sizeCtl` を1つの `div` で囲うだけ。
  **ボタンの見た目・処理・保存キーは現状維持**（`palletApp.navShow` /
  `palletApp.stashPos` / `palletApp.cell`）
- 既定は閉じる。**開閉の状態は保存しない。** 設定を触るのは最初の1回だけで、
  毎回開いている必要がない
- 開くと盤が下へ押される。設定を触る頻度が低いので、この代償は受け入れる

### 5-1. 結果が無いときの出し分け

`showMapState()`（`files/index.html:2064`）が `#sizeCtl` の表示を `hasResult` で
切り替えている。切り替える対象を、**⚙ ボタンとアコーディオンを囲った枠**に変える。
結果が無いときは ⚙ ごと消え、`#editEmpty` の案内だけが出る。

閉じたまま結果が消えて、また結果が出たときにアコーディオンが開いたままにならないよう、
枠を隠すときにアコーディオンも閉じる。

## 6. 選択の状態を帯へ集約

`#moveHint` にあった選択数と「選択解除」を、盤の上端に貼りつく帯（`#toolFlag`）へ移す。

帯の中身を3つに分ける。**案内の表示・非表示で消えるのは説明文だけ**にするためである。

| 帯の中の要素 | 中身 | 案内＝非表示のとき |
|---|---|---|
| 説明文（`msg`） | 「そのまま外へドラッグで運ぶ・選択の中をなぞると外れる」等 | **消す** |
| 選択数 | 「5マス選択中」 | **出す** |
| ボタン | 選択解除／いまのなぞりを取り消す | **出す** |

- いまは選択数が `msg` の文字列に埋め込まれている
  （`updateFlag()` の `msg="✋ "+n+"マス選択中 ／ …"`）。
  **これを分離し、選択数だけを独立した要素にする。** 埋め込んだままだと
  案内を切った瞬間に選択数まで消えてしまう
- `#selCount` の要素が消えるので、`showSelCount()` の書き込み先をその新しい要素に変える
- 「選択解除」ボタンを `#sweepUndoBtn` の隣に置き、`sel.cells.size>0` のときだけ出す
- 帯そのものの表示条件は「説明文・選択数・ボタンのどれかがある」に変える。
  いまの `(moveMode && (msg||undoOn))` から `moveMode` を落とし、選択数を条件に足す

帯は `position:sticky; top:0` なので、長い盤をたどっても選択数と解除が指の近くに残る。
盤の外に同じものを置かないのは、二重に出すと削る目的に反するためである。

## 8. エッジケース

| 状況 | どうなるか |
|---|---|
| 結果が無い（`hasResult===false`） | ⚙ とアコーディオンごと消え、`#editEmpty` だけが出る。アコーディオンは閉じた状態に戻す |
| マウスだけの端末（PC） | なぞるは元から PC でも同じ判定で動く。`touch-action` はマウスに効かないので影響なし |
| 案内＝非表示 | 説明文だけが消える。選択数・選択解除・なぞりの取り消しは出る |
| タブを離れて戻る | 選択は消えている（`clearSel()`）。編集は開いた瞬間から可能 |
| 退避スペースの中身を選択中にタブを離れる | 同上。選択が消えるだけで、退避の中身は残る |
| 通路列を含む盤 | 見た目（灰・破線）も配置も現状のまま。切り替えるボタンだけが無くなる |
| 保存済みの手動調整があるまま開く | 復元されたまま編集できる。`toggleEdit()` にあった破棄確認は、通路編集ごと無くなるので出ない |

## 9. 検証

`localhost:8765`（`.claude/launch.json` の `pallet-layout`）で確認する。
§2-5 のとおり合成イベントは使わず、ハンドラ関数を直接呼ぶ。

### 9-1. 画面

1. 結果ありで配置編集タブを開く → 盤より上にあるのが ⚙ だけであること
2. ボタンを1つも押さずに `toggleCell()` でマスが選べること（`moveMode===true`、`tool==="sweep"`、
   `#mapBody` に `sweep` クラス）
3. ⚙ を押すとアコーディオンが開き、案内・退避の位置・マスの大きさの3組が出ること
4. 3点それぞれが今までどおり効き、`localStorage` に保存されること
5. 結果を空にすると ⚙ ごと消え、アコーディオンが閉じた状態に戻ること
6. 案内を非表示にしても、選択数・選択解除・なぞりの取り消しが出ること
7. タブを離れて戻ると選択が消えていること

### 9-2. 消えたものが残っていないこと

`moveBtn` / `editBtn` / `editHint` / `moveHint` / `toolCtl` / `selCount` の各 id が
DOM に無いこと。`editMode` / `setEditMode` / `toggleEdit` / `toggleMove` /
`isTouchDevice` が `window` に無いこと。

### 9-3. 紙の非退行

`docs/superpowers/plans/2026-09-01-sheet-top-overflow-rescue.md` の `window.probe` と
フィクスチャ（FN / FR / FP）をそのまま使い、変更前後で幾何と紙の中身が一致することを確認する。
配置表まわりの関数群はハッシュ一致で無変更であることも確かめる。

`@media print` の中の宣言は `getComputedStyle` では読めない。
確認は CSSOM（`document.styleSheets` → `CSSRule.MEDIA_RULE` →
`conditionText.includes("print")`）で行う（lessons.md `[2026-08-30]` の教訓）。

### 9-4. 通路が生きていること

スペース設定のテキストで列を `6*` に変えて「設定を反映」→
盤に灰・破線で出ること、収容能力の内訳が変わること、配置図の表の通路列が変わらないこと。

### 9-5. 実機（人の作業）

Pixel 9a / Android Chrome、PWA のスタンドアロン表示で確認する。

- 配置編集タブを開いた直後、ボタンを押さずになぞって選べること
- 盤が縦にも横にもスクロールできること
- ⚙ を開いてマスの大きさを変え、盤が押し下げられても操作に支障がないこと
- 帯の選択解除が指の届く位置に出ること
