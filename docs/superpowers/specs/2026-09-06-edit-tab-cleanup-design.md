- 作成: 2026-09-06

- 前提となる機能: `docs/superpowers/specs/2026-09-03-stash-space-and-sweep-select-design.md`
- 状態: 設計承認済み。未実装

## 1. 背景と目的

配置編集タブは機能を足すたびにボタンと説明が増え、盤を見る前に読むものが多くなった。
いま盤より上にあるのは、見出し1つ・ボタン2つ・説明2つ・設定3組である。

利用者の指摘は5点。

1. 「ロットを移動」「移動を終了」ボタンが不要。**タブを開いた時点で編集できる**方が操作が少ない。
   「指の使い方：なぞる」を既定にして、指の使い方の項目は廃止する
2. 案内・退避スペースの位置・マスの大きさの3点は、タブ内の設定ボタンから開くようにして画面の情報を削る
3. 「通路編集」が初見では意味不明なので廃止する
4. 「配置不可エリアの設定」を新設する（前日の荷物で使えないエリアをなぞって選び、自動配置・配置編集から外す）
5. タブ内トップの「配置編集」という見出しはタブ名と二重なので廃止する

**この設計書は 1・2・3・5 だけを扱う。** 4 は `place()`・保存・配置図の表にまで届く新機能なので、
第2弾として別の設計書・別の計画で扱う。1・2・3・5 は画面だけで閉じており、
配置のモデルにも紙にも触らない。先に画面を空けておくと、4 を素直に載せられる。

## 2. 技術制約

`~/claude-lessons/lessons.md` を読み、該当する教訓を反映した。

### 2-1. 実機は Pixel 9a（Android Chrome）

本アプリの実機検証は **Pixel 9a / Android Chrome**、PWA としてホーム画面に追加した
スタンドアロン表示で行う。iOS Safari は現時点の対象外。

`docs/memos/2026-09-03-stash-space-and-sweep-select-progress.md` に
「実機（iPhone）でも確認済み」とあるが、これは前セッションの誤記である。

### 2-2. なぞる常時オンでもスクロールできる（実機確認済み）

`#mapBody.sweep .cell[data-lot]{touch-action:none}`（`files/index.html:180`）があるため、
なぞるモードのあいだは**指がマスの上にあるとスクロールしない**。
`touch-action` は指が触れた瞬間に評価されるので、なぞり始めてから付けても間に合わず、
先付けするしかない（この知見は既存コードのコメントにある）。

一見すると「盤を眺めるだけのときに困る」ように読めるが、**そうならない**。

- **今すでに 🖐 なぞる を選べば、まったく同じ状態になる。** item 1 は新しい状態を作るのではなく、
  既に実機で使われている状態を既定にするだけである
- 2026-09-06 に利用者が「スマホではなぞる方式でスクロール含めて何も問題ない」と報告している
- 縦スクロールの当たりは、列と列の隙間（`.spaces{gap:16px 26px}`）・列の下の数字・
  エリアの余白・`.floor` の padding・盤の外に十分ある。横は `.scroller{overflow-x:auto}`

したがって item 1 の**スクロールには新しい技術リスクは無い**。この点は今後蒸し返さない。

### 2-2-1. ただし `sweep` には見た目が3つぶら下がっている

`touch-action` 以外に、`sweep` クラスは次の3つを連れてくる。常時オンにすると
「なぞるモードに入っている」という**印だったものが常設の装飾になる**。

| CSS | 現状の役目 | 常時オンにすると |
|---|---|---|
| `#mapBody.sweep{outline:3px solid #2563eb;outline-offset:8px}`（`:200`） | モードに入っている印 | 盤が**常に青枠で囲まれる** |
| `#mapBody.sweep .scroller{background-image:none}`（`:205`） | なぞり中は影を消す | 横スクロールの**影ヒントが恒久的に消える** |
| `#mapBody.sweep .cell[data-lot]{cursor:crosshair}`（`:181`） | なぞれる合図 | PC で常に十字カーソル |

**青枠と影の打ち消しは廃止する。** どちらもモードの印であり、常時オンなら意味を失う。
とくに影は「右にまだ列が続く」ことを示す手掛かりで、マスの上からは横スクロールできない
以上、消したままにすると横に続くことに気づく手段が減る。

`cursor:crosshair` は残す。PC ではモードの印ではなく「ここはなぞれる」という
操作の手掛かりとして働くためである。

### 2-3. `edgeScroll()` は選択中しか動かない

端に指を寄せたときの自動スクロール（`edgeTick()`、`files/index.html:2428`）は
`drag.started` か `sweep.started` のあいだだけ回る。
ただ盤を眺めているときの助けにはならない。§2-2 のとおり隙間で足りるので、
今回この挙動は変えない。

### 2-4. PWA のキャッシュ

`files/index.html` を変更するので `files/sw.js` の `CACHE_VERSION` を
v28 → v29 に上げる（lessons.md `[2026-07-09]` の教訓。README の手順にも明記されている）。
検証を `localhost` で行う場合、Service Worker が登録されるので、
確認の前に登録解除と Cache Storage のクリアを行う。

### 2-5. 検証の制約（合成イベント）

`dispatchEvent` した PointerEvent は `isTrusted:false` で既定動作を持たない。
タップ・なぞり・スクロールはブラウザ上では原理的に再現できない。
ハンドラ関数を直接呼ぶ形で検証し、指の操作は実機に送る（プロジェクトの既知の罠）。

## 4. 編集を常時オンにする

### 4-1. 何を固定するか

- `moveMode` は常に真。変数は残すが、切り替える関数と入口を消す
- `tool` の既定を `"sweep"` にする。**変数と `setTool()` は残す**（§4-1-1）

`setMoveMode()` はボタンの文言と `#moveHint` / `#toolCtl` の出し分けを持っていたが、
その3つが消えるので関数ごと不要になる。

### 4-1-1. `tool` と `setTool()` は消さずに残す

`#toolCtl`（画面の2択）は消すが、**仕組みは残す**。理由は第2弾にある。

item 4「配置不可エリアの設定」は、なぞりで**ロットではない別の対象**
（前日の荷物で使えないエリア）を選ぶ。いまのなぞりは `toggleCell()` の
「空マスは選べない」「`sel.lotId` は1ロットだけ」に固く縛られているので
（`files/index.html:2275-2288`）、第2弾は必ず「いま何を選んでいるのか」の
切り替えを必要とする。ここで `tool` を消すと、第2弾で同じものを作り直すことになる。

したがって:

- `let tool="scroll"` → `let tool="sweep"` に既定を変える
- `setTool()` からは**ボタンの `classList` 更新ループだけ**を削る。
  `tool` の代入・`#mapBody` の `sweep` クラス切替・`updateFlag()` は残す
- 起動時に `setTool("sweep")` を1回呼んで `sweep` クラスを付ける。
  HTML にクラスを焼き付けるのではなく関数を通すことで、第2弾が
  `setTool("block")` のような値を足せる余地を残す
- `pointerdown` の `tool!=="sweep"` の条件も**残す**。いまは常に偽になるが、
  第2弾で別の `tool` が入ったときにそのまま意味を持つ

### 4-2. タブを離れるとき

いまは `switchTab()` が `setMoveMode(false)` と `setEditMode(false)` を呼び、
`redraw()` で `editable` クラスを落としている（`files/index.html:2040-2042`）。

- `setMoveMode(false)` の実質は `clearSel()` と `setTool("scroll")` である。
  戻す先が無くなるので、**`clearSel()` だけを残す**
- `redraw()` は不要になる。`editable` は `editMode` 専用で、
  `drawZone()` が他に `moveMode` 由来のクラスを焼き込んでいないため

タブへ戻ったときに選択が残っていない挙動は今までどおりである。

### 4-3. 連動して単純になる箇所

- `updateFlag()`（`files/index.html:2742`）の表示条件から `moveMode` を落とす。
  `else if(moveMode) msg="👆 マスをタップすると選べます"` は
  `tool` の既定が `"sweep"` になったことで到達しなくなるので消す
- `toggleCell()` によるタップ1マス選択は残す。なぞるモードでもタップは効く
- `pointerdown` の `tool!=="sweep"` の条件は §4-1-1 のとおり**残す**

## 5. タブ上部と ⚙ 表示設定（item 2・5）

`<h2>` が丸ごと消えるので、その位置に右寄せの ⚙ ボタンを1つだけ置く。
押すと直下にアコーディオンが開く。

```
[                                   ⚙ 表示設定 ]
  ├ 案内             表示 / 非表示
  ├ 退避スペースの位置   左上 / 右上 / 下
  └ マスの大きさ       小 / 中 / 大
```

- 中身は既存の `#dockCtl` と `#sizeCtl` を1つの `div` で囲うだけ。
  **ボタンの見た目・処理・保存キーは現状維持**（`palletApp.navShow` /
  `palletApp.stashPos` / `palletApp.cell`）
- 既定は閉じる。**開閉の状態は保存しない。** 設定を触るのは最初の1回だけで、
  毎回開いている必要がない
- 開くと盤が下へ押される。設定を触る頻度が低いので、この代償は受け入れる

### 5-1. 結果が無いときの出し分け

`showMapState()`（`files/index.html:2064`）が `#sizeCtl` の表示を `hasResult` で
切り替えている。切り替える対象を、**⚙ ボタンとアコーディオンを囲った枠**に変える。

**ただし `hasResult` だけでは足りない。** `run()` には「有効な荷物が1件も無いが
SNP 未入力の行はある」という枝があり（`files/index.html:1895-1908`）、
そこは `showMapState()` を呼んだ**直後に自分で打ち消している**。

```js
showMapState();                                              // editEmpty → block, mapBody → none
document.getElementById("editEmpty").style.display="none";   // すぐ戻す
document.getElementById("mapBody").style.display="block";    // 盤も出し直す
```

つまり `hasResult===false` なのに**盤は出ている**状態が実在する。
ここで ⚙ だけを消すと、盤が見えているのにマスの大きさを変える手段が無くなる。

**規則をひとつにする: ⚙ は盤が出ているときに出す。**

- `showMapState()` は `hasResult` で `#editCtl` を出し分ける（通常の経路）
- `run()` の上の枝でも、`mapBody` を出し直す行の隣で `#editCtl` を出し直す
- 枠を隠すときはアコーディオンも閉じる。閉じずに隠すと、
  次に結果が出たとき開いたまま復帰してしまう

## 6. 選択の状態を帯へ集約

`#moveHint` にあった選択数と「選択解除」を、盤の上端に貼りつく帯（`#toolFlag`）へ移す。

帯の中身を3つに分ける。**案内の表示・非表示で消えるのは説明文だけ**にするためである。

| 帯の中の要素 | 中身 | 案内＝非表示のとき |
|---|---|---|
| 説明文（`msg`） | 「そのまま外へドラッグで運ぶ・選択の中をなぞると外れる」等 | **消す** |
| 選択数 | 「5マス選択中」 | **出す** |
| ボタン | 選択解除／いまのなぞりを取り消す | **出す** |

- いまは選択数が `msg` の文字列に埋め込まれている
  （`updateFlag()` の `msg="✋ "+n+"マス選択中 ／ …"`）。
  **これを分離し、選択数だけを独立した要素にする。** 埋め込んだままだと
  案内を切った瞬間に選択数まで消えてしまう
- `#selCount` の要素が消えるので、`showSelCount()` の書き込み先をその新しい要素に変える
- 「選択解除」ボタンを `#sweepUndoBtn` の隣に置き、`sel.cells.size>0` のときだけ出す
### 6-1. 待機中は帯を出さない

帯は `position:sticky; top:0` で盤の上端に貼りつく。**選択が無く、取り消しも無いときは
帯ごと消す。**

素直に作ると、案内が表示のあいだは「マスをなぞると、同じロットをまとめて選べます」が
常に出るので、**盤の上に常設の帯が居座る**ことになる。画面の情報を削るという
今回の目的に真っ向から反するので、待機中の説明文そのものを出さない。

帯を出す条件は「選択がある、または なぞりの取り消しがある」。
その中で、案内が非表示なら説明文だけを空にする。

### 6-2. 帯に入る量の見積もり

Pixel 9a（幅 412px）で実測したところ、`#stashDock` が `float:right; width:33vw` で
**136px** を占める（`files/index.html:236-239`）。帯に使える幅は約 250px しかない。

そこへ選択数・説明文・ボタン2つが入る。`flex-wrap:wrap` なので折り返すが、
**帯の高さが盤を押し下げる**。実機（Task 7）で高さを見て、収まらなければ
説明文を短くする。文言は次のとおり短縮する。

- 選択中: `そのまま外へドラッグで運ぶ・選択の中をなぞると外れる`
- 運搬中: `置きたい列の上で指を離してください`

（いずれも先頭の絵文字と「Nマス選択中」は選択数の要素へ移したので、説明文からは外す）

### 6-3. 選択数が重なる場所

退避スペースの中身だけを選んでいるとき、`drawStashDock()` は浮き枠の見出しに
「Nマス選択中」を書く（`files/index.html:2639-2641`）。帯の選択数と**同じ数字が
2か所**に出ることになる。

これは許容する。浮き枠の見出しは「その枠の中で何を選んでいるか」、帯は
「盤全体で何を選んでいるか」で、見る場面が違う。統合すると、退避の中身を
選んでいるのか倉庫のマスを選んでいるのかが分からなくなる。

### 6-4. タップ目標の大きさ

`.flagundo{min-height:38px}`（`files/index.html:196`）は、指で押すボタンの
推奨サイズ 44px を下回っている。帯に選択解除を移して**指で押す前提になる**ので、
`min-height:44px` に上げる。

## 9. 検証

`localhost:8765`（`.claude/launch.json` の `pallet-layout`）で確認する。
`file://` は使えない（この環境では静的スナップショットになりスクリプトが動かない）。
§2-5 のとおり合成イベントは使わず、ハンドラ関数を直接呼ぶ。

**px を測る前に `innerWidth` を確かめる。** Browser pane が実サイズを持たないと
`innerWidth === 0` になり、`getBoundingClientRect()` が数値を返すのに値が丸ごと嘘になる
（2026-09-06 に実測。284.6px のはずが 1616.5px を返した）。
0 なら `resize_window` で `width:412, height:915`（Pixel 9a 相当）を明示する。

**結果が無い状態は `clearLots()` で作る。** 全行の SNP を空にする方法だと §5-1 の
「盤は出たまま」の枝に入ってしまい、別の状態を測ることになる。
`clearLots()` は `hasResult=false; lastLots=null; showMapState();` で終わるので
打ち消しが無い（`files/index.html:1094-1099`）。冒頭で `confirm()` するのでスタブが要る。

**スペース設定を触る検証は、前後で `localStorage` を退避して戻す。**
`resetConfig()` は `saveData(STORE_KEY.spaces, null)` で保存ごと消すので、
検証用プロファイルに実倉庫の列構成が入っていると失われる。

### 9-1. 画面

1. 結果ありで配置編集タブを開く → 盤より上にあるのが ⚙ だけであること
2. ボタンを1つも押さずに `toggleCell()` でマスが選べること（`moveMode===true`、`tool==="sweep"`、
   `#mapBody` に `sweep` クラス）
3. ⚙ を押すとアコーディオンが開き、案内・退避の位置・マスの大きさの3組が出ること
4. 3点それぞれが今までどおり効き、`localStorage` に保存されること
5. `clearLots()` で結果を空にすると ⚙ ごと消え、アコーディオンが閉じた状態に戻ること
6. 全行の SNP を空にして `run()` した場合は、盤が出ているので ⚙ も出ること（§5-1）
7. 選択が無いとき帯が出ていないこと。案内の表示・非表示どちらでも同じ（§6-1）
8. 選択があるとき帯が出て、案内を非表示にしても選択数・選択解除・取り消しが出ること
9. タブを離れて戻ると選択が消えていること

### 9-1-1. 目的が達成できたかを数で見る

「盤より上に出ているものを ⚙ だけにする」を実際に測る。
`resize_window` で 412×915 にしてから、`#editCard` の上端から `#mapBody` の上端までの
高さを改修前後で比べる。

**改修前の実測値（2026-09-06、412×915）: 284.6px**
内訳は `<h2>` 44px ／ `#dockCtl` 86px ／ `#sizeCtl` 40px ／ `#messages` 61.6px と各余白。

改修後は `<h2>` と `#dockCtl` と `#sizeCtl` が ⚙ 1行に置き換わるので、
**おおむね 130〜160px** に減るはずである。増えていたら §6-1 の帯か
アコーディオンの余白を疑う。

### 9-2. 消えたものが残っていないこと

`moveBtn` / `editBtn` / `editHint` / `moveHint` / `toolCtl` / `selCount` の各 id が
DOM に無いこと。`editMode` / `setEditMode` / `toggleEdit` / `toggleMove` /
`isTouchDevice` が `window` に無いこと。

**`tool` と `setTool` は残っていること**（§4-1-1）。`setTool` が
`toolScrollBtn` / `toolSweepBtn` を参照していないこと。

`#mapBody` の `outline-width` が `sweep` によって太くなっていないこと、
`.scroller` の `background-image` が `none` でないこと（§2-2-1）。

### 9-3. 紙の非退行

`docs/superpowers/plans/2026-09-01-sheet-top-overflow-rescue.md` の `window.probe` と
フィクスチャ（FN / FR / FP）をそのまま使い、変更前後で幾何と紙の中身が一致することを確認する。
配置表まわりの関数群はハッシュ一致で無変更であることも確かめる。

`@media print` の中の宣言は `getComputedStyle` では読めない。
確認は CSSOM（`document.styleSheets` → `CSSRule.MEDIA_RULE` →
`conditionText.includes("print")`）で行う（lessons.md `[2026-08-30]` の教訓）。

### 9-4. 通路が生きていること

スペース設定のテキストで列を `6*` に変えて「設定を反映」→
盤に灰・破線で出ること、収容能力の内訳が変わること、配置図の表の通路列が変わらないこと。

### 9-5. 実機（人の作業）

Pixel 9a / Android Chrome、PWA のスタンドアロン表示で確認する。

- 配置編集タブを開いた直後、ボタンを押さずになぞって選べること
- 盤が縦にも横にもスクロールできること
- ⚙ を開いてマスの大きさを変え、盤が押し下げられても操作に支障がないこと
- 帯の選択解除が指の届く位置に出ること。押せる大きさであること（44px、§6-4）
- **帯の高さが盤を押し下げすぎていないこと**（§6-2）。折り返して3行以上になるなら文言を短くする
- 選択していないときに帯が出ていないこと
- 盤が青枠で囲まれていないこと。横に続く帯の端に影のヒントが出ること（§2-2-1）
