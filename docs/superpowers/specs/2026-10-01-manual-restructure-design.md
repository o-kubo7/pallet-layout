日付: 2026-10-01
前提: `docs/superpowers/specs/2026-09-24-manual-11pages-design.md`（13ページ版）と、その末尾の改訂節。
作業ブランチ: `feat/manual-11pages`（2026-10-01 に `main` を取り込み済み。アプリは v78）

## 1. 目的

13ページ版は、アプリを初めて使う人向けに操作を細かく説明している。
チームの作業内容を理解している人を想定読者とし、本編を短くする。
本編だけで「何ができるか」「どう作業するか」「自動配置に何を期待してよいか」「画面のどこに何があるか」が分かるようにする。
細かい操作の説明は付録としてすべて残す。

チュートリアル（アプリ内で操作しながら説明するモード）は、このあと別の開発として設計する。この設計の範囲外。

## 3. 本編の中身

### P1　1. このアプリでできること

- リード: 「発送伝票から、配置図を作る。」
- 本文: 「**配置図の作成**を省力化するアプリです。」
- 完成した配置図の画像（`sheet-final`。ページの約半分）
- 比較表（`.tbl.compare`。今の P1 と同じ見た目で3行）
  - 個数とSNPからパレット数を手計算する → 入力すると自動で計算する
  - 品目・ロットごとに集計し、配置を考える → 自動配置を出発点に、画面で整える
  - 所定の用紙に配置を記入する → 配置図を作成して印刷する（A4横）
- 3つのタブの図（`tabs`。入力・配置編集・配置図を赤枠で強調）と、タブごとに1行の説明
- 一番下に注意: 入力や配置は、使っているPCのブラウザに自動で保存されます。ブラウザのサイトデータを削除すると消えます。

### P2　2. 作業の手順と、自動配置のしくみ

2.1 毎日の手順（①〜⑤）
1. 入力タブで、FAX 1枚につき1伝票を入力する。FAXが届いていない分は仮伝票にする。
2. 「▶ 自動配置を作成」を押す。
3. 配置編集タブで、品目のまとまりや置き場を整える。
4. 配置図タブで表記を確かめ、印刷して配る。
5. FAXが届いたら仮伝票を直して受領済みにし、自動配置を作り直す（手で整えた配置は消える）。

2.2 自動配置がすること
- 充填品を先に置き、その後で製品を置く。結果として、充填品が倉庫内（メイン）を取りやすい。
- 品目どうしは入力した順に置く。同じ品目の中は、パレット数の多いロットから置く。
- 置き場は決まった順に試す: メイン → メインの通路列 → 軒下①② → PC横 → EV横 → 出庫口横 → 5棟壁際。
- 1列に1ロット。ロットが丸ごと入る場所を探し、無ければ空いている列に分けて詰める。
- 余った分は、空きのある列に混載する（設定「満杯時に混載を許可」がオンのとき）。それでも入らない分は退避スペースへ回り、配置図には「未定」の欄として載る。
- 「半」はロットの下側のマスに付く。

2.3 自動配置がしないこと（`aside.warn` の囲み）
- 全体を見比べて、いちばん良い配置を探すことはしない（見つかった最初の場所に置く）。
- 同じ品目のロットを、必ず隣どうしに置くとは限らない。
- 出荷や入庫の順番、取り出しやすさ、検品のタイミングは考えない。
- 緊急用のマスは使わない。
- だから、自動配置は出発点。最後は人が画面で整える。

1ページに収まらなければ、2.2・2.3 を次のページに分ける（本編は7ページ、付録は1ページずつ後ろへずれる）。

根拠（2026-10-01 時点の `files/index.html`、v78 取り込み前の調査。実装時に行番号を確かめ直す）:
- 置く順番: `place()` の並べ替え（充填品が先、同じ「種別＋品名＋SNP」の中はパレット数の多い順、まとまりどうしは入力順）
- エリアの順: `DEFAULT_SPACES` の並び順、`areaCandidates()`
- 丸ごと入る場所の探索と分割: `placeLot()`、`findRun()`
- 混載: `fillMix()`、設定 `mix`（既定オン）
- 退避: 置けなかった分を退避スペースへ移す処理
- 緊急用マスを使わない: `aisleRows` の扱い
- 「半」: `halfCells()`

### P3〜P5　3. 画面の見方

- 試作 `manual/drafts/ov-input.html`・`ov-edit.html`・`ov-sheet.html` を本編のページにする。
- 見出しは「3. 画面の見方 <small>（1）入力</small>」のように章3の中の小見出しにする（試作の「3. 入力 画面の見方」等から変える）。
- 表の「詳しくは」は、付録の新しいページ番号にする。
- 札の位置は、2026-09-26 のレビューで決めた向きのまま（`capture/overview.cjs` の `side`）。

### P6　4. 補足：従来の配置図の書き方

4.1 手書きの頃の手順（ユーザー提供の要点をそのまま。図なし）
1. 発送伝票と予定表から、ロットのP数を計算する。品目ごとにまとめる。発送伝票が無いものは仮置き。
2. 品目ごとの合計P数を把握。
3. 品目ごとにまとまるようにスペースへの配置を考える。
4. 充填品を倉庫内に優先配置する。

4.2 配置の考え方（今の P2 の 2.2・2.3 から移す）
- 品目ごと、その中でロットごとにまとめる理由（作業者の登録単位、入庫設定が品目ごとに完了する）
- 充填品を優先して倉庫内へ置く理由（製品は入庫前の検査で入庫設定が遅れがち）
- 今の P2 の `sheet-item-group` の図（仕掛品1 の3ロット）は、余白があれば残す

結び: 「アプリは、この手順の1・2を自動で行い、3・4の出発点を作ります。」

## 4. 作り方

### 4.1 ページ

- `manual/pages/` を新しい順に並べ直す。本編 p01〜p06（または p07）、付録はその後ろ。
- 試作 `manual/drafts/` は `pages/` に移して削除する。
- 試作専用の組版 `manual/draft-overview.cjs` と `npm run draft` は削除する。

### 4.2 組版

- 見取り図の札を重ねる処理を `build.cjs`（と `lib/build-lib.cjs`）に移す。札の座標は `verification.json` の `overview` から読む。手で座標を書かない。
- 札の差し込み処理に単体テストを足す（座標が無いときは止める、札の数と表の行が一致する など）。
- ページ参照の検査を足す: 本文中の「P数字」「P数字〜数字」が、組版したページ数の範囲に入っていることを確かめ、外れていれば止める。
- 付録のページにも、見出し上部の章の位置表示（入力 → 配置編集 → 配置図）をそのまま出す。本編 P1・P2・P6 は位置表示なし。

### 4.3 撮影

- `capture/overview.cjs` は `npm run all`（`capture.cjs` の ORDER）に含まれていることを確かめる。
- v78 のアプリで `npm --prefix manual run all` をやり直す。撮影時の検証（合計 101P / 100P、手動配置の復元、確認ダイアログの文言など）が通ることを確かめる。
- 見た目が変わった画面があれば、本文と合っているかを確かめる。合わない場合は止めて相談する。

### 4.4 範囲外

- アプリ本体（`files/`）は変更しない。
- 起動方法（URL、PC）は書かない（会社のPCへの導入が未決定）。
- チュートリアル。

## 5. 検証

- `npm --prefix manual test` がすべて通る（今の18件＋追加分）。
- 全ページ `spaceToFooter` 0以上、`images:true`。
- ページ参照の検査が通る。
- `grep -nE '元に戻す|やり直す|●|AAA|※未定' manual/pages/*.html` が何も出さない。
- 確認ダイアログの画面例（付録の入力・配置編集）に、撮影時に記録した文言が入っている。
- プレビューで本編と付録の全ページを目視する。

## 6. 技術制約

- ブラウザ・OS・デバイスの新しい API には依存しない（既存の Playwright＋Google Chrome による撮影、`sips` による PNG 化。macOS 専用は従来どおり）。
- ディスクの空きが少ない（2026-09-24 時点で約700MB）。撮影の前に空きを確かめる。
- アプリ本体の更新（v76 → v78）で画面が変わっている可能性がある。撮影時の検証で止まった場合は、止めて相談する。
