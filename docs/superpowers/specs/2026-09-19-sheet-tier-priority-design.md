# 配置図の欄割り当てを「掲載先＝優先する段」に変える 設計書

**状態**: 設計の合意済み（2026-09-19、対話で §1〜§3 を承認）。実行計画は未作成。
**次の手順**: この設計書をユーザーがレビュー → `/dig` で前提とリスクを洗い出す → `superpowers:writing-plans` で実行計画を作る。

---

## 1. 背景

配置図の下段の欄が足りない日に、**メインエリアのロットが追記欄へ落ち、PC横・EV横 のロットが下段の欄を占める**。

現場から上がった実例（2026-09-18）:

- 下段8欄: 部品E, 部品C, **製品W(※EV横)**, 製品Y, 部品A, 製品Z, 部品B, **製品X(※EV横)**
- 追記欄のまとめ欄: 部品D・部品3 / L-104・333 / 14P・24P / 注記 **※メイン**・※PC横・EV横

倉庫の主役であるメインの荷物が小さい文字のまとめ欄に落ち、隅の置き場である EV横 が通常の欄を取っている。

### 原因

`files/index.html` の `arrangeBottomSlots()`。

```js
const keptRight=rightEntries.slice(0, Math.min(rightEntries.length, count));
const mainCap=Math.max(0, count-keptRight.length);
const keptMain=mainEntries.slice(0, mainCap);
```

`rightEntries`（基準エリア＝メイン以外、つまり PC横・EV横）が最大 `count` 件まで**先に**欄を取り、メインは残りだけを受け取る。あふれたメインは `dropped` から追記欄へ回る。

これは事故ではなく、`docs/superpowers/specs/2026-09-12-sheet-slot-proximity-design.md` の決定1「PC横・EV横の右詰めを**最優先**する」を実装したもの。**今回その決定を上書きする。**

### ユーザーの運用（2026-09-18 の指示、原文）

> 下段は、まずメインエリアのロットで埋める。メインエリアと軒下ではない置き場のロットは、上下段の空いた欄に注釈とともに記載する、欄が足りなければ追記欄に記載する。

## 2. 前提の変化（着手前に必ず確認すること）

**2026-09-19 に配置図の欄数を増やした**（コミット `feat: 配置図の欄を増やし、追記欄を2列にする`）。

- wide 様式が 16列×42px＝672px → **18列×39px＝702px**
- 上段 5→**6欄**、下段 8→**9欄**
- 追記欄が 156px の縦2枠 → **78px×2列×2段＝4枠**
- まとめ欄になるのは5件以上あふれた日だけ

**欄が3つ増えたぶん、メインがあふれる頻度自体が下がっている。** この設計に着手する前に、
ユーザーの実運用データで「まだメインが追記欄に落ちるか」を確認すること。落ちないなら
優先順の変更自体が不要になる可能性がある。

## 3. 決定事項

### 3-1. 掲載先の意味を変える

エリアの掲載先（`sheet`: `top` / `bottom` / `over`）を「**固定の段**」から「**まず使う段**」に読み替える。
保存形式（`SPACES_SAVE_VERSION`）と設定画面の項目は変えない。値も `top`/`bottom`/`over` のまま。

現在のエリアと掲載先:

| 掲載先 | エリア |
|---|---|
| `top` | 軒下①、軒下②、出庫口横、5棟壁際 |
| `bottom` | メイン、PC横、EV横 |
| `none` | 退避 |

### 3-2. 各段の埋め方

その段を優先に設定されたエリアを、**設定タブの並び順**に詰める。

- 下段: メイン → PC横 → EV横
- 上段: 軒下① → 軒下② → 出庫口横 → 5棟壁際

**下段の右詰めは維持する。** メインを先に配り、残った欄に PC横・EV横 を**右端から**詰め、EV横 を最右に置く。
盤のマス位置への近接配置の総当たり探索（`choose()`）は「メイン用に確保した欄の中」という定義のまま効く。
探索の組合せ数は最大 C(9,4)=126 程度で問題にならない。

上段に右詰めの概念は無い（現状どおり並び順に詰める）。

### 3-3. 段をまたぐ回送（双方向・新規）

詰めきれなかった項目は、もう片方の段の空き欄へ注釈つきで回す。順番は決め打ちにする。

1. 各段、自段優先のエリアを配る
2. 上段のこぼれ → 下段の空き欄（**既存の `moved` / `fromTop`。現状のまま**）
3. 下段のこぼれ → 上段の空き欄（**新規**）
4. 退避（`※未定`）→ まだ残っている空き欄
5. 残り全部 → 追記欄（順序は「実在する置き場 → 退避」＝現状のまま）

**2 と 3 は排他になる。** 下段があふれる日は下段の空きが 0 なので 2 は起きず、上段があふれる日は
上段の空きが 0 なので 3 は起きない。片方向ずつしか動かないので、順序で結果が変わることはない。

**メイン自身が下段の欄数を超えた日も、メインを上段の空き欄へ回してよい**（2026-09-18 にユーザー確認済み）。
「こぼれた項目は片方の空き欄へ」でルールを統一する。

回された欄は注釈を作り直す（基準エリアを省かない）。既存の `fromTop` と同じ扱い。
引き出し線は盤のマスから引くので、盤に描かれない PC横・EV横 が回っても線は発生しない。

**退避は上段の空き欄を先に使う。** 下段は盤と引き出し線で対応づいており、盤に実在しない退避が
下段に混ざると読み手が盤の上を探してしまう。上段は倉庫外・その他の置き場の欄なので相性が良い。

### 3-4. 様式の判定

**回送前の件数で行う**（現状の方針を維持）。先に wide にして欄を増やし、それでもあふれる分だけを回す。

## 4. 実装の構造

責任分担は維持する。`sheetPlacement()` が「どの項目をどちらの段に回すか」、
`arrangeBottomSlots()` が「下段の行のどこに置くか（右端固定＋近接配置）と何がこぼれるか」。

### 4-1. `arrangeBottomSlots()` — 優先順を入れ替える

下段に入る順位を次にする。

`メイン → PC横・EV横（右端固定・EV横が最右）→ 上段からの救済 → 退避`

救済を PC横・EV横 より後ろにするのは、ユーザーの運用の「**空いた**欄に記載する」に合わせたもの。
自段のエリアが先。

### 4-2. `sheetPlacement()` — 回送を双方向にする

現在は上段→下段の一方向だけで、退避は無条件に上段の末尾へ連結している。

```
lay = sheetLayout(上段自前, 下段自前)        // 様式は回送前の件数で
上段の空き = lay.top    - 上段自前の件数
下段の空き = lay.bottom - 下段自前の件数
→ §3-3 の 2〜5 の順に流す
```

### 4-3. 印（フラグ）

`fromTop` は現状どおり残す（`renderSheet()` が引き出し線の id を落とすのに使っている）。
下段→上段の回送には引き出し線の問題が無い（上段に線は引かれない）ので新しい印は要らず、
注釈を作り直すだけで足りる。

### 4-4. 触らないもの

`sheetLayout` / `sheetEntries` / `slotAreaNote` / `mergeEntries` / `stashSlots` /
`arrangeOverflowSlots` / `overflowTable` / `drawLeaders` / `gridRows` / `fitSheetText` /
`PRINT_ZOOM` / `SHEET_LAYOUTS`。

## 5. テスト方針

サンドボックス実行方式（`new Function` で関数を組み立てて実際の戻り値を見る）で書く。ソース照合だけにしない。

**追加するテスト**

- 下段9欄・メイン9件・PC横1・EV横2 → 下段は全部メイン、PC横/EV横 は下段からこぼれる
- 下段9欄・メイン6件・PC横1・EV横1 → `メイン6 | 空1 | PC横 | EV横`（右端固定とEV横最右の維持）
- 下段があふれ上段に空きがある日 → こぼれが上段の空き欄へ、注釈つき
- 上段があふれ下段に空きがある日 → 既存の救済が変わらない（回帰）
- 退避は実在する置き場の後、かつ上段の空きを先に使う
- 両段満杯 → 追記欄。順序は実在する置き場 → 退避
- **現場の実例の再現**: 2026-09-18 の画面（下段に EV横 が2件・メインが追記欄）が、
  新しい挙動では下段が全部メインになること

**書き替えが要りそうな既存テスト**（`tests/sheet-placement.test.js`、行番号は 2026-09-19 時点）

- `PC横・EV横ではEV横を右端に配置する`
- `PC横とEV横はメイン項目に挟まず右端へ連続配置する`
- `右端を予約してもメインロットは物理的に最短の下段欄へ置く`
- `sheetPlacementはグリッドセル中心に近い下段欄へメインロットを置く`
- `右端予約で欄数が減ってもあふれたメイン項目は入力順を保つ`

実装時に実際に落ちたものだけを、新しい期待値に書き替える。

## 6. 技術制約

`~/claude-lessons/lessons.md` を読んだうえで、この設計に効くものだけを挙げる。

- **テストの実行は `node --test tests/sheet-placement.test.js tests/stash-overflow.test.js`。**
  `node --test tests/` は Node v22.15.0 ではディレクトリを解決できず失敗する
- `sheetGridAnchors()` はデータ由来で DOM 実測を含まない（2026-09-17 実測確認）。
  ただし**紙の高さや欄幅を測る検証は配置図タブを表示してから**行う。
  非表示タブでは `getBoundingClientRect()` が 0（2026-08-23／2026-08-30 で2回踏んでいる）
- **計画に埋め込む検証スクリプトは、計画を確定する前に改修前のコードへ1回流す**（2026-08-30）
- `@media print` の中の宣言は `getComputedStyle` で読めない。CSSOM を走査する（2026-08-30）
- 開発中の再読込に `CACHE_VERSION` の繰り上げは効かない。ブラウザ検証の冒頭に
  **SW の unregister + `caches.delete()` + キャッシュバスティング付き URL** を定型で置く（2026-08-31）
- LAN 経由の実機は secure context でないため **SW が登録されない**。
  `CACHE_VERSION` の効果は実機では検証できない（2026-09-16）

### 6-1. 検証データを作るときの罠（2026-09-19 に3回踏んだ）

ブラウザで荷物を投入して検証する場合、次の3点を守らないと**数字が毎回変わる**。

1. **`clearLots()` は先頭で `confirm()` を出す。** 自動実行では否定されて何も消えない。
   `window.confirm` を一時的に差し替えてから呼ぶこと
2. **`clearLots()` は伝票ごと消すので入力欄が0行になる。** 先に `addSlip('fax')` で伝票を1枚作ってから
   `addItemRow()` で行を足す
3. **消さずに足すとロットが累積する。** `initLots()` が localStorage の保存分を読むため、
   リロードのたびに 16→31→42件と増える

動く投入コードの例（ロット16件・合計216P・退避47P の日を作る）:

```js
(()=>{const f=e=>e.dispatchEvent(new Event('input',{bubbles:true})),
 by=p=>[...document.querySelectorAll('#tab-input input')].filter(i=>i.placeholder===p);
 const oc=window.confirm; window.confirm=()=>true; clearLots(); window.confirm=oc;
 switchTab('input'); if(by('品名').length===0) addSlip('fax');
 let g=0; while(by('品名').length<16 && g++<60){
   const a=[...document.querySelectorAll('#tab-input button')]
     .find(b=>b.getAttribute('onclick')==='addItemRow(this)'); if(!a) break; addItemRow(a); }
 const n=by('品名'),l=by('ロット'),s=by('SNP'),q=by('個数'),Q=[60,110,160,210];
 for(let i=0;i<16;i++){ n[i].value='品目'+(i+1); l[i].value='L-'+(101+i);
   s[i].value='10'; q[i].value=String(Q[i%4]); [n[i],l[i],s[i],q[i]].forEach(f); }
 console.log('投入完了。「▶ 自動配置を作成」を押す')})()
```

4. **表の幅を実験的に差し替えるときは `.sheet table:not(.overflow-table)` を使う。**
   `.sheet table` に当てると追記欄の内側の表にも効き、欄が画面外へ流れて空に見える
