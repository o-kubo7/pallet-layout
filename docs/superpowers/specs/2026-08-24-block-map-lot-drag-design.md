# ブロック図でのロット移動（マス選択＋ドラッグ＆ドロップ）

作成日: 2026-08-24
対象: `files/index.html`, `files/sw.js`

## 背景

自動配置は「メイン → 軒下 → PC横・EV横」の優先順で機械的に列を埋める。
大枠としては妥当な結果になるが、現場の判断が入る余地が残る。

- 入庫口から遠い位置に小口が置かれる。実際には PC横 のほうが近い
- 大口の一部（3P など）を通路へ出せば、残りを詰めて置ける
- 空きのある列に 2P を混ぜれば収まりが良くなる

いずれも「自動配置の結果は概ね正しいが、印刷前に数か所だけ直したい」という性質の調整である。
現在この調整手段は無く、配置を変えるには荷物の入力か通路設定を変えて再計算するしかない。

本機能は、ブロック図上でマスを選択し、ドラッグ＆ドロップで別の列へ移す操作を追加する。

## 現状の実装

### 配置データ

配置結果は `lastSp` に保持される。`buildWork()`（index.html:874）が `SPACES` から生成する。

```js
lastSp = [
  { name:"メイン", zone:"near", orient:"v", block:3, align:"top",
    cols:[ { h:7, aisle:false, fills:[ {id:0, count:7} ] }, ... ] },
  ...
]
```

`fills[]` の要素は「どのロットが何パレット分か」だけを持ち、**列の中の位置は持たない**。
描画時に `cellsOf()`（index.html:1057）が `fills` を先頭から順に並べて位置を決める。

- メインは `align:"top"` かつ `.col.top{flex-direction:column}` なので、`fills[0]` が列の上端
- 軒下① / PC横 / EV横 は `orient:"h"` で `.hrow` は通常の flex row なので、`fills[0]` が左端

`placeLot()`（index.html:906）は 1 ロットを連続した空き列に分割して入れる。
`fillMix()`（index.html:940）は満杯時の最終手段として、既存の `fills[]` へ別ロットを `unshift`（＝上側）で差し込む。
上側に入れるのは、引き出し線の終点が既存ロットと干渉しないようにするための意図的な選択である。

`fills[]` の要素に付く `ov`（通路はみ出し）と `mix`（混載）のフラグは、
`ov` はどこからも参照されておらず、`mix` は `fillMix()` 内の holder 判定にのみ使われる。
描画・表・警告のいずれもこれらのフラグを読まない。

### 描画

`drawZone()`（index.html:1067）が `lastSp` から DOM を組み立てる。

```
.space > .grid / .grid-h
  └ .colwrap[data-space][data-col]
      └ .col / .hrow
          └ .cell × col.h        ← 現在 data 属性を持たない（index.html:1098）
      └ .colcap                   ← "7/7" や "0/5 通"
```

### 配置図の表

`renderSheet()`（index.html:1327）以下はすべて `lastSp` を読んで組み立てる。

- `sheetEntries()`（index.html:1300）— エリアごとにロットを集計し、基準エリア以外は「※PC横」等の注記を付ける
- `gridRows()`（index.html:1400 付近）— メインのグリッド、「半」マーク、太枠
- `drawLeaders()` — 下段の欄からグリッドへの引き出し線

したがって `lastSp` を書き換えれば、表・注記・半マーク・引き出し線はすべて追随する。
表側に追加の実装は要らない。

### 再計算の経路

`run()` は内部で `place()` を呼び、`lastSp` を丸ごと置き換える。呼び出しは 9 か所。

| 箇所 | きっかけ |
|---|---|
| index.html:320 / 436 | 「▶ 自動配置を作成」ボタン |
| index.html:700 | サンプル読込 |
| index.html:1147 | 「通路を編集」モードの開始・終了 |
| index.html:1155 | 編集モードで列を通路⇔通常に切替 |
| index.html:1182 / 1188 | 設定タブでのスペース定義の反映・リセット |
| index.html:1620 / 1623 | 起動時（`initLots` が復元後に必ず呼ぶ） |

**荷物の入力欄を編集しても `run()` は呼ばれない。** 入力変更後に画面の配置図が古いままなのは既存の挙動である。

### 既存の編集モード

「通路を編集」（`toggleEdit()` index.html:1141）は `document` のクリックを拾い、
`.colwrap` のクリックで `SPACES` の `aisle` を反転して `run(false)` する（index.html:1149）。

## 技術的な前提（調査済み）

設計承認前に以下を確認した。

1. **Pointer Events は Baseline「広く利用可能」** — 2020年7月から全ブラウザで利用可
   （https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events ）。
   iOS Safari を含め、本アプリの対象環境で問題ない。

2. **`touch-action` は Baseline「広く利用可能」** — 2019年9月から
   （https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action ）。
   ただし `touch-action:none` を指定した要素上ではピンチズームが効かなくなる（MDN のアクセシビリティ注記）。
   **付与はドラッグ開始時ではなく選択時に行う。** タッチでは 8px 動いた時点で既にブラウザが
   パンを開始しており、そこから `touch-action` を変えても間に合わず `pointercancel` で中断する。
   `.cell.sel` に CSS で静的に持たせ、選択を解除したときに自動で外れる形にする。
   影響を受けるのは選択中の数マス（30px 角）だけに限定される。

3. **`setPointerCapture()` 中は `event.target` がキャプチャ元に固定される** — MDN が明記している。
   ドロップ先の判定に `event.target` は使えないため、`document.elementFromPoint()` で座標から引く。

4. **HTML5 Drag & Drop API は使わない** — iOS Safari で動作しないため。Pointer Events で自前実装する。

5. **座標計算はドラッグ中のみ実行する** — 教訓「非表示タブでは `getBoundingClientRect()` が 0 を返す」
   （lessons.md 2026-08-23）に該当する処理だが、ドラッグ中は配置図タブが必ず表示されているため罠は踏まない。
   タブ非表示中に座標を測る経路は本機能に存在しない。

6. **印刷への影響は無い** — `@media print` が `#mapBody` を非表示にしている（index.html:244）。
   ブロック図と選択ハイライトは紙に出ない。印刷されるのは配置図の表のみ。

7. **PWA のキャッシュ** — 教訓（lessons.md 2026-07-09）のとおり、`index.html` を変更したら
   `sw.js` の `CACHE_VERSION` を上げないと更新が届かない。現在 v15（sw.js:6）→ v16 にする。

## 決定事項

ブレインストーミングで確定した仕様。

| 論点 | 決定 |
|---|---|
| 分割の警告 | 移動後の結果が飛び地になったら警告 |
| 既に分割済みのロット | 分割数が「増えた」ときだけ警告 |
| 容量不足の移動先 | 落とせない（ドロップ拒否） |
| 混載の縦位置 | 上に入れる（自動配置の `fillMix` と同じ） |
| 手動調整の保存 | 保存する。入力が同じ間は復元 |
| 操作の入口 | 「ロットを移動」ボタンを追加（「通路を編集」と排他） |
| 取り消し機能 | 不要。リセットは「▶ 自動配置を作成」のやり直し |
| 移動先 | 通路列・別エリア・混載のいずれも可 |
| 分割警告の強さ | 続行可の確認ダイアログ（禁止しない） |
| ドロップ先の粒度 | 列単位（混載位置が上固定なので行は見ない） |

## 設計

### 1. 状態

追加するグローバル変数は 2 つ。

```js
let moveMode = false;                          // 「ロットを移動」モード
let sel = { lotId:null, cells:new Set() };     // 選択中。cells は "スペース名|列番号|行番号"
```

配置データは `lastSp` を直接書き換える。手動調整を別データとして持たない。
「今の配置＝ `lastSp`」が常に成り立つため、表・引き出し線・メッセージは追加対応なしで追随する。

### 2. モードの排他

| モード | マスのタップ | 列のドラッグ |
|---|---|---|
| 通常 | 何も起きない | 横スクロール |
| 通路を編集（既存） | 列を通路⇔通常に切替 | 横スクロール |
| ロットを移動（新規） | 選択トグル | 選択済みマスからは移動、他は横スクロール |

- 「ロットを移動」に入ると「通路を編集」を抜ける。逆も同様
- 既存のクリックハンドラ（index.html:1149）の先頭に `if(moveMode) return;` を足す
- 「ロットを移動」ボタンは「通路を編集」の隣に置く。モード中は `btn-on` 表示
- モード中はヒント文を出す（既存の `#editHint` と同じ形式）

### 3. DOM の変更

`cellsOf()` の戻り値に行番号を含め、`drawZone()` のセル出力に属性を足す。

```js
// cellsOf(): arr[r] に row を持たせる
arr[r] = { id:f.id, seg:(k===0&&fi>0), label:"", row:r };

// drawZone(): セルのテンプレート（index.html:1098）
cells += `<div class="${cls.join(' ')}" data-row="${a.row}"`
       + (filled ? ` data-lot="${a.id}"` : "")
       + ` style="${bg?'background:'+bg:''}">${label}</div>`;
```

スペース名と列番号は親の `.colwrap[data-space][data-col]`（index.html:1104）から取る。

### 4. 選択

```
タップ（8px 未満の移動で pointerup）
  ├ sel.cells が空                    → そのマスのロットで選択開始
  ├ data-lot が sel.lotId と一致       → 選択に追加 / 既に選択済みなら解除
  └ 一致しない、または空マス           → 何も起きない
```

- すべて解除されると `sel.lotId` を null に戻し、次は任意のロットを選べる
- 別ロットへ乗り換えるための「選択解除」ボタンをモード中だけ表示する
- 選択は複数列にまたがってよい（例：隣接2列から2マスずつ、計4マス）
- 選択の反映は `.sel` クラスの付け外しのみ。`drawZone()` の再実行はしない
- 「ロットを移動」モードを抜けたとき、および `drawZone()` が走ったとき（移動の確定後・自動配置のやり直し後）は選択を解除する

`.sel` の見た目は、白い内側の枠（`box-shadow: inset 0 0 0 2px #fff`）と外周の濃い枠。
マスの背景色はロットの色なので、色ではなく枠で示す。

### 5. 移動（ポインタ処理）

```
pointerdown（選択済みマスの上）
  → 開始座標を記録。まだドラッグ確定しない
pointermove
  → 8px 以上動いたらドラッグ開始
     ・setPointerCapture()
     ・ゴースト（半透明の四角＋「部品A 3P」）を body に追加し、指へ追従
     （touch-action:none は選択時に `.cell.sel` として既に付いている）
  → ドラッグ中は毎回 elementFromPoint() で .colwrap を引き、
     移動可なら緑、容量不足なら赤でハイライト
  → ポインタが .scroller の左右 40px に入ったら横スクロール、
     画面の上下 60px に入ったらページを縦スクロール（毎フレーム 8px）
pointerup
  → ドロップ先の .colwrap を確定し、検証 → 移動
  → ブロック図の外、または移動元と同じ列なら何もしない（選択は保持）
pointercancel
  → ゴーストを消して中止
```

ドロップ先の判定に `event.target` を使わないのは、ポインタキャプチャ中は
キャプチャ元に固定されるため（技術的な前提 3）。

タップとドラッグの区別は 8px の移動量のみで行う。長押しの待ち時間は設けない。
選択済みマスからのドラッグだけを移動として扱うため、横スクロールとの競合は起きない。

### 6. 検証

`lastSp` のコピーに移動を適用し、その結果を判定する。問題があればコピーを捨てる。
巻き戻し処理を持たない。

**容量チェック（拒否）**

```
used(移動先の列) + 選択マス数 > 移動先の列の高さ  → 移動不可
```

ドラッグ中は赤く表示し、離しても何も起きない。選択は保持される。

**分割チェック（確認ダイアログ）**

`blockCountOf(sp, lotId)` を移動前と移動後で比較し、増えていれば `confirm()` を出す。

```
blockCountOf():
  エリアごとに、そのロットを含む列番号を昇順で並べる
  隣り合う列番号は 1 ブロックにまとめる
  間に挟まる列がすべて「空の通路列」の場合も 1 ブロックとみなす
  エリアが違えば必ず別ブロック
  全エリアのブロック数を合計して返す
```

文言は「部品A が 1か所から 2か所に分かれます。このまま移動しますか？」。
OK なら実行する。禁止はしない。

分割数が変わらない移動では確認を出さない（元から分割されているロットを動かす場合を含む）。

### 7. データ操作

```js
// 選択を「スペース名+列番号 → マス数」に集計し、各列から差し引いて移動先へ足す
function moveCells(next, sel, destSpaceName, destColIndex)
```

- 移動元の各列で、対象ロットの `fills` 要素の `count` を選択数だけ減らす
- 移動先の列の `fills` に `{id:sel.lotId, count:合計}` を `unshift`（＝上側／左側）で差し込む
- 移動先が通路列なら `ov:true`、既に他のロットが入っていれば `mix:true` を付ける
  （描画には影響しないが、自動配置が付けるフラグと整合させる）
- 最後に正規化する
  - `count <= 0` の要素を削除
  - 同じ列で同一ロットの要素が隣接したら統合

同じ列に同一ロットの要素が 2 つ生じうるのは、`fillMix()` がロット自身の列へ追加した場合。
正規化で統合されるため、以降の処理は「1 列に同一ロットは 1 要素」を前提にできる。

`moveCells` / `blockCountOf` / `validateMove` は DOM を触らない純粋なデータ操作とし、
コンソールから直接呼んで単体で確認できるようにする。

### 8. 保存と復元

`STORE_KEY` に `manual:"palletApp.manual"` を追加する。

```js
{ fp: <荷物入力の JSON 文字列>, sp: lastSp, lots: lastLots }
```

- 手動移動が成立するたびに上書き保存する
- 起動時、現在の入力から作った `fp` が保存値と一致すれば、`run()` を呼ばずに復元して描画する
- 一致しなければ保存を破棄し、従来どおり `run(false)` を実行する

ロットの `id` は行順の連番なので（index.html:685）、入力が完全一致すれば id も再現される。
`fp` 一致を条件にすることで、id の取り違えは原理的に起きない。

**「▶ 自動配置を作成」を押したとき**は、保存された手動調整がある場合だけ
「手動調整を破棄して自動配置し直します。よろしいですか？」と確認する。
OK なら保存を消して従来どおり実行する。手動調整が無いときは無確認（既存の挙動のまま）。

`run()` を呼ぶ残りの 5 経路も手動調整を破棄する。確認は出さない。

| 経路 | 破棄する理由 |
|---|---|
| サンプル読込（index.html:700） | 荷物が総入れ替えになる |
| 通路を編集の開始・終了（index.html:1147） | 配置の前提が変わる |
| 通路⇔通常の切替（index.html:1155） | 同上 |
| 設定タブでのスペース定義の反映（index.html:1182） | 同上 |
| 設定のリセット（index.html:1188） | 同上 |

起動時の 2 経路（index.html:1620 / 1623）は破棄ではなく、上記の復元分岐が入る箇所である。

### 9. run() の分割

復元経路は `run()` を通らないため、`run()` の後半を切り出して共用する。

```
run(goMap)
  ├ 前半：readLots() → place() → lastSp/lastLots/hasResult の更新   ← そのまま
  └ 後半：renderResult()                                            ← 切り出す
        ・警告／完了メッセージの生成（あふれ・通路・混載・表の欄数超過）
        ・凡例の描画
        ・drawZone() × 2（倉庫外・倉庫内）
        ・合計行の更新
        ・showMapState()
```

復元処理は `lastSp` / `lastLots` / `hasResult` を復元したうえで `renderResult()` を呼ぶ。
色（`colorOf`）は `lastLots` の並び順から `PALETTE` で再計算できるため保存しない。

SNP 未入力や種別の食い違いの警告は `readLots()` の戻り値（`unknown` / `typeMix`）から作られる。
復元経路でも `readLots()` は呼び、この 2 つだけを受け取ってメッセージに使う。
配置には保存済みの `lastSp` を使い、`place()` は呼ばない。
`fp` が一致している以上 `readLots()` の結果は保存時と同じになるため、表示は食い違わない。

切り出しは機械的で、既存の動作は変わらない。

### 10. CSS

```
.cell.sel        選択中のマス。内側に白 2px、外周に濃い枠
.colwrap.drop-ok  ドラッグ中の移動可の列（緑の outline）
.colwrap.drop-ng  ドラッグ中の容量不足の列（赤の outline）
.dragghost       指に追従する半透明の表示。position:fixed, pointer-events:none
```

`.cell.sel` には `touch-action:none` を含める。JS での付け外しはしない。
選択された時点で付き、解除された時点で外れる。

`user-select:none` と `-webkit-touch-callout:none` を `.cell` に付け、
長押し時の選択ハンドルやコールアウトが出ないようにする。

## 既存の表示への影響

いずれも既存ロジックが自動で反応するもので、追加実装は要らない。挙動として記録する。

1. **「半」マークが通路側へ移る** — `gridRows()` は「通路にはみ出していれば半マークは通路のマス、
   なければ通常列の最後」というルール（index.html:1420 付近）。
   大口の一部を通路へ出すと、半マークが通路列へ移動する。

2. **引き出し線が斜めになる場合がある** — 混載で押し下げられた既存ロットは開始行が 0 より下がり、
   線の終点がその位置になる（index.html:1447 のコメントに既記載）。
   手動混載でこの状況を作れてしまう。既存の制約であり、今回は解消しない。

3. **別エリアへ移すと表に注記が付く** — `sheetEntries()` の `baseArea` 判定により
   「※PC横」等が自動で付き、下段のパレット数が分かれる。

4. **警告メッセージは追随する** — 「通路へのはみ出しあり」「混載あり」は
   `lastSp` の走査で判定されるため、手動移動の結果が反映される。

## 対象外

- **「入りきらない荷物」の手動配置** — あふれたパレットはブロック図にマスが無く選択できない。
  手で空きを作っても `lot.rem` は変わらず、あふれの警告は解消しない。
- **列内の位置の指定** — 配置データは列内の位置を持たない。
  列の途中のマスを選んで動かすと、残ったマスは詰めて再描画される。
- **取り消し／履歴** — リセットは「▶ 自動配置を作成」のやり直しで行う。
- **引き出し線が斜めになる問題の解消** — 既存の制約として残す。
