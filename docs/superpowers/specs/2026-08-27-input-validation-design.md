# 入力の不完全な行を赤枠で示す（設計書・承認済み 2026-08-27）

`docs/superpowers/specs/2026-08-26-input-validation-design-draft.md` のドラフトを引き継ぎ、
未確認だった2点を確定させたうえで正式な設計書としてまとめたもの。ドラフトは役目を終えた。

## 背景

実機（Pixel 9a / Android / Gboard）での確認中に出た要望。

> 個数などが未入力の荷物がある状態で、「自動配置を作成」をタップすると、アラートは出ますが、
> 配置編集タブに飛びます。情報の入力が不完全な項目があれば、web の情報入力でよくあるような
> 赤枠などで目立たせる、そして次のタブに飛ばないようにしてください。

同じ実機で「個数が未入力の荷物があっても警告が出ず、そのまま自動配置されて配置編集タブへ飛ぶ」
ことを再現確認済み。

## 現状の挙動（コードで確認済み）

`files/index.html` の `readLots()`（713行目付近）:

- `v.qty<=0` の行は**黙って無視**される（`unknown` にも入らない）
- `v.snp<=0` の行は `unknown` に入り、`#messages` に警告が出る

`run(goMap)`（1366行目付近）:

- `lots.length===0 && unknown.length===0` → `alert("荷物を1件以上入力してください。")` して return（タブに飛ばない）
- `lots.length===0`（`unknown` はある）→ 警告を出して `switchTab('edit')` ← タブに飛ぶ
- それ以外（有効な荷物が1件でもある）→ 配置を作り、警告を出して `switchTab('edit')` ← タブに飛ぶ

「一部の行だけ正しく、他が未入力」の場合、個数が空の行は警告すら出ないまま無視され、
残りの行で配置が作られてタブへ遷移する。これが今回直す対象。

## 確定した仕様

brainstorming で5点を確認し、すべて確定した。

1. **必須項目は品名・個数・SNP。ロットは任意。**
   （ロット番号がまだ分からない荷物も配置したい場面がありうるため）
2. **赤枠はその欄に入力した時点で即消す。**
3. **エラー時は「最初の欄へスクロール＋フォーカス＋画面内メッセージ」。** `alert()` は出さない。
4. **赤枠は「赤い枠線＋薄い赤背景」。** `border-color:#dc2626` / `background:#fef2f2`。
   既存のドラッグ不可（`#dc2626`）・削除ボタン（`#fee2e2`）と同系統で、配色から浮かない。
5. **欠けている欄だけを赤くする。** 行やカード全体は赤くしない。
   「品名だけ入れた行」は、品名がマスタ登録済みなら `nameChanged()` が SNP を自動補完するので
   個数だけが赤枠、未登録の品名なら SNP と個数の2つが赤枠になる。これで意図どおり。

## 設計

### 判定 — `validateLots()`

`#lotTable tbody tr` を走査し、各行を3通りに分ける。判定には既存の `rowValues(tr)` を使う
（`{type, name, lot, snp, qty, cells}` を返す。`cells` は `0=種別 1=品名 2=ロット 3=SNP 4=個数`）。

| 分類 | 条件 | 扱い |
|---|---|---|
| 空行 | `!v.name && !v.lot && v.snp<=0 && v.qty<=0` | スキップ |
| 不完全 | 空行ではなく、`!v.name` / `v.snp<=0` / `v.qty<=0` のいずれか | エラー |
| 完全 | 上記以外 | 通す |

種別（`<select>`）は常に値を持つので判定に含めない。
末尾に常に空行がある UI なので、空行をスキップしないと常にエラーになる。

欠けている欄の名前は `"name"` / `"snp"` / `"qty"` の3種で、**必ずこの順に並べる**。
テーブルもカードも欄の並びが 品名 → ロット → SNP → 個数 なので、この順が「最初の欠け欄」になる。

返り値:

```js
[{ tr, i, fields: ["name", "qty"] }, ...]   // i は 0 始まりの行番号
```

`i` はカード側の欄を `.lotcard[data-i="${i}"]` で引くために要る。

### エラー状態の持ち方 — `tr.dataset.err`

```js
tr.dataset.err = "name,qty";   // 欠けている欄だけをカンマ区切りで
```

行の追加・削除で番号がずれない。`syncCards()` はカードだけを作り直して `<tr>` は残すので、
カード再生成後もエラー状態が生き残る。

（変数の配列で「行番号 → 欠けている項目」を持つ案は、行を消したときに番号がずれる。
教訓 2026-07-30 の「状態は『どの入力に対する結果か』と一緒に持つ」に沿って、
状態を対象の `<tr>` そのものに貼る形にした。）

### 見た目

```css
.err{border-color:#dc2626 !important;background:#fef2f2 !important}
```

`background` にも `!important` が要る。カードの `.fld input{...;background:#fff}` は
セレクタの詳細度が `.err` より高く、そのままでは白背景に負ける。

クラスは状態そのものではなく `tr.dataset.err` の写しとして扱う。
`applyRowErr(tr, i)` 1本が dataset を読んで、テーブル側（`cells[1]/[3]/[4]`）と
カード側（`.fld[data-f="…"]` の中の `input` / `select`）の両方に `classList.toggle()` する。

**カードは `syncCards()` で毎回作り直されるので、後から付けたクラスは次の再生成で消える。**
そこで `syncCards()` の末尾で全行ぶんを付け直す。
（同じ罠はオートコンプリートの `#acList` を `<body>` 直下に置いた理由と同根。）

**再適用のフックは2か所で足りる。**
`rowChanged()` / `cardSnpSelect()` / `acPick()` / `snpAdd()` / `cardType()` / `removeRow()` は
いずれも中で `syncCards()` を呼ぶので、末尾のフック1つで拾える。
唯一 `cardEdit()` だけは入力中のフォーカスを保つため `syncCards()` を呼ばず
`updateCardFoot()` で済ませているので、ここにも呼び出しを足す。

SNP 欄は候補が2つ以上あると `<select>` になるので、`<input>` だけを対象にすると当たらない。
`<select>` にも `.err` を付けられるようにする。

### 画面内メッセージ

「荷物の入力」カードの `<h2>` 直下に新しい要素を置く。

```html
<div id="inputErr" class="inputerr" style="display:none"></div>
```

```
⚠ 入力が足りない荷物が 2 件あります（品名・個数・SNP は必須）
```

件数は**行数**で数える（欠けている欄の数ではない）。
既存の `#messages` は `#tab-edit` の中にあるので入力タブでは使えない。

### 解除

**その行に `dataset.err` があるときだけ**再判定する。

- 埋まった欄の `.err` を外し、`dataset.err` を残りの欠け欄で更新する
- 全部埋まったら `dataset.err` を削除する
- どの行にも `dataset.err` が無くなったら `#inputErr` を隠す

`dataset.err` の無い行を編集しても何も起きない。ボタンを押す前は赤枠が一切出ない。

### 実行時の動作

`runFromButton()` の先頭、未登録品目チェックより**前**に置く。

```
不完全な行あり
  → 全該当行に dataset.err を設定し、赤枠を反映（テーブル＋カード）
  → #inputErr に帯を出す
  → 最初の不完全行の最初の欠け欄へ フォーカス → スクロール
  → return（タブに飛ばない・未登録品目の登録もしない）
```

`hasManual()` の確認ダイアログとの順序は、バリデーションを**先**にする。
入力が不完全なまま「手動調整を破棄しますか」と聞くのは筋が悪く、破棄せずに済む。

### フォーカス先の選び方

600px 以下では `#lotTableWrap` が `display:none`、それより広いとカード（`.lotcards`）が
`display:none` になる。**非表示側の欄に `focus()` しても効かない。**

```js
const tableVisible = document.getElementById("lotTableWrap").offsetParent !== null;
```

- 表示中がテーブル → `tr.querySelectorAll("select,input")[idx]` を引く
- 表示中がカード → `.lotcard[data-i="i"] .fld[data-f="f"]` の中の `input` / `select` を引く

既存の `focusField(i, f)` は使わない。あれはカード専用なうえ、キャレットを末尾へ送るために
`focus()` を `preventScroll` 無しで呼ぶ。今回フォーカスするのは必ず**空の欄**なので
キャレット位置は意味を持たず、`preventScroll` を使えないほうが害になる。

呼ぶ順序は `focus({preventScroll:true})` → `scrollIntoView({behavior:"smooth", block:"center"})`。
先に `focus()` させておき、そのあと自前で位置を決める。逆順だと `focus()` の既定スクロールで
せっかく合わせた位置が飛ぶ。

### 触らないもの

- `readLots()` の `unknown`（SNP が 0 の行）と `inputWarnHtml()` の警告表示はそのまま残す。
  新バリデーションで実質届かなくなるが、`redraw()` 経由など他の呼び出し元があるため
- `alert("荷物を1件以上入力してください。")` もそのまま（完全に空の表で押した場合の経路）
- `loadSample()` が呼ぶ `run(true)` は通さない（サンプルは常に完全なため）
- `run(goMap)` 自体には手を入れない。バリデーションは `runFromButton()` にだけ置く

## 技術制約

| 依存 | 対応状況 |
|---|---|
| `element.focus({preventScroll:true})` | Chrome 64+ / Safari 15+ / Firefox 68+。Android Chrome 対応済み |
| `scrollIntoView({behavior, block})` | 全モダンブラウザ対応 |
| `HTMLElement.dataset` | 制約なし |
| `offsetParent === null` による可視判定 | `position:fixed` の要素では使えないが、`#lotTableWrap` は static なので問題ない |

**PWA:** `files/sw.js` は HTML を network-first で配るので `index.html` の変更は届く。
ただしファイル先頭の注記どおり `CACHE_VERSION` を `v17` → `v18` に上げる。

**実機依存:** 合成イベントには既定動作が無いため、フォーカス移動と Gboard の挙動は
ブラウザの自動操作では確定しない。Pixel 9a 実機での確認を完了条件に含める。

## 実機での確認手順（Pixel 9a）

1. 「入力をクリア」で空にする
2. 1行目に品名「部品A」だけ入れる（SNP が 10 に自動補完される）→「▶ 自動配置を作成」
   → 帯が出る／個数欄だけが赤枠／**配置編集タブに飛ばない**／個数欄にフォーカスが来る
3. 個数を入力 → 赤枠がその場で消え、帯も消える
4. もう一度ボタン → 配置が作られ、配置編集タブへ飛ぶ
5. 未登録の品名（例「テスト品」）だけの行を作ってボタン → SNP と個数の2つが赤枠
6. 行を10行ほど増やし、画面外になる最下行だけ不完全にしてボタン
   → その行まで自動でスクロールし、赤枠が見える状態で止まる
7. 完全な行と不完全な行が混在する状態でボタン → 配置は作られず、不完全な行だけが赤枠
8. PC 幅（ウィンドウを 600px より広く）でも 2〜7 が同じように動く
