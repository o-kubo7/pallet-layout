# 上段のあふれを下段の空き欄で受ける 設計書

- 日付: 2026-09-01
- 対象: `files/index.html`（配置図の表）
- 前提: `docs/superpowers/specs/2026-09-01-sheet-slot-expand-design.md`（入りきらない日だけ欄を広げる）の実装が入っていること

---

## 1. 背景

配置図の表は上段（軒下ブロック）と下段（メインブロック）の 2 段に分かれ、段ごとに欄数の上限がある。
欄数は様式で決まり、`normal` は上段 4 欄・下段 7 欄、`wide` は上段 5 欄・下段 8 欄。

上段に載るのは `軒下①`（基準）`軒下②`『出庫口横』`5棟壁際` の 4 エリア、
下段に載るのは `メイン`（基準）`PC横`『EV横』の 3 エリア（`files/index.html` の `DEFAULT_SPACES` の `sheet` 属性）。

現場から出た実例（2026-09-01）:

- 荷物 13 件。上段に 6 件・下段に 7 件が割り当たった
- `wide` に切り替わっても上段は 5 欄しかないので、6 件目の `製品4`（ロット 444・4P 半）が紙から落ちた
- 一方で**下段は 8 欄のうち 7 欄しか使っておらず、1 欄が空いていた**

下段の欄数は下段のエリア数で頭打ちになる（メインの荷物がいくら多くても、まとめの結果として並ぶ欄の数には限りがある）。
つまり「上段があふれているのに下段が空いている」日が構造的に起こる。

この空き欄を上段のあふれの受け皿にする。

読む人が誤解しない根拠は既に紙の中にある。

- **注釈がある欄はメイン以外**（下段では既に `※PC横` `※EV横` がそう読まれている）
- **引き出し線がない欄はグリッドに位置を示さない**

救済した欄はこの 2 つを両方満たすので、下段の既存の読み方のままで理解できる。

---

## 2. 決定事項

1. 救済の向きは**上段 → 下段のみ**。下段 → 上段はやらない
2. **`wide` への切り替えを先に判定し、救済は最後の手段**にする
3. 救済した欄には**置き場所のエリア名を必ず注釈として出す**
4. 救済した欄には**引き出し線を引かない**（アンカーの有無に頼らず、明示的に引かせない）
5. 救済が起きた日は**画面にだけ**告知する。紙には出さない
6. 上段・下段の欄と様式を決める処理を **1 つの関数 `sheetPlacement()` に集約**し、警告と紙の両方がそこを通る

### 検討して採らなかった案

**下段 → 上段の救済もやる（双方向）**
下段の荷物（メイン）にとっては引き出し線がグリッド上の位置を示す主情報で、上段へ移すとその線が失われる。
さらに上段の見出しは「軒下」なので、メインの荷物がその下に並ぶと置き場所を誤読させる。採らない。

**`normal` のまま救済して収まるなら `wide` にしない（救済を先に）**
紙の見た目（列幅 48px）が変わる日は減るが、上段の荷物が下段に混ざる日が増える。
上段の荷物はできるだけ上段に並んでいるほうが現場で読みやすい。救済は最後の手段に置く。

**`sheetSlots()` の中で救済する**
`sheetSlots(tier)` は段ごとに独立して呼ばれ、様式（`lay`）を知らない。
一方 `lay` は上段・下段の件数から決まるので、`sheetSlots` の中で救済しようとすると循環する。採らない。

**救済の計算を警告側と `renderSheet()` の 2 か所に書く**
前回の改修（2026-09-01 欄を広げる）で潰したばかりの不都合が再発する。
片方だけが救済を知っていると、警告の件数と実際に紙へ出る欄がずれる。採らない。

## 3. 決めの流れ

`sheetPlacement()` が次の順で決める。

```
topAll    = sheetSlots("top")                 // 上段の欄（まとめ後）
bottomAll = sheetSlots("bottom")              // 下段の欄（まとめ後）
lay       = sheetLayout(topAll, bottomAll)    // 様式の判定は救済前の件数で行う（現行のまま）
free      = max(0, lay.bottom - bottomAll.length)   // 下段の空き欄
over      = max(0, topAll.length - lay.top)         // 上段のあふれ
n         = min(free, over)                         // 実際に回せる数
moved     = topAll[lay.top ... lay.top+n]           // 回す欄（上段の並び順のまま先頭から）
bottom    = bottomAll ++ moved                      // 下段の末尾に足す
```

冒頭の実例に当てはめると:

| | 件数 | 様式 | 空き | あふれ | 救済 | 結果 |
|---|---|---|---|---|---|---|
| 上段 | 6 | `wide` 5 欄 | — | 1 | −1 | 5 欄（`製品4` が下段へ） |
| 下段 | 7 | `wide` 8 欄 | 1 | 0 | +1 | 8 欄（8 欄目が `製品4`） |

紙から落ちる荷物はゼロになり、欄数超過の警告は消える。

### 救済しても足りない日

`free` が 0 の日、または `over` が `free` を超える日は、回しきれなかった分がこれまでどおり紙から落ちる。
その分だけを**今の文言・今の数え方（`lotsIn` で `members` を合計）で警告する**。

- 上段の残り = `topAll.length - lay.top - n` 件
- 数える対象 = `topAll.slice(lay.top + n)`

下段は救済で増えるが、`free` の範囲でしか足さないので下段のあふれは増えない。

## 4. 救済した欄の見え方

### 4-1. 位置

下段の末尾（右端）から詰める。上段での並び順は変えない。

下段の品名欄は太枠で囲われており（`slotCells()` の `extra` が `i===0` に `bl2`、`i===count-1` に `br2` を付ける）、
これは欄の index で決まるので、末尾に足しても囲みの見た目は保たれる。

### 4-2. 注釈

**置き場所のエリア名を必ず出す。**

上段の欄は「上段の基準エリア（`軒下①`）を除いた残り」を注釈にしているため、`軒下①` だけに置かれた荷物は注釈が空になる。
下段へ回すとその欄にとって注釈が唯一の場所情報になるので、**基準を除かずに全エリア名から作り直す**。

- `軒下①` だけ … `※軒下①`
- `軒下①` と `軒下②` にまたがる … `※軒下①・軒下②`
- `軒下②` だけ（上段でも `※軒下②` だった）… `※軒下②`（変わらない）

### 4-3. 引き出し線

**救済した欄からは引き出し線を引かない。**

`drawLeaders(anchors, slotIds)` は下段の欄の index 順に `slotIds` を受け取り、
`anchors` に無い id は線を引かない（`files/index.html` の `drawLeaders`）。
上段の荷物はメインに乗っていないので、放っておいても線は引かれない。

それでも**明示的に `null` を渡して引かせない**。理由は分割配置の日:

同じロットが `メイン` と `軒下①` の両方に分かれて置かれた日、そのロットは下段（メイン分）にも上段（軒下分）にも欄を持つ。
上段の欄が救済されて下段の末尾に来ると、**同じ id の欄が下段に 2 つ**並ぶ。
アンカーの有無に任せると、救済した欄からもメインの同じマスへ 2 本目の線が伸び、
「この軒下の荷物がメインのここにある」と誤読させる。

実装では救済した欄に印（`fromTop`）を付け、`drawLeaders()` へ渡す id をその欄だけ `null` にする。

## 5. 画面の告知

`wide` の告知と同じ `#sheetMsg` に 1 行足す。

> ※ 上段に入りきらない 1 件を下段の空き欄に回しています。

- 件数は**欄の数ではなく荷物の数**（`lotsIn` と同じ数え方。まとめた欄は複数のロットを含む）
- `#sheetMsg` は印刷 CSS で `display:none` なので**紙には出ない**
- `wide` の告知と同時に出る日がある。その場合は 2 行になる（`wide` の告知 → 救済の告知の順）

## 6. 実装対象

触るのは `files/index.html` の 5 か所と `files/sw.js` の 1 行。

### 6-1. `sheetPlacement()` を新設

`sheetSlots()` の直後に置く。返すのは `{lay, top, bottom, moved}`。

- `top` … 上段の欄（救済分も含んだ全件。紙に出るのは先頭 `lay.top` 件で、`slotCells()` が切る）
- `bottom` … 下段の欄 ＋ 救済した欄
- `moved` … 救済した欄の配列（告知の件数と、警告の起点に使う）

救済した欄は元の欄を複製して `fromTop:true` と作り直した `note` を持たせる。元の欄は書き換えない。

### 6-2. 欄数超過の警告（`renderResult()` 内）

`sheetSlots()` を 2 回呼んでいる箇所を `sheetPlacement()` の 1 回に置き換える。
上段の残り件数の起点を `lay.top` から `lay.top + moved.length` にする。
**警告の文言と `lotsIn` の数え方は変えない。**

### 6-3. `renderSheet()`

`sheetSlots()` の 2 回呼びと `sheetLayout()` を `sheetPlacement()` の 1 回に置き換える。
`top` / `bottom` / `lay` の使い方は現行のまま。

### 6-4. `drawLeaders()` へ渡す id

`bottom.map(e=>e.lot.id)` を `bottom.map(e=>e.fromTop ? null : e.lot.id)` にする。

### 6-5. `fitSheetText()`

現在は様式（`lay`）を省略可の引数で受けている。これを配置（`sheetPlacement()` の戻り値）を受ける形に変える。
**省略可のままにすること。** `applyDisplay()` が引数なしで呼ぶので、必須にすると表示設定を変えた瞬間に落ちる。
省略時は自分で `sheetPlacement()` を引く。

### 6-6. `files/sw.js` の `CACHE_VERSION`

最後に繰り上げる（`v26` → `v27`）。

### 6-7. 触らないもの

- 総幅 672px（`.sheet table` の `width/min-width/max-width`）
- `SHEET_LAYOUTS` の欄数・列数・列幅、`sheetLayout()` の判定条件
- 配置アルゴリズム（`areaCandidates` ほか）
- まとめ（`mergeEntries()`）の規則
- 欄数超過の警告の**文言**と `lotsIn` の数え方
- グリッド（`gridRows()` / `gridNoticeRow()`）
- 表示設定（項目を増やさない。`STORE_KEY` を増やさない）

## 7. 技術制約

この改修は新しいブラウザ API を使わない。DOM の組み立てと計測だけで、
権限・オフライン・ストレージ・PWA 固有の制限に新しく触れる箇所はない。
`~/claude-lessons/lessons.md` から、この改修に効く既存の教訓を引く。

### 7-1. Service Worker が cache-first（2026-07-09）

`files/sw.js` はキャッシュ優先。`CACHE_VERSION` を上げないと、インストール済みの端末に更新が永続的に届かない。
最後のタスクで必ず繰り上げる。

検証を `file://` で行う場合は Service Worker が登録されないので回り道は起きない。
`http` で開く場合は unregister と `caches.delete()` を先に行う。

### 7-2. 非表示タブでは `getBoundingClientRect()` が 0 を返す（2026-08-23 / 2026-08-30）

幾何を測る前に必ず `switchTab('sheet')` を呼ぶ。タブの識別子は `'sheet'`。
`drawLeaders()` 自身も `base.width` が 0 なら描かずに帰るので、非表示のまま測ると「線が 0 本」に見える。

### 7-3. `@media print` の中の宣言は `getComputedStyle` で読めない（2026-08-30）

印刷の収まりを確かめるときは CSSOM（`document.styleSheets` → `CSSRule.MEDIA_RULE`）を走査する。
今回は欄数も列数も変わらない（救済は空き欄を埋めるだけ）ので、印刷高さは前回の実測（`wide` で 666.4 ≦ 上限 718.5）から増えない。
ただし救済した欄の注釈が増えるぶん、注釈行の折り返しが起きれば高さが伸びうるので、**印刷高さは再測する**。

### 7-4. 背景色は既定で印刷されない（2026-08-23）

救済した欄を色で区別してはいけない。区別は注釈（文字）と引き出し線の有無だけで行う。
この設計はそれに従っている。

### 7-5. 新設した状態が「到達不能」でないことを先に確かめる（2026-07-26 / 2026-08-31）

救済が起きるには「上段があふれ、かつ下段に空き欄がある」日が必要で、
これは配置アルゴリズムの結果として作られる。**入力を書いただけでは到達を保証できない。**
実装の前に、フィクスチャが実際にその状態へ到達することを実測で確認する（§8-1）。

### 7-6. コメントに書いた前提は更新されない（2026-07-19）

`drawLeaders()` の「メイン外のロットには線を引かない」というコメントは、
救済後は「メイン外のロットには線を引かない ＋ 救済した欄には id を渡さない」に変わる。
コメントも一緒に直す。

### 8-2. 測る項目

1. **非退行（通常モード）**: `SAMPLES.basic` で列数 14・列幅 48px・上段 4 欄 96px・下段 7 欄 96px・引き出し線 5 本・警告なし・告知なし
2. **救済が起きる**: 上のフィクスチャで下段が 8 欄になり、8 欄目の品名が `製品4`、ロットが `444`
3. **注釈**: 救済した欄に `※` で始まる注釈が出る（`軒下①` だけの荷物なら `※軒下①`）
4. **引き出し線**: 救済した欄からは線が出ない。下段の他の欄の線の本数は救済前と変わらない

6. **回しきれない日**: 下段に空きが無い状態を作り、残った分だけが今の文言で警告される

8. **表示設定から落ちない**: `applyDisplay()` を引数なしで呼んでも例外にならず、告知が消えない
9. **印刷の収まり**: 救済が起きた日の印刷高さが上限（718.5）以内

## 10. 既知の制限

- 救済できるのは下段の空き欄の数まで。上段が大きくあふれ、下段も埋まっている日は従来どおり紙から落ちる
- 救済した欄は下段の末尾に付くので、下段の並びは「メイン → PC横・EV横 → 軒下から回ってきた分」になる。
  上段の並び順は保つが、下段全体としてはエリアの並び順が一巡する形になる
- 上段の荷物が下段に現れることで、「軒下の荷物は上段だけを見ればよい」という読み方は成り立たなくなる。
  注釈と引き出し線の有無で読み分ける前提に立つ（§1）
