# パレット配置図アプリ 操作説明書 設計書

日付: 2026-09-13

## 1. 目的

現場でアプリを操作する利用者が、文章を読み込まなくても図を追って基本操作を完了できる説明書を作る。
初回利用時は一連の作業を短時間で体験でき、2回目以降は画面名や困りごとから必要な操作だけを探せる構成にする。

説明書の最後には、品目マスタ、配置マス、表示設定、データ保存、公開・更新を扱う管理者向けの章を置く。

## 2. 対象読者と説明範囲

### 2-1. 主対象

- 現場で伝票を入力し、配置を調整し、配置図を印刷する利用者
- PCまたはスマートフォンから初めてアプリを使う人
- 作業中に特定の操作だけを調べたい人

### 2-2. 詳しさ

「基本の流れ＋よく使う編集操作＋注意点」を扱う。
配置計算の内部実装やすべての例外を解説する開発者向けリファレンスにはしない。

### 2-3. 対象外

- JavaScript関数や保存データ構造の詳細
- 配置アルゴリズムの実装解説
- 実在する顧客名、品名、伝票、ロット番号を使った例
- Gitやソースコード編集を前提とする日常利用者向け手順

公開・更新手順のうち管理者が必要とする内容は、管理者向け章にまとめる。

## 3. 採用する説明方式

### 3-1. クイックスタート＋逆引き型

冒頭のクイックスタートで、組み込みサンプルを使い次の流れを一度体験する。

1. 搬入日と朝／昼を選ぶ
2. FAX伝票を追加し、品名・ロット・SNP・個数を入力する
3. 自動配置を作成する
4. 配置編集で結果を確認し、1回だけロットを移動する
5. 配置図を開いて印刷する

クイックスタートでは配置不可エリア、退避スペース、細かな表示設定を詳説しない。後続の画面別・目的別の章で扱う。

### 3-2. 実画面＋模式図のハイブリッド

- 実際に押す場所は、現行画面のスクリーンショットへ番号を付けて示す
- 操作前後の変化や作業全体の流れは模式図で示す
- 1項目は原則1操作に絞り、本文は2〜3文を目安にする
- PCとスマートフォンで表示や操作が異なる箇所は両方を載せる
- 注意、禁止、補足は同じ見た目の部品で統一する
- 色が失われても意味が通じるよう、色に加えて番号、アイコン、見出し、枠線を使う

## 4. 章立て

### 4-1. クイックスタート

- アプリで行う作業の全体図
- サンプルを使った入力から印刷までの最短手順
- 印刷前に見る最小限の確認事項

### 4-2. 入力する

- 搬入日と朝／昼の切替
- FAX伝票と仮伝票の違い
- 伝票の追加、品目の追加、削除
- 品名、ロット、SNP、個数、種別の入力
- パレット数の自動計算と端数
- 品名候補と品目マスタからのSNP補完
- 入力エラーの見方と直し方
- 入力を変更した後に再配置が必要になること

### 4-3. 自動配置を作る

- 「満杯時に混載を許可」の意味
- 「自動配置を作成」の実行
- 配置順、充填品の優先、ロット単位の基本ルール
- 色、凡例、「越」「混」、合計・配置済み・あふれの見方
- 入りきらない荷物がある場合
- 未登録品目を品目マスタへ登録する確認

### 4-4. 配置を編集する

- マスのタップ選択、なぞり選択、選択解除
- 選択したロットのドラッグ移動
- 直前のなぞりの取り消し
- 退避スペースへ移す、倉庫へ戻す
- 退避中の荷物は配置図へ出ないこと
- マスの大きさ、案内、退避スペース位置の変更
- 配置不可エリアの編集と、自動配置の再実行
- 手動調整を破棄する確認が出る操作

### 4-5. 配置図を確認・印刷する

- 朝／昼の切替と、選択中の時間帯だけが印刷対象になること
- 配置図の欄、引き出し線、注釈、パレット数の見方
- 下段欄が対応エリアに近い位置へ割り当てられること
- 表示倍率の変更
- 警告の確認
- 印刷前に退避スペースとあふれを確認すること
- 印刷ボタンからA4横の配置図を印刷する手順

### 4-6. 困ったとき

- 入力変更後に配置編集・配置図が開けない
- 入力を元に戻すと保存済みの配置が復元される場合
- 荷物が配置図に出ない（退避、あふれ、掲載先設定）
- 古い画面が表示される、更新案内が出る
- 別の端末で保存データが見つからない
- ブラウザのサイトデータ削除後に元へ戻せない
- 文字や図が紙で見づらい場合の印刷設定

### 4-7. 管理者向け: 設定と運用

- 品目マスタの追加、削除、同じ品名に複数SNPを登録する方法
- 品目マスタJSONの保存・読込と、含まれないデータ
- 配置マス設定の各項目、行順の意味、反映時の注意
- 表示設定と、文字が自動で横方向に縮むこと
- 端末単位のlocalStorage保存と消失条件
- PCとスマートフォンのデータが自動同期されないこと
- ホーム画面への追加とオフライン利用
- GitHub Pagesへの公開
- アプリ、説明書、図、PDF、Service Workerの更新手順

## 5. 成果物

### 5-1. `files/manual.html`

説明書の原本とする。次を備える。

- PCとスマートフォンに対応するレスポンシブ表示
- 章へ移動する目次
- 現在位置が分かる章見出し
- 元のアプリ画面を閉じてしまった場合に使う「アプリを開く」リンク
- 「印刷する」ボタン
- 画像が表示できない場合にも内容が分かる代替テキストとキャプション

### 5-2. `files/manual-assets/`

- 組み込みサンプルだけを使った画面キャプチャをPNGで保存する
- 実在する業務データを撮影しない
- 操作番号は画像に焼き込まず、`manual.html` の図上へ割合座標で重ねる
- 模式図はHTML/CSSまたはインラインSVGで構成し、印刷時にも鮮明さを保つ
- 画像ファイル名は章と内容が分かる名前にする

### 5-3. `files/manual.pdf`

`manual.html` から生成する配布用PDFとする。
HTMLと同じ章番号、見出し、説明、図を持つ。HTML更新時にはPDFも同時に再生成する。

### 5-4. 既存ファイルの変更

- `files/index.html`: ヘッダー右上に「？ 説明書」を追加する
- `files/sw.js`: 説明書と必須画像を事前キャッシュへ追加し、キャッシュ版を更新する
- `files/README.md`: 利用者向け説明書へのリンクを追加する。既存の開発・公開手順は維持する

## 6. アプリから説明書への移動

- 「？ 説明書」はヘッダー右上に置き、4つの作業タブとは分ける
- PCとスマートフォンの両方で常時見つけられる表示にする
- `target="_blank"` と `rel="noopener"` を付け、新しいタブまたはウィンドウで `manual.html` を開く
- 元のアプリ画面を残すことで、開いていたタブ、スクロール位置、配置編集の選択状態を維持する
- 説明書のヘッダーには、元のアプリを閉じた場合の代替経路として「アプリを開く」を置く
- ホーム画面PWAでは説明書が通常ブラウザ側へ開く場合があるが、作業中のPWAを残すことを優先する
- アプリの配置図を印刷するときは、説明書リンクを既存の印刷CSSで非表示にする

## 7. ブラウザ表示と印刷表示

### 7-1. ブラウザ

- 本文の最大幅を設け、ワイド画面で文章と図が横に間延びしないようにする
- PCでは章目次を左側または上部へ固定し、スマートフォンでは折りたたみ式または横スクロール式にする
- 見出しリンクで目的の操作へ直接移動できるようにする
- タップ対象はスマートフォンでも押しやすい大きさにする

### 7-2. 印刷・PDF

- A4縦を基本とする
- ブラウザ用の目次、移動ボタン、印刷ボタンは印刷時に隠す
- 章、操作項目、図、注意枠が不自然に分断されないよう改ページを指定する
- 背景色が省略されても理解できるよう、白黒でも残る番号、文字、輪郭線を使う
- `print-color-adjust: exact` と `-webkit-print-color-adjust: exact` は補助として使うが、色の保持を前提にしない
- PDF生成後に全ページを画像化し、切れ、重なり、空白ページ、文字の小ささを目視確認する

## 8. 技術制約

### 8-1. 印刷CSS

`@media print` で画面用UIを除外し、`@page` で用紙サイズと余白を指定できる。
ただし、ブラウザとプリンタは背景色や背景画像を省略することがあり、`print-color-adjust: exact` も利用者設定より優先される保証はない。

参考:

- MDN, Printing: https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries/Printing
- MDN, `print-color-adjust`: https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/print-color-adjust
- MDN, `Window.print()`: https://developer.mozilla.org/en-US/docs/Web/API/Window/print

過去の教訓「ブラウザは既定で背景色を印刷しない」を反映し、図解は色だけに意味を持たせない。印刷プレビューと生成PDFのカラー・グレースケール表示で確認する。

### 8-2. Service Workerとオフライン

現行のService Workerは、HTMLをネットワーク優先、その他のファイルをキャッシュ優先で扱う。
`manual.html` と説明に必須の画像は `PRECACHE` へ加え、初回インストール後にオフラインでも説明書を開けるようにする。

`Cache.addAll()` は列挙した取得のいずれかが成功応答でなければ失敗するため、登録した全パスの存在確認を完了条件にする。
PDFは大きくなり得るため事前キャッシュには含めない。オンラインで一度開けば現行のfetch処理により通常キャッシュされるが、オフライン時はHTMLの印刷機能を代替経路とする。

参考:

- MDN, `Cache.addAll()`: https://developer.mozilla.org/en-US/docs/Web/API/Cache/addAll
- WebKit, Workers at Your Service: https://webkit.org/blog/8090/workers-at-your-service/

過去の教訓「Service Workerのキャッシュにより更新前の画面を見続ける」を反映し、`CACHE_VERSION` を更新する。ローカル検証ではService Worker登録解除とCache Storage削除を行ってから確認する。

### 8-3. PWA、OS、権限

- 新しいカメラ、マイク、通知、ファイル書込などの権限は使わない
- 利用者が押した通常の同一オリジンリンクだけを使う
- 説明書を新しいタブまたはウィンドウで開き、ホーム画面PWA側の作業状態を残す
- Android WebView固有APIには依存しない
- iOS/iPadOSではホーム画面追加したサイトがWebアプリとして開く構成を維持する

参考:

- WebKit, Web Push for Web Apps on iOS and iPadOS: https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/

### 8-4. 保存内容の説明

説明書は現行コードと整合させ、次を明記する。

- データは端末・ブラウザごとのlocalStorageに保存される
- PCとスマートフォンの間で自動同期されない
- サイトデータを削除すると消える
- 品目マスタJSONに含まれるのは品名とSNPの一覧であり、伝票、配置結果、配置マス、表示設定は含まれない
- 入力や列構成を変えると、条件に合わない保存済み配置は表示されない

## 9. エラーと代替経路

- 画像が読めない場合: `alt` とキャプションだけでも操作対象が分かる文面にする
- PDFが開けない場合: `manual.html` の「印刷する」から印刷またはPDF保存できるようにする
- オフラインでPDFを開けない場合: 事前キャッシュ済みHTML説明書を案内する
- 古い説明書が表示される場合: 更新バーの「更新する」と再読込を案内する
- データが見つからない場合: 端末・ブラウザ・サイトデータの違いを確認する逆引きを置く
- 印刷時に色が消える場合: 色なしでも読める設計とし、必要に応じてブラウザの背景グラフィック設定を案内する

## 11. 更新ルール

画面名、ボタン、入力項目、配置編集操作、警告、保存範囲を変更した場合は、説明書への影響を確認する。
説明書の本文または図を変更した場合は、HTML、画像、PDF、`sw.js` のキャッシュ版を一組として更新する。

一時的なビジュアル検討ファイル `.superpowers/brainstorm/` は成果物にもコミットにも含めない。

## 12. 完了条件

- 利用者がクイックスタートだけで入力から印刷まで完了できる
- よく使う編集操作と注意点を、画面名または困りごとから探せる
- 管理者が品目マスタ、配置マス、表示、保存、公開、更新の要点を確認できる
- HTML、PDF、実画面画像、模式図の内容が一致している
- PC、スマートフォン、A4印刷、オフラインで説明書を利用できる
- 既存アプリの配置計算と印刷動線に回帰がない

## 13. 残存リスク

- ホーム画面PWAから `target="_blank"` のリンクを開いたとき、新しいタブ、別ウィンドウ、通常ブラウザのどれに開くかはOSとブラウザにより異なる。ただし、元のアプリ画面を残すことを優先し、JavaScriptのポップアップではなく利用者が直接押す `<a>` を使う
- 実機プリンタでの確認を完了条件に含めないため、プリンタ固有の余白、濃度、背景印刷設定による差は未検証のまま残る。説明書は色が出なくても理解できる構成にし、管理者向け章に印刷設定の確認を記載する
- HTMLとコミット済みPDFは別ファイルなので、更新時の再生成を忘れると内容がずれる。更新手順、テスト、レビューで同時更新を強制する
