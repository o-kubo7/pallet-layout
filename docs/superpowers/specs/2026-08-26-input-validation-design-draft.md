## きっかけ

実機（Android 17 / Gboard）での確認中にユーザーから出た要望。

> 個数などが未入力の荷物がある状態で、「自動配置を作成」をタップすると、アラートは出ますが、
> 配置編集タブに飛びます。情報の入力が不完全な項目があれば、web の情報入力でよくあるような
> 赤枠などで目立たせる、そして次のタブに飛ばないようにしてください。

## 現状の挙動（コードで確認済み）

`files/index.html` の `readLots()`（713行目付近）:

- `v.qty<=0` の行は**黙って無視**される（`unknown` にも入らない）
- `v.snp<=0` の行は `unknown` に入り、`#messages` に警告が出る

`run(goMap)`（1366行目付近）:

- `lots.length===0 && unknown.length===0` → `alert("荷物を1件以上入力してください。")` して return（タブに飛ばない）
- `lots.length===0`（`unknown` はある）→ 警告を出して `switchTab('edit')` ← **タブに飛ぶ**
- それ以外（有効な荷物が1件でもある）→ 配置を作り、警告を出して `switchTab('edit')` ← **タブに飛ぶ**

つまり「一部の行だけ正しく、他が未入力」の場合、警告は出るが配置は作られタブへ遷移する。
これがユーザーの言う「アラートは出ますが、配置編集タブに飛びます」。

## ユーザーに確認済みの決定事項

brainstorming で3問確認し、以下が決まっている。

1. **必須項目は品名・個数・SNP。ロットは任意。**
   （ロット番号がまだ分からない荷物も配置したい場面がありうるため）
2. **赤枠はその欄に入力した時点で即消す。**
   （Web の入力フォームで一番よくある振る舞い）
3. **エラー時は「最初の欄へスクロール＋フォーカス＋画面内メッセージ」。**
   `alert()` は出さない。画面外の行が不完全だと赤枠が見えないため、そこまで連れていく。

## 設計（提示済み・未承認）

### 判定 `validateLots()`

`#lotTable tbody tr` を走査し、各行を3通りに分ける。

- **完全な空行** — 品名・ロット・個数・SNP がすべて空/0 → **スキップ**
  （末尾に常に空行がある UI なので、これを弾くと常にエラーになる）
- **不完全な行** — 何か入っているが、品名・個数・SNP のいずれかが欠けている → **エラー**
- **完全な行** — 通す

返り値は `[{row: 行番号, fields: ["name","qty"]}, …]` の形を想定。

### 赤枠 `.err`

```css
.err{border-color:#dc2626 !important;background:#fef2f2}
```

テーブルの `<input>` とカードの `<input>/<select>` の両方に付ける。

**注意:** カードは `syncCards()` で毎回作り直されるため、DOM にクラスを付けるだけでは消える。
エラー状態を変数（行番号 → 欠けている項目）で保持し、`syncCards()` の末尾で再適用すること。
（同じ罠は Task 4 のオートコンプリートでも踏んでいる。`#acList` を `<body>` 直下に置いた理由と同根）

### 解除

`rowChanged()` と `cardEdit()` の中でその行を再判定し、埋まった欄の `.err` を外す。

### エラー時の動作

`runFromButton()` の先頭、Task 3 の未登録品目チェックより**前**に置く。

```
不完全な行あり
  → 赤枠を付ける
  → 「荷物の入力」カードの見出し直下に赤い帯で「入力が足りない項目が N 件あります」
  → 最初の欄までスクロールしてフォーカス
  → return（タブに飛ばない・未登録品目の登録もしない）
```

### メッセージの置き場所

既存の `#messages` は `#tab-edit` の中にあるので入力タブでは使えない。
「荷物の入力」カードの `<h2>` 直下に新しい要素を置く。

### 触らないもの

- `readLots()` の `unknown`（SNP が 0 の行）と `inputWarnHtml()` の警告表示はそのまま残す。
  新バリデーションで実質届かなくなるが、`redraw()` 経由など他の呼び出し元があるため
- `alert("荷物を1件以上入力してください。")` もそのまま（完全に空の表で押した場合の経路）
- `loadSample()` が呼ぶ `run(true)` は通さない（サンプルは常に完全なため）

### 触るファイル

`files/index.html` のみ。
