# 配置編集：退避スペースとなぞり選択 — 設計書

- 作成: 2026-09-03
- 対象ファイル: `files/index.html`（単一ファイルの PWA）／ `files/sw.js`（CACHE_VERSION）
- 状態: 実装済み。§8 の検証まで通っている

---

## 1. 背景と目的

配置編集タブには「ロットを移動」があり、同じロットのマスをタップで選び、
選んだマスをドラッグして別の列へ運べる（`files/index.html` の
「ロットの手動移動」節）。荷物が多い日にこれを使うと、次の2つで詰まる。

**① 置き場所が無いと動かせない。**
倉庫が埋まっている日は、A を動かすために先に B をどかす必要がある。
どかす先が倉庫の中にしか無いので、玉突きになって編集が進まない。

**② 1マスずつしか選べない。**
25P のロットの一部だけを動かしたいとき、タップを何度も繰り返すことになる。
スマホでは 22px のマスを正確に叩き続ける必要があり、現実的でない。

この2つを外す。**倉庫に実在しない置き場（退避スペース）** を画面の中だけに作り、
**指でなぞってまとめて選べる**ようにする。

## 2. 退避スペース

### 2-1. 何であるか

`DEFAULT_SPACES` に足す1エリアで、実体は他のエリアと同じ「列の集まり」である。
違うのは次の3点。

```js
{name:"退避", zone:"stash", orient:"v", block:99, align:"top", sheet:"none",
 cols:[{h:4},{h:4},{h:4}]}
```

- `zone:"stash"` … 倉庫内（near）でも倉庫外（far）でもない第3のゾーン
- `sheet:"none"` … 配置図の表に欄を作らない（`sheetAreas()` はこの値を拾わない）
- 自動配置の候補から外す（`areaCandidates()` で `zone!=="stash"` を除く）

`moveCells()` / `validateMove()` はエリア名と列番号だけで動くので、
**移動処理は1行も変えずに退避への出し入れが成立する。**

### 2-2. 位置に意味が無い

退避スペースは倉庫に実在しないので、**その中のどのマスに置くかは何の情報も持たない。**
意味があるのは「どのロットが何枚逃げているか」だけである。この性質から次が決まる。

- 描く前に `repackStash()` で**詰め直す**。落とすたびに列が伸びると隅の小さな枠で
  形が崩れるが、詰め直しても失われる情報が無い
- 1列は4マス（`STASH_COL_H`）。隅の枠に収まる高さにそろえる
- 末尾に必ず空き列を1本残す（`ensureStashRoom()`）。0本だと
  `validateMove()` の空き判定に引っかかって運び込めなくなる

### 2-3. 自動配置し直しても残す

`run()` は `place()` で `lastSp` を作り直すので、素直に作ると
「▶ 自動配置を作成」で退避の中身が倉庫へ戻ってしまう。それでは
**荷物が多い日に逃がす**という目的が果たせない。

`place()` の前に退避分を控え、ロットのパレット数から引いてから配置し、
あとで積み戻す（`stashCounts()` → `putToStash()`）。
ロットIDは入力行の順番で変わるため、引き当ては `readLots()` と同じ
**品名＋ロット**のキー（区切りは U+0000）で行う。

### 2-4. 紙に出ないことを知らせる

`sheet:"none"` なので配置図の表には出ない。出ないまま印刷すると現物と紙がずれるので、
退避に残っている限り `renderResult()` で警告を出す
（既存の「over のエリアに荷物が残っています」と同じ趣旨）。

### 2-5. 設定テキストから外す

`applyConfig()` は区分を `near` / `far` しか受け付けない。退避スペースを
設定テキストに出すと「設定を反映」が通らなくなるため、`spacesToText()` から除く。

**除くだけでは足りない。** 一覧を組み直すと退避スペースごと消えるので、
`withStash()` で必ず足し直す。足し直すのは次の2か所。

- `applyConfig()` の `SPACES=withStash(out)`
- 起動時の復元 `SPACES=withStash(normalizeSpaces(d.spaces))`

`DEFAULT_SPACES` が変わったので `SPACES_SAVE_VERSION` を 2 → 3 に上げる。
既存端末の保存済みスペース設定と手動調整は初期値に戻り、設定タブにその旨が出る
（既存の仕組みのまま）。

## 3. マスの選び方

覚えることを1つにするため、**PC でもスマホでも判定は同じ**にする。

| 始めた場所 | 動き | 結果 |
|---|---|---|
| 未選択のマス | タップ | そのマスを選ぶ |
| 選択済みのマス | タップ | そのマスを外す |
| 未選択のマス | なぞる | 同じロットのマスを続けて選ぶ |
| 選択済みのマス | 選択の中をなぞる | 続けて外す |
| 選択済みのマス | 選択の外へ出す | 運ぶ（従来のドラッグ） |

### 3-1. 「外す」と「運ぶ」の区別

どちらも選択済みのマスに指を置いて動かすので、始点では区別できない。
**そのあと指がどこへ行ったか**で決める。

- 次に触れたのが**別の選択済みマス** → 外す
- 次に触れたのが**選択されていないマス**、または**マスの上に無いまま1マス分以上離れた**、
  または盤の外へ出た → 運ぶ

1マス分の余裕を見るのは、列と列の隙間（数px）を通っただけで運ぶ側に倒れると
外す操作が壊れるため。逆に余裕を見ないと、マスの無い余白へ指を出したときに
何も起きないまま止まる（実機で指摘を受けた不具合）。

外し始めたあとで外へ出た場合は、**外した分を戻してから**運びに切り替える。
隅にある退避スペースへ指を引くと、途中で自分の選択の上を通るため必ず起きる経路である。

このとき、いま自分で外したマスを「選択の外」と見なしてはいけない。
見なすと1マス外した次の瞬間に運びへ倒れる（`sweep.erased` で除外する）。

### 3-2. 指だけ2択が要る理由

`touch-action` は**指がマスに触れた瞬間に評価される**。なぞり始めてから
`touch-action:none` を付けても間に合わず、ブラウザが先にパンを始めて
`pointercancel` で中断する（この知見は既存コードのコメントに既にある）。

そのため指のときだけ「👆 画面を動かす／🖐 なぞる」の2択を出す。
マウスにこの制約は無いので、**マウスだけの端末には2択を出さない**
（`matchMedia("(any-pointer: coarse)")` で判定）。

`.cell.sel` には既存コードが `touch-action:none` を付けているので、
**選択済みのマスを運ぶ操作は 👆 のままでもできる。**
「選ぶ→運ぶ」の基本線はボタンを一度も触らずに完結する。

なお `touch-action:none` はパレットのマスにだけ付く。列の隙間・列の下の数字・
エリアの余白・盤の外は普通にスクロールする（実機で確認）。

### 3-3. 隠しキーを作らない

一時期 Option/Alt で外す側に反転する仕組みを入れたが、**押さないと分からない機能は
無いのと同じ**という指摘を受けて廃止した。画面上のボタンと指の動きだけで完結させる。

## 4. 運んでいることを見せる

元のマスから離れた時点で、次の4つを同時に出す。指の下は指で隠れるので、
**盤の側でも分かる**ようにするのが要点。

1. 指の下の吹き出し（`.dragghost`。ロット名と枚数）
2. 選んだマスを薄くする（`#mapBody.moving .cell.sel{opacity:.4}`）
3. 盤の上端に貼りつく帯の文言を「運んでいます」に変える
4. 退避スペースの枠を強調する（落とせる先であることを示す）

切り替わった瞬間に出す。次の `pointermove` を待つと、指を止めているあいだ
何も起きていないように見える。

## 5. 画面

### 5-1. 退避スペースの位置

既定は**右上**。左上と下（画面下の帯）も選べる。右利き・左利きで指の移動が変わるため。

`#mapBody` の中に置き、`position:sticky` ＋ `float` で貼りつける。
`position:fixed` にすると、上のタブ列（`.tabs` は `position:sticky`）を覆って
タブが押せなくなる。貼りつく位置はタブ列の高さを実測して `--docktop` に入れる。

大きさは、スマホが**画面幅の1/3の正方形**（実測 129×129）、PC が **240×210px**。
PC の値は「1マス18pxで4段×5列＝20パレットが一目で入る」ことと、
「盤が横に広いので隅の240px程度なら実際の置き場にかぶらない」ことから決めた。
足りないときは ⤢ で一時的に広げる。

### 5-2. 中身の見せ方

**マスで見せる。** 退避も「置き場」なので、盤と同じ見た目・同じ操作で扱えるほうが
覚えることが少ない。中のマスは盤と同じキー（`エリア名|列|行`）なので、
タップやなぞりの処理は共通のまま効く。

掴んでいるあいだも**中身をそのまま見せ、枠だけで知らせる**。
素の状態から「ここへドラッグ」と書いてあるので、文字を出し直す必要はない。

### 5-3. 案内の表示を切れるようにする

盤の上の帯（「3マス選択中」など）は慣れると邪魔になるので、表示・非表示を選べる。
**ただし「↩ いまのなぞりを取り消す」だけは非表示でも出す。**
取り消す手段が消えると、なぞりすぎたときに戻せなくなる。

設定は端末に保存する（`palletApp.navShow` / `palletApp.stashPos`）。

## 6. 触っていないもの

- 配置アルゴリズム（`place` / `placeLot` / `fillMix` / `areaCandidates` の中身）
- 配置図の表（`sheetPlacement` / `renderSheet` / まとめ / 引き出し線）
- 入力・品目マスタ・バリデーション
- `validateMove` / `moveCells` / `normalizeFills` の中身
- 印刷 CSS（退避スペースは `#mapBody` の中なので、既存の `.tabpanel` 非表示で一緒に消える）

## 7. エッジケース

- **退避に入りきらない**: `STASH_MAX_COLS`(14) と `STASH_COL_MAX_H`(21) で頭打ち。
  超える分は落ちない（`validateMove` が弾く）
- **入力からロットが消えた**: 次の `run()` で引き当てに失敗し、その分の退避は消える
- **通路を編集**: 既存どおり自動配置し直しになる。退避は §2-3 の仕組みで残る
- **ブロック分割の警告**: 退避は「何か所に分かれたか」の勘定から外す（`blockCountOf`）。
  外さないと一部を退避するたびに「2か所に分かれます」と聞かれる

## 8. 検証

`file:///.../files/index.html` を直接開いて、ヘッドレスブラウザ（Playwright）で実行。
`file://` では Service Worker が登録されないので、キャッシュの回り道は起きない。

| 観点 | 内容 |
|---|---|
| 選ぶ・外す・運ぶ | §3 の表の5行すべて。取り消しボタンの出方も |
| 運び始めの表示 | 隙間の範囲では出さず、1マス分離れたら4つとも出る。余白の上でも出たまま |
| 退避スペース | 受け皿として反応する／自動配置し直しでも残る／中のマスをタップして戻せる |
| 位置と案内 | 右上・左上・下の切り替え。案内オフでも取り消しは出る |
| 文言 | 見出しが枠内に収まる（113/129px）。掴んでも中身が出たまま |
| 既存機能 | 配置表が描ける／紙に「退避」が出ない／スペース設定に出ない・消えない／リロードで復元 |

すべて JS エラーなしで通っている。

**実機（iPhone）で確認済み**: なぞりの効き、スクロールが従来どおりできること、
運び始めの表示。
