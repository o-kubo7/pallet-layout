# 入力と配置図まわりの5改善

作成日: 2026-08-25
対象: `files/index.html`, `files/sw.js`

## 背景

現場での利用を通じて、5つの改善要望が出た。

1. 「配置図」タブの中でブロック図と表を切り替えているが、用途が別なので独立したタブにしたい
2. 荷物の入力で、Enter を押しても次の項目へ進まない（個数欄だけが例外）
3. 入力した品目が未登録のままで、次回また SNP を打ち直すことになる
4. 品名の候補が「プルダウン」として出ない
5. ブロック図の配色が色覚多様性に配慮できているか分からない

いずれも配置アルゴリズムには手を入れない。入力操作と表示の改善に閉じる。

## 現状の実装

### タブ

`switchTab()`（index.html:1160）が `input` / `map` / `settings` の3タブを出し分ける。
`map` タブの中はさらに `sheetMode`（index.html:530）で2つの表示を切り替える。

- `sheetMode = true` … 配置図の表（`#sheetView`）
- `sheetMode = false` … ブロック図（`#mapBody`）

切替は `setView()`（index.html:1605）で、`STORE_KEY.view` に保存される。
`showMapState()`（index.html:1173）が結果の有無と `sheetMode` から4つの領域の表示を決める。

「ロットを移動」「通路を編集」はブロック図だけで動く。
`toggleMove()`（index.html:1346）はブロック図でなければ `setView('block')` を呼んで切り替える。

印刷CSS（index.html:256）は `#mapBody` を含む多くの要素を隠し、表だけを出す。
つまり印刷は実質的に表専用の機能である。

### 入力

入力は同じデータを2つのUIで見せている。

- PCテーブル `#lotTable`（index.html:613 `addRow()`）… データの実体
- スマホカード `#lotCards`（index.html:722 `syncCards()`）… テーブルから毎回組み直す

カード側の編集は `cardEdit()`（index.html:838）がテーブルの `<input>` へ書き戻す。
`rowValues()` は `tr.querySelectorAll("select,input")` の並び順に依存しており、
`c[0]`=種別 `c[1]`=品名 `c[2]`=ロット `c[3]`=SNP `c[4]`=個数 と固定されている。

Enter を拾っているのは個数欄だけで、`addNextRow()`（index.html:823）を呼ぶ。
他の4欄に `keydown` ハンドラは無い。

### 品名の候補

`<datalist id="nameOptions">`（index.html:325）に品名を入れ、
テーブル（index.html:622）とカード（index.html:755）の品名欄が `list="nameOptions"` で参照する。
中身は `refreshNameOptions()`（index.html:592）が `MASTER` から作る。

### 品目マスタへの登録

自動登録は `snpEntered()`（index.html:800）の1経路だけ。
これは SNP欄の「＋」ボタンで追加入力モードに入り、値を確定したときにのみ走る。
通常の入力（品名を打ち、SNPを直接打つ）では登録されない。

### 配色

`PALETTE`（index.html:521）の18色を、ロットの並び順に `i % 18` で割り当てる（index.html:1028）。

マスの文字は `cellsOf()`（index.html:1085）が塊の**末尾1マスにだけ**ロットコードを入れ、
`drawZone()`（index.html:1143）が `codeShort()` でそれを描く。
凡例（index.html:1057）は色見本と「品名 / ロット nP」だけで、番号は無い。

## 改善1: タブ分割

### タブ構成

`入力 / 配置編集 / 配置表 / 設定` の4タブにする。

| 新タブ | id | 中身 |
|---|---|---|
| 入力 | `tab-input` | 現状のまま |
| 配置編集 | `tab-edit` | ブロック図（旧 `#mapBody`）、`#messages`、移動・通路編集、マスの大きさ |
| 配置表 | `tab-sheet` | 表（`#sheetView`）、表示倍率、矢印の先、角の丸み、印刷 |
| 設定 | `tab-settings` | 現状のまま |

`sheetMode` と `setView()` は廃止する。表示の分岐はタブが担う。

`STORE_KEY.view` も廃止する。
これは「配置図タブの中でどちらを見ていたか」を覚えるためのものだった。
起動時は常に入力タブから始まり、配置を作れば配置編集タブへ飛ぶので、
復元する場面が無くなる。`initView()`（index.html:2036）ごと削除する。
localStorage に旧値が残るが、読む側が消えるので無害。

### 空状態

`#mapEmpty` は現在1つしかなく、配置編集・配置表の両方で必要になる。
`#editEmpty` / `#sheetEmpty` の2つに分け、`hasResult` が false のときそれぞれに出す。

### 遷移

- 「▶ 自動配置を作成」→ `switchTab('edit')`
- `toggleMove()` の `setView('block')` 呼び出しは `switchTab('edit')` に置き換える
- `switchTab('sheet')` に来たときに `renderSheet()` を呼ぶ
  （表は表示されて初めて幅が測れるため、現状の `map` タブと同じ理由）

### 印刷

印刷CSS の隠し対象に `#tab-edit` を加える。
配置表タブ以外を開いた状態で印刷しても表が出るよう、`window.print()` の前に
配置表タブへ切り替える（ボタンは配置表タブにあるので実害は無いが、
ブラウザのメニューからの印刷に備える）。

## 改善2: Enter で次の項目へ

### 送る順序

```
品名 → ロット → SNP → 個数 → [行を追加] → 次の行の品名
```

種別はセグメントボタンなので飛ばす。

### 実装

品名・ロット・SNP の3欄に `keydown` を足す。個数欄は現状の `addNextRow()` を維持する。

```js
// 同じ行の次の欄へ送る。カードとテーブルのどちらから呼ばれても動くよう、
// フォーカスは「今表示されているUI側」の要素に当てる。
function enterNext(el, nextField){ ... }
```

カード側は `.lotcard[data-i] .fld[data-f="..."] input` を、
テーブル側は同じ `tr` の次の `input` を対象にする。
既存の `focusField(i, f)`（index.html:791）がカード側の移動を既に持っているので、これを使う。

SNP欄が `<select>`（同名で複数SNP登録時、index.html:741）のときも Enter で個数へ送る。

### ソフトキーボード

品名・ロット・SNP に `enterkeyhint="next"`、個数に `enterkeyhint="done"` を付ける。
これは Enter キーの見た目のラベルを変えるだけで、遷移そのものは `keydown` で行う。

## 改善3: 未登録品目の自動記録

### タイミング

「▶ 自動配置を作成」を押した時点で一括登録する。
入力途中の打ちかけがマスタに残らないようにするため。

### 条件

各行について、次をすべて満たすとき登録の候補にする。

- 品名が空でない
- SNP > 0
- `snpsOf(品名)` にその SNP が含まれていない

同名・別SNPは既存仕様どおり別行として追加する（`addMasterRow()` + `onMasterChange()`）。

### 確認ダイアログ

登録は取り消しが効かない。打ち間違い（`部品A` → `部品AA`、SNP `10` → `35`）も
そのまま恒久的にマスタへ入り、以後その品名の SNP 欄が `<select>` に化けて入力UIが変わる。
除去手段は設定タブでの手動削除だけ。

そこで**登録の前に品名と SNP を並べた確認ダイアログを出す**。

```
次の品目が未登録です。「設定」タブに登録しますか？

　・新部品ZZ　SNP 24
　・新部品YY　SNP 15

（キャンセルしても配置図は作成します）
```

断っても配置は作る。登録と配置は別の関心事なので、片方を断ってもう片方が止まるのは避ける。

### 実装位置

`runFromButton()`（index.html:1433）の中、`run(true)` の前に置く。

```js
function runFromButton(){
  if(hasManual() && !confirm(...)) return;
  const n = registerUnknownItems();   // 追加
  run(true);
  if(n > 0) /* messages に「品目をn件登録しました」を追記 */;
}
```

`run()` の中ではなく `runFromButton()` に置く理由は、
起動時の復元（index.html:2011 の `run(false)`）やサンプル読込（index.html:718）でも
`run()` が呼ばれるため。復元のたびに登録処理が走るのは避ける。

### 通知

`#messages` に「✅ 「設定」タブに登録しました：新部品ZZ(24) / 新部品YY(15)」を1行追加する。
`renderResult()` が `#messages` を上書きするので、`run()` の後に追記する。

この行はロットを1つ動かすと `redraw()` → `renderResult()` で消えるが、
登録そのものは設定タブに残るので実害はない。

既存の `snpEntered()` はそのまま残す（SNP欄「＋」からの即時登録は挙動を変えない）。

## 改善4: 品名オートコンプリート

### 方式

`<datalist>` を廃止し、自前のドロップダウンに置き換える。

Android 11 以降は IME が候補をキーボード上のストリップにインライン表示するため、
`<datalist>` ではドロップダウンにならない。標準要素側で制御する手段は無い。

### 挙動

| 項目 | 仕様 |
|---|---|
| 開く | 品名欄にフォーカスしたとき、および入力したとき |
| 絞り込み | 部分一致（`1111` で `1111-2222` が引ける）。未入力時は全件 |
| 表示 | `品名` と、その品名に登録された SNP を併記（`部品A  SNP 10 / 25`） |
| 確定 | タップ、または ↑↓ で選び Enter |
| 確定後 | 既存の SNP 自動補完（`nameChanged()` 相当）を通し、ロット欄へフォーカスを送る |
| 新規品名 | リストに無い文字列もそのまま確定できる（Enter で改善2の遷移に乗る） |
| 閉じる | Esc、外側のタップ、確定時 |

### DOM

候補リストを入力欄の親に入れる形（`position:relative` の親＋絶対配置の子）は採らない。
カードは `syncCards()` で毎回作り直されるため、入力中にリストごと消えてしまう。

**リストは `<body>` 直下に1つだけ置き、`position:fixed` で対象欄の位置に合わせる。**
同時に開くのは1つだけなので、これで足りる。

```html
<!-- body 直下に1つだけ。開くとき対象欄の座標に合わせて配置する -->
<div id="acList" class="ac-list" hidden>
  <div class="ac-item" data-name="部品A">部品A<span>SNP 10 / 25</span></div>
</div>
```

対象の入力欄は `acOpen(inputEl)` の引数で保持する。
`syncCards()` がカードを作り直したときは、開いていたリストを閉じる。

### キーボードで隠れる場合

`visualViewport.height` で可視領域の下端を求め、
リストの高さが入らない場合は入力欄の**上側**に出す。
`visualViewport` が無い環境（古いブラウザ）では常に下側に出す。

### タップ時の blur

候補をタップすると `blur` が先に走ってリストが閉じ、タップが不発になる。
候補側で `pointerdown` を `preventDefault()` して入力欄のフォーカスを保つ。

### 影響

`refreshNameOptions()` は datalist ではなく、候補の元データ（配列）を作る関数に変える。
`<datalist id="nameOptions">` と2か所の `list="nameOptions"` を削除する。

## 改善5: 配色と番号

### 診断結果

現行18色を1型（P型）・2型（D型）・3型（T型）でシミュレーションし、
全153ペアの色差 CIEDE2000（ΔE00）を計算した。

| 視点 | ΔE00 < 10 のペア数 | 最小 ΔE00 | 最小のペア |
|---|---|---|---|
| 一般色覚 | 10 | 3.7 | `#fca5a5` / `#fda4af` |
| 1型（P型） | 35 | 0.4 | `#c4b5fd` / `#f0abfc` |
| 2型（D型） | 41 | 0.3 | `#7dd3fc` / `#d8b4fe` |
| 3型（T型） | 33 | 0.5 | `#fca5a5` / `#fda4af` |

明度は L\* 74.6〜90.3（幅15.6）しかなく、色が潰れたときに明度で補う余地が無い。
一般色覚でも既に判別困難なペアが10組ある。

### 色覚対応を採らない判断

カラーユニバーサル対応で確実に判別できる質的色数は 8〜9 が上限である
（CUD推奨配色セットの広面積用ベースカラーは7色、Okabe-Ito 標準セットは8色）。
実際に探索したところ、黒文字コントラスト 4.5:1 を保った上で
全視点の最小 ΔE00 は 8色で 16.3、10色で 14.2、12色で 12.2 まで落ちる。
18色を色だけで判別可能にすることはできない。

そこで**識別の役割を番号に移し、色は「同じロットのまとまり」を示す補助**と位置づける。
色覚対応は見送り、代わりに一般色覚での色差を改善する。

### 新パレット

「薄い（L\* 78〜93）」「カラフル（HSL彩度 0.55以上）」を制約に、
一般色覚での最小 ΔE00 を最大化して18色を探索した。結果 **ΔE00 = 14.5**（現行は 3.7）。

色相順に並べたものを前半・後半で交互に差し込み、
隣り合うロットの色が近づかないようにしてある。

```js
const PALETTE=["#ffadb1","#71d69e","#ffdbcc","#47ffed","#ffaf7a","#c8efef",
               "#ffbb3d","#3de2ff","#e3cfa0","#8fc7ff","#ffed47","#d7e0f4",
               "#aed369","#cdb8ff","#dbefc8","#f4d7ee","#3dff64","#ffa3e8"];
```

19ロット以上では色が一周するが、番号は連番のまま続くので識別できる。

### 番号表示

**マスにはロット番号（素の数字）を表示する。**

- ロットコードは `1111-2222` のように長いことがあり、30pxのマスに収まらない
- 丸数字（①②③）は ㉕ が上限で、2桁は丸の中が詰まり、端末フォントにも依存する

現状はロットの塊の**末尾1マスにだけ**ロットコードを描いているが、
番号に変えるのに合わせて**すべての塗られたマスに番号を出す**。

```js
// cellsOf(): 末尾だけでなく全マスに id を持たせる
// drawZone(): const label = filled ? String(a.id + 1) : "";
```

番号は `lot.id + 1`。`id` は `readLots()` が付ける0始まりの連番（index.html:698）なので、
凡例の並び順とマスの番号が一致する。

`codeShort()`（index.html:1157）はマスのラベル描画専用なので、参照が無くなる。削除する。
混載の区切り（`seg` フラグによる破線、index.html:1140）は残す。
全マスに番号が出るため、破線と番号の両方で品目の切れ目が分かる。

CSS は `.cell` の `font-size:calc(var(--cell) * .3)` を `.46` に上げ、`font-weight:800` にする。

### 凡例

各項目の先頭に番号を付ける。

```
1 ■ 部品C / 1111-2222　25P
2 ■ 部品A / 1111-2301　12P
```

## 技術制約（調査済み）

- **datalist**: Android 11 以降、IME が autofill 候補をサジェストストリップにインライン表示する。
  Chrome on Android の datalist もこの経路に乗るため、ドロップダウン表示にはならない。
  ブラウザ側の制御手段が無く、自前実装以外に選択肢が無い。
- **enterkeyhint**: Chrome 77+ / iOS Safari 13.4+ で対応。
  Enter キーのラベルを変えるだけで、フォーカス移動は自前の `keydown` 処理が必要。
- **iOS のテンキーには Enter キーが無い**: ロット欄は `inputmode="tel"`、
  SNP と個数は `type="number"`。iOS Safari のこれらのキーボードには実行キーが存在せず、
  `enterkeyhint` も出しようがない。**Enter 連鎖は Android を対象とする**。
  iPhone では欄をタップして移る従来の操作になる（既存の機能が減るわけではない）。
  Android の Gboard は数字レイアウトにも実行キーがあるので成立する。
  ロット欄に「−（ハイフン）」ボタンがあるのは、同じテンキー制約への既存の回避策である。
- **日本語入力の変換確定**: IME の変換中に押される Enter も `keydown` に届く。
  ガードしないと、変換候補を確定した瞬間に次の欄へ飛ぶ。
  Enter と ↑↓ を扱うハンドラの先頭で `ev.isComposing || ev.keyCode===229` を弾く。
- **visualViewport**: iOS Safari 13+ / Android Chrome で利用可。
  ソフトキーボード表示時の可視領域を取得できる。未対応環境向けのフォールバックを用意する。
- **blur とタップの順序**: 候補のタップは `blur` → `click` の順に発火するため、
  `blur` でリストを閉じるとタップが届かない。`pointerdown` の `preventDefault()` で回避する。
- **PWA キャッシュ**: `sw.js` の fetch ハンドラは HTML を**ネットワーク優先**、
  それ以外のアセットをキャッシュ優先にしている。`index.html` 自体はオンラインなら即届く。
  それでも `CACHE_VERSION` を **v16 → v17** に上げる理由は3つ。
  `sw.js` が変わることで新しい Service Worker が install され「新しいバージョンがあります」
  のバーが出ること、`activate` で旧キャッシュが破棄されること、
  HTML 以外（`manifest.json`・アイコン）はキャッシュ優先なので上げないと古いものが残ること。
- **secure context**: `http://<IP>` では Service Worker が登録されず standalone にもならない。
  ローカルの実機確認では PWA としての挙動（アドレスバーの無い画面高さ、
  オフライン起動）を見られない。GitHub Pages へ反映後に別途確認する。
- **色数の上限**: カラーユニバーサル対応の質的色数は 8〜9 が上限。18色では原理的に成立しない。

### ついでに直す既存の不具合

いずれも今回の変更で踏みやすくなるため、同じ変更に含める。

- **`setCellSize()` が他のボタンの選択を消す**（index.html:1181）

  倍率・矢印・角丸の選択も外れる。同一タブ内だった今までは気づけたが、
  タブを分けると「別タブの表示が壊れる」ことになり原因が見えない。
- **`addNextRow()` が PC でフォーカスを飛ばさない**（index.html:823）
  `.lotcard` にしかフォーカスを当てず、`.lotcards` は 601px 以上で `display:none`。
  PC では行だけが増えてカーソルが動かない。Enter 連鎖を入れると露見する。
- **`updateCardFoot()` が個数欄を壊す**（index.html:855）
  SNP 欄を `.fld input` の3番目で引いているが、SNP が `<select>` のカードでは
  3番目が個数欄になる。品名やロットを打つたびに個数が SNP の値で上書きされる。
  自動登録は `<select>` に化ける品名を増やす方向に働くので、踏む頻度が上がる。

## 検証

### 手で確かめること

1. 4タブが切り替わり、配置編集にブロック図、配置表に表が出る
2. 配置を作ると配置編集タブへ飛ぶ
3. 「ロットを移動」を押すと配置編集タブに切り替わり、ドラッグで移動できる
4. 印刷プレビューに表だけが出る
5. 品名→ロット→SNP→個数→次の行 と Enter で送れる（PC・スマホ実機の両方）
6. 未登録の品名＋SNPを入れて自動配置すると、設定タブに登録され、件数が通知される
7. 品名欄をタップすると候補がドロップダウンで出る（Android実機）
8. 候補が絞り込まれ、タップで確定し、SNPが自動で入る
9. 入力欄が画面下部にあるとき、候補がキーボードに隠れない
10. マスに番号が出て、凡例の番号と一致する
11. 19ロット以上でも番号で区別できる

### 回帰確認

- 手動調整（ロット移動）の保存・復元が壊れていないこと
- サンプル読込の確認ダイアログが出ること
- 通路編集モードが動くこと
- 混載・通路はみ出しの警告表示が出ること
