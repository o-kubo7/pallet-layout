# 入りきらない日だけ配置表の欄を広げる 設計書

- 作成: 2026-09-01
- 対象: `files/index.html` の配置表（`renderSheet()` 周辺）
- 関連: メモ `docs/memos/2026-08-27-sheet-improvements-memo.md` §3（欄数と縦線）、§4（実装順序）

---

## 1. 背景

2026 年 8 月最終週、現場で荷物とロットの数が多い日に**配置表の欄が不足した**。
手書き用紙で運用していたため、左ブロックと上段ブロックの間の余白に書き込んで対応した。

同じ日にアプリで配置表を作っていた場合、載りきらないロットは表から消え、
欄数超過の警告（`files/index.html:1650` 付近）が出るだけで、対応手段が無かった。

ユーザーの言葉での要件は次の 3 点。

- **表に書ききれないロットがあることが最大の不都合**（最優先で解消する）
- **通常は元の欄数で足りる。欄が多いと視認性が悪い**（通常日は現状のままにする）
- **欄が増えても、ほぼ同じ見た目なので問題ない**（切り替わった日の見た目差は許容する）

## 2. 決定事項

配置表に 2 つのモードを持たせ、荷物の量から**自動で**選ぶ。現場の操作は増やさない。
表示設定に項目は追加しない。

- **通常モード** … 現状と完全に同一（上段 4 欄・下段 7 欄・欄幅 96px・メイン列 48px）
- **拡張モード** … 上段 5 欄・下段 8 欄・欄幅 84px・メイン列 42px

総幅 672px は両モードで不変。用紙の外形は変わらない。

### 検討して採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 常時 5・8 欄 | 通常日にも欄が増える。「欄が多いと視認性が悪い」に反する |
| 表示設定で手動 on/off | 現場の操作が増える。切り忘れると欄不足が再発する |
| 上段 6 欄（メモ §3-3 の採用案） | 左ブロックが 180px まで痩せ、総パレット数が 4 桁になると桁が溢れる。<br>また総幅を 720px に広げる必要があり、通常日の紙も変わる |
| 列の土台を固定し罫線だけ出し入れ | 通常日も欄幅 84px になり、視認性が現状より落ちる |

## 3. 切替条件

```
拡張モード ⇔ sheetSlots("top").length > 4 または sheetSlots("bottom").length > 7
```

- この判定に使う件数は、**ロットまとめを適用した後**の欄数（`sheetSlots()` の戻り値）。
  まとめが on のときはまとめた後の件数で判定する
- 判定式は既に存在する。`files/index.html:1652` の `overTop` / `overBottom` が
  同じ比較をしている。現在は警告を出すためだけに計算しているものを描画側でも使う
- **上段だけが溢れた日でも、上下段そろって拡張モードになる。**
  列の土台を 1 つのテーブルで共有しているため、上段と下段を別々のモードにはできない
- 拡張しても足りない日（上段 6 件以上・下段 9 件以上）は、**従来どおり警告を出す**。
  警告の文言・件数の数え方（`lotsIn` で members を合計する）は変更しない

## 4. 列の土台

### 通常モード = 14 列 × 48px（現状のまま）

```
左ブロック 5列(240px) | すき間 1列(48px) | 上段 4欄 × 2列(96px)  = 14 列
下段 7欄 × 2列(96px)                                            = 14 列
メイン 14列 × 48px(672px)                                       = 14 列
```

### 拡張モード = 16 列 × 42px

```
左ブロック 5列(210px) | すき間 1列(42px) | 上段 5欄 × 2列(84px)  = 16 列
下段 8欄 × 2列(84px)                                            = 16 列
メイン 14列 × 42px(588px) ＋ 右の余り 2列(84px)                  = 16 列
```

### なぜこの数値なのか

- **84 = 42 × 2** … 下段の欄境界がメインの列線に全部乗る。
  現状の 96 = 48 × 2 と同じ性質を保つ（実測 7/7 一致）
- **左ブロック＋すき間 = 252px = 84 × 3** … 上段の欄境界も下段に乗る（実測 4/4 一致）
- **左ブロックは両モードとも 5 列** … 曜日セルが 5 個並ぶため 5 列未満にはできない。
  拡張時の 1 列は 42px で、`.ring` に必要な 36px（文字 11px×2 ＋ padding 6px ＋
  border 4px ＋ td の padding/border 4px）を満たす

### 構造の同一性

両モードで **HTML の組み立てロジックは共通**。左ブロックは 5 列＋すき間 1 列、
上段・下段の欄は colspan 2、メインは 1 列ずつ。変わるのは次の 3 つの数値だけ。

- 列の総数: 14 / 16
- 上段の欄数（`SHEET_TOP_SLOTS` 相当）: 4 / 5
- 下段の欄数（`SHEET_BOTTOM_SLOTS` 相当）: 7 / 8

拡張モードでだけ、メインの各行の右端に 2 列ぶんの空セルを足す。
ここは後日あふれブロック（メモ §4「これから」2）が入る用地で、今回は空白のまま。

## 5. 実装対象

### 5-1. 定数を「モードから引く」形にする

現在 `files/index.html:658` の

```js
const SHEET_TOP_SLOTS = 4, SHEET_BOTTOM_SLOTS = 7;
```

は固定値。これを 2 モードぶん持ち、判定結果から引く形にする。
警告側（`files/index.html:1652`）と描画側（`renderSheet()`）が**同じ値を見る**ことを保つ。

### 5-2. `14` のハードコードを列数に差し替える

| 行 | 内容 | 拡張時の値 |
|---|---|---|
| `files/index.html:2837` | 上下段の区切り `<td class="none sep" colspan="14">` | 16 |
| `files/index.html:2845` | 下段とメインの間の gap `<td class="none" colspan="14">` | 16 |
| `files/index.html:2857` | `<colgroup>` `Array(14).fill('<col style="width:48px">')` | 16 列 × 42px |
| `files/index.html:3075` | グリッド案内 `<tr class="gnote"><td colspan="14">` | 16 |

`<colgroup>` は既に存在するので新設は不要。**`table-layout:fixed` は colspan だけでは
列幅を均等配分しないため、この `<colgroup>` が幅を決めている。**列数と幅の両方を
モードから引く。672 ÷ 16 = 42 で割り切れる。

### 5-3. 上段タイトルの colspan

`files/index.html:2814` の `<td class="ttl bb2" colspan="8">軒下</td>` は
上段の欄数 × 2。拡張時は 10。

### 5-4. メインの右の余り

`gridRows()`（`files/index.html:2943`）が組む各行は `SHEET_GRID_ORDER`
（`files/index.html:2918`）由来の 14 列。拡張時は各行の右端に
`<td class="none" colspan="2"></td>` を足して 16 列にそろえる。

### 5-5. 触らないもの

- **引き出し線** `drawLeaders()` … セルの実測座標から引くので自動追随。変更しない
- **水平圧縮** `fitSheetText()` … 欄が狭まるぶん圧縮率が上がるが、実測で切れる欄 0 件
- **ロットまとめ** `mergeEntries()` / `mergeLots` … 変更しない
- **表示設定** … 項目を増やさない
- **配置アルゴリズム** … 変更しない。欄数は表示側の上限にすぎない

## 6. モックでの実測値

`docs/memos/mock-sheet-split.html` にプリセット（現状 / 案A / 案B / §3-3 分割案）を追加済み。
本設計は「案B」。

| | 実寸 | A4 横の最大倍率 | 欄幅 | メイン列 | 縦線一致（上段/下段） | 切れている欄 |
|---|---|---|---|---|---|---|
| 通常モード | 675.0 × 485.5px | 1.510 | 96px | 48px | 3/3・6/6 | 0 件 |
| 拡張モード | 675.0 × 497.5px | 1.473 | 84px | 42px | 4/4・7/7 | 0 件 |

- 印刷は `PRINT_ZOOM = 1.4` 固定（`files/index.html:2734`）。**両モードとも収まる**（1.4 ≤ 1.473）
- 高さは 497.5 × 1.4 = 696.5px ≤ `PRINT_H_LIMIT` 718.5px（`files/index.html:2736`）で収まる
- 拡張時の最強圧縮 68%。`FIT_MIN_SCALE = 0.4` を大きく上回る
- 総パレット数は 200 を超えない（ユーザー確認済み）ため 3 桁。
  拡張時の総P欄は 126px・数字の割当 84px で、表示設定の上限 32px でも 68.4px に収まる

## 7. 技術制約

`~/claude-lessons/lessons.md` の既知の制約のうち、本設計に効くものを列挙する。

### 7-1. Service Worker が cache-first（2026-07-09 / 2026-08-31）

`files/sw.js` は cache-first。**開発中の再読込に `CACHE_VERSION` の繰り上げは効かない。**
ブラウザで検証する手順には、冒頭に次を定型として入れる。

```
SW を unregister → caches.delete() → キャッシュバスティング付き URL で開く
```

リリース時は別途 `CACHE_VERSION` を繰り上げる（前回は v25）。

### 7-2. 非表示タブでは `getBoundingClientRect()` が 0 を返す（2026-08-23 / 2026-08-30）

`fitSheetText()` / `drawLeaders()` / `applySheetZoom()` は実測に依存する。
配置図タブが `display:none` のうちは測れない。
**検証スクリプトには、幾何を測る前に `switchTab('map')` を必ず入れる。**

本設計の切替判定そのものは件数の比較で、DOM 測定に依存しない。

### 7-3. `@media print` の中の宣言は `getComputedStyle` で読めない（2026-08-30）

印刷まわりを確認する手順は CSSOM を走査する形に統一する。

```
document.styleSheets → CSSRule.MEDIA_RULE → conditionText.includes("print")
```

### 7-4. 「結果が無い状態」は `localStorage.clear()` では作れない（2026-08-31）

`initLots()` は保存データが無いと `SAMPLES.basic` を自動で読み込む。
空の状態が要るときは `clearLots()` を使う。

### 7-5. `border-collapse:collapse` の表では `border-radius` が効かない（2026-08-23）

本設計では角丸を扱わないため影響なし。記録のみ。

### 7-6. 背景色は既定で印刷されない（2026-08-23）

メインの通路列の灰色には `print-color-adjust:exact` が入っている。
拡張時に足す右の余り 2 列は**背景色を持たせない**（罫線も引かない空セル）ので影響なし。

## 8. 検証

テストランナーが無いプロジェクトのため、ブラウザのコンソールで測る。
**フィクスチャの弱さで検証が空振りする事例が 2026-08-25 / 08-30 / 08-31 と 3 回続いている**
ため、以下は「その状態に実際に到達すること」を先に確かめてから合格判定に使う。

### 8-1. 必要な 3 つの状態

| 状態 | 作り方 | 期待 |
|---|---|---|
| 通常モード | `SAMPLES.basic` | 14 列・上段 4 欄・下段 7 欄・欄幅 96px。**現状と 1px も変わらない** |
| 拡張モード | 上段が 5 件、または下段が 8 件になる入力 | 16 列・上段 5 欄・下段 8 欄・欄幅 84px |
| 拡張でも足りない | 上段 6 件以上、または下段 9 件以上 | 16 列のまま、従来どおり警告が出る |

拡張モードのフィクスチャは、過去に上段を埋めるのに使えた
「詰め物F qty700 でメインを埋め、部品A を複数件あふれさせる」形を起点にする
（`.superpowers/sdd/progress.md` の Task 5 の記録）。
**件数はロットまとめを適用した後の欄数で数えることに注意。**

### 8-2. 測る項目

- `<colgroup>` の `<col>` の本数と `width`
- 上段・下段の欄の実効幅（`getBoundingClientRect()`。`switchTab('map')` の後で測る）
- 縦線の一致本数（上段↔下段、下段↔メイン）
- `fitSheetText()` の結果（切れている欄が 0 件であること）
- 引き出し線の本数が下段のロット数と一致すること
- 印刷時の推定高さが `PRINT_H_LIMIT` を下回ること
- 通常モードの実寸が改修前と一致すること（**非退行の確認**）

### 8-3. 実機確認

Pixel 9a で、通常モードと拡張モードの両方を印刷プレビューまで確認する。
特に拡張モードで、メインの右に出る 84px の余白の見え方を目で見る。
