# 「半」の位置指定（配置編集）と下側初期位置 設計書

- 日付: 2026-09-24
- 対象: `files/index.html`、`files/sw.js`、`tests/sheet-placement.test.js`
- 前提コミット: `04d8fb7`（メイン2ロット両端詰め・軒下①右詰め）

## 1. 目的

配置図のメイングリッドに出る「半」（端数パレットの印）の位置を、次の2点で改善する。

1. 指定が無いときの初期位置を、図の下側にする（混載列では、そのロットのまとまりの中で下側）。
2. 配置編集で、ユーザーが「半」を付けるマスを指定できるようにする。設定で ON/OFF でき、初期値は OFF。

現状は「ロットを詰めた順の最後のマス」に「半」を付けている。准緊急マス（上に飛び出したマス）は通常マスの後に詰めるため最上段に、両端詰めの第2ロットは下から上へ詰めるためまとまりの上端に「半」が来て、現物の置き方と合わない。

## 2. 対象範囲

- 「半」の位置指定はメインエリアだけ。グリッドにマス単位の「半」が出るのはメインだけで、その他のエリアは表の「P 半」表記だけのため。
- 「半」の数はロットの `half`（端数のある伝票の数）で決まり、この機能では増減しない。

## 3. 「半」の位置の決め方

### 3-1. 手動指定の持ち方

メインの各列に `halfMarks` を追加する。

```js
col.halfMarks = { "<lotId>": [k, ...] }   // k = その列にあるそのロットのマスの「下から k 番目」（0 始まり）
```

- 並び順は指定した順（古い順）。3-4 の「一番古い手動指定」に使う。
- 下から数えるので、同じ列の他ロットが移動してマスの物理位置がずれても、そのロットのまとまりに対する位置は保たれる。
- 「下」は物理的な行番号が大きい側（`cellsOf()` の `row` が大きい側）。准緊急マスは最上段、緊急用マスは最下段になる。

### 3-2. 共通関数 `halfCells(sp, lots, manualOn)`

メインのスペースについて「半」を付けるマスの集合を返す純粋関数。配置編集の盤と配置図のグリッドが同じ関数を使うので、両者の位置は必ず一致する。

ロットごとに、次の順で決める（`n = lot.half`、`n <= 0` のロットは対象外）。

1. `manualOn` が true のとき、有効な手動指定を集める。
   - 有効とは、その列にそのロットのマスが `k + 1` 個以上あること。
   - 無効な指定は無視する（データからは消さない。描画のたびに判定する）。
   - `n` 個を超える場合は古い順に `n` 個だけ使う。
2. 手動指定の数が `n` に足りなければ、残りを自動で埋める。
   - 手動指定が1つも無いロット: `halfAreaOf(id)` がメインのときだけメインに置く（末尾エリアがメイン以外なら、そのエリアの表の「P 半」で表す）。
   - 手動指定が1つ以上あるロット: 残りもメインの中から選ぶ。
   - 自動の選び方: そのロットのメイン内の末尾の列（詰め順で最後にそのロットがある列）から始め、その列にあるそのロットのマスを下から上へ選ぶ。足りなければ前の列へ進み、同じく下から上へ選ぶ。手動指定済みのマスは飛ばす。

### 3-3. `halfAreaOf(id, manualOn)`

表の「P 半」を付けるエリアを返す。

- `manualOn` が true で、そのロットにメインの有効な手動指定がある → `"メイン"`
- それ以外 → 現在の `tailAreaOf(id)` と同じ

`sheetEntries()`（`files/index.html:5065` 付近）と退避スペースの欄（同 5204 付近）の `tailAreaOf()` 呼び出しをこの関数に置き換える。

### 3-4. 手動指定の無効化

- ロットを移動したとき（`applyMove()` と `applyMoveToStash()` で `lastSp = v.next` を入れる直前）、移動したロットの `halfMarks` を移動元と移動先の列から消す。
  - 理由: 枚数だけのデータでは、「半」の現物がどのマスと一緒に動いたかを判定できないため。
  - 設定の ON/OFF に関係なく消す。
- 他ロットの移動では消さない（3-1 のとおり相対位置は保たれる）。
- 範囲外になった指定は 3-2 のとおり描画時に無視する。
- 自動配置をやり直すと列データが作り直されるので、すべての指定が消える。現在の手動調整と同じ扱い（破棄の確認ダイアログに含まれる）。

## 4. 配置編集の操作

### 4-1. 操作バーのボタン

既存の操作バー（`#toolFlag`：元に戻す・やり直す・選択数）にボタンを1つ追加する。新しいモードは作らない。

表示条件（すべて満たすとき）:

- 設定「半を手動で設定する」が ON
- 選択が1マスだけで、そのマスがメインにある
- そのロットの `half >= 1`
- 配置が最新（`isActiveFresh()` が true）

ボタンの表示内容（アイコンは丸囲みの「半」）:

| 選択マスの状態 | ボタン | 押したとき |
|---|---|---|
| 「半」ではない | （丸囲み半）半を設定 | そのマスを手動指定に加える。「半」の総数を保つため既存の「半」を1つ外す。自動で置かれた「半」があればそれを優先して外し、なければ一番古い手動指定を外す |
| 手動指定の「半」 | （丸囲み半）半を自動に戻す | そのロットの手動指定をすべて消す |
| 自動で置かれた「半」 | （丸囲み半）半を設定（押せない） | ― |

- `half = 1` のときは「半がこのマスへ移る」動きになる。
- 押せないボタンも消さずに表示する（既存の元に戻すボタンと同じく、位置ずれによる押し間違いを防ぐ）。

### 4-2. 押したあと

- 移動と同じく履歴に1手として積み（`pushMoveStep()` 相当）、元に戻す・やり直すの対象にする。
- 手動調整として保存する（`saveManual()`）。
- 選択を解除し、盤と配置図を描き直す。
- 教訓（2026-09-21「最初の1回」）に従い、履歴に積んだ関数の末尾で `updateFlag()` まで呼ぶ。

### 4-3. 盤での表示（案B：角バッジ）

- メインのマスで「半」のものに、右上へ小さな角バッジ「半」を付ける。ロット番号は残す。
- バッジ: 14px 角、白地・黒文字 10px、左辺と下辺に 1px の黒線、左下だけ角丸。
- 手動指定と自動の区別は付けない（配置図と同じ見た目）。
- 設定が OFF でも、自動の位置でバッジを表示する（「半」の位置を確認する手段として残す）。
- 選択中の表示（`.cell.sel` の二重枠）や混載の境界の破線と重ならない位置であること。

### 4-4. 操作バーの2行表示

- 「半」のボタンを出すとき、帯が上限幅に収まらなければ帯を2行にし、2行目に「半」のボタンを置く。
- 1行目（元に戻す・やり直す・選択数）の並びと位置は変えない。
- 2行にするかどうかは画面幅（`@media`）で決めない。既存の `fitFlagCount()` と同じく、必要な幅を実測して帯の上限（`max-width`）と比べて決める。
- 選択数の省略（入らなければ隠す）は、1行目だけで判定する。

## 5. 配置図

### 5-1. グリッド（`gridRows()`）

- `isHalf` を作る部分（詰め順の末尾に付ける処理）を `halfCells()` の呼び出しに置き換える。
- 緊急用マスに「半」が来たときは、現状どおり列番号の欄に「半」を出す。
- 引き出し線（`sheetGridAnchors()`）は変更しない。

### 5-2. 表の「P 半」

3-3 の `halfAreaOf()` で付ける欄を決める。

### 5-3. テキスト編集の署名

`currentSheetSig()`（`files/index.html:5467`）は `snapshotSpaces(lastSp)` を署名に含む。`halfMarks` を含めたままだと、「半」を指定しただけで配置図の書き足しが「前の配置の編集」扱いになって非表示になる。

- 署名用の配置データからは `halfMarks` を除く。
- 設定の ON/OFF も署名に含めない。

## 6. 設定「半を手動で設定する」

- 場所: 設定タブ「配置のしかた」欄、「ロットが複数箇所に分かれるとき確認する」の下。
- 表示:
  - チェックボックス: 「配置編集で『半』の位置を手動で設定する」
  - 説明: 「ONにすると、配置編集で1マスを選んだときに『半を設定』が出ます。OFFの間は、設定済みの位置を残したまま自動の位置（下側）で表示します。」
- 保存: `STORE_KEY.halfManual`（`palletApp.halfManual`）。既存の `splitConfirm` と同じ読み書き。端末ごとの設定で、日ごとの配置データには含めない。
- 初期値: OFF（保存値が無いとき OFF）。
- OFF のとき:
  - 操作バーの「半」のボタンを出さない。
  - `halfCells()` と `halfAreaOf()` は `halfMarks` を無視する。
  - `halfMarks` のデータは消さない。ON に戻すと指定位置が復活する。
- 切り替えたとき: 盤と配置図をその場で描き直す。配置データは変わらないので、履歴には積まない。

## 7. 保存・互換性

- `halfMarks` は列データの一部なので、履歴（`snapshotSpaces()`）と手動調整の保存（`saveManual()`）にそのまま入る。新しい保存経路は作らない。
- 古い保存データには `halfMarks` が無い。無い場合は「手動指定なし」として扱う。データ移行はしない。
- `SPACES_SAVE_VERSION` は倉庫の形の設定の版であり、今回は変更しない。
- `files/sw.js` の `CACHE_VERSION` を `v75` から `v76` に上げる。

## 8. 技術制約

### 8-1. 使うブラウザ API

新しいブラウザ・OS の API は使わない。既存の DOM 描画、Pointer Events によるタップ選択、`localStorage`（既存の `saveData()`／`loadData()`）だけを使う。実機（Pixel 9a / Android Chrome）でこれらはすでに動作している。

### 8-2. 保存容量

`halfMarks` は「ロットID → 小さな整数の配列」で、1日あたり数十バイト程度。既存の手動調整の保存と履歴に比べて無視できる大きさで、`localStorage` の容量に影響しない。

### 8-3. 操作バーの幅（教訓 2026-09-21「flex の padding は縮まない」を反映）

- 412px 幅（Pixel 9a）での帯の上限は約 211px（過去の実測値）。
- 帯の中身: 左右の余白 24px ＋ 元に戻す・やり直す 98px ＋ 間隔 10px → 残りは約 79px。
- 必要な幅の見積もり: 「（丸囲み半）半を設定」約 104px、「（丸囲み半）半を自動に戻す」約 146px。
- → 1行に収まらないので、4-4 の2行表示にする。見積もりはボタンの外形（border box）の値。実装後に実測で確かめる。
- ボタンに `padding` を付けるので、縮めて収める設計にはしない（padding は flex で縮まない）。

### 8-4. Service Worker（教訓 2026-07-09、2026-09-16 を反映）

- `files/index.html` を変更するので `CACHE_VERSION` を上げる。
- ローカル検証では、Service Worker の登録解除と Cache Storage の削除をするか、新しいオリジン（別ポート）で開く。
- LAN の HTTP で開いた実機では Service Worker が登録されない。実機では UI 操作の確認だけをし、更新配信の確認は対象外とする。

### 8-5. テストに具体値を固定しない（教訓 2026-09-21「運用で変わる値」を反映）

`CACHE_VERSION` の値、色、寸法はテストに直書きしない。版は既存の「版付き形式」の不変条件テストで確かめる。

## 9. テスト

### 9-1. 自動テスト（`node:test`）

1. `halfCells()`
   - 手動指定なし: 単独ロットの列で最下段のマスに付く。
   - 手動指定なし: 両端詰めの混載列で、そのロットのまとまりの下端に付く（第1ロット・第2ロットとも）。
   - 准緊急マスありの列: 准緊急マスではなく、まとまりの下端に付く。
   - 緊急用マスまで使っている列: 最下段の緊急用マスに付く。
   - 複数列にまたがるロット: 末尾の列の下端に付く。
   - `half >= 2`: 末尾の列の下から順に付き、足りなければ前の列へ進む。
   - 手動指定あり: 指定位置に付く。一部だけ指定した場合は残りが自動で埋まる。
   - 範囲外の指定: 無視され、自動の位置に付く。
   - `manualOn` が false: 手動指定があっても自動の位置に付く。
   - ユーザーから提示された2つの配置図の状態を再現したケース。
2. `halfAreaOf()`: 手動指定あり・なし、`manualOn` の true・false。
3. 署名: `halfMarks` の有無で `currentSheetSig()` の材料が変わらない。
4. 移動: 移動したロットの `halfMarks` だけが移動元・移動先の列から消え、他ロットの指定は残る。
5. 既存テスト3件（`tests/sheet-placement.test.js` の「配置表の第2ロット半パレット印は降順配置の末尾に付ける」「配置表の准緊急込み2+6は第1ロット末尾row1に半を付ける」「配置表の両端詰め1+8は第2ロットの物理的な末尾row1に半を付ける」）の期待値を、下端基準に書き換える。

### 9-2. ブラウザでの確認

教訓（2026-09-21「機能が動く最初の1回」）に従い、機能は本物の入口（タップ・ボタン）から確かめる。スクリプトで状態を作るのは寸法の実測だけにする。

1. 設定が OFF の初期状態で、操作バーに「半」のボタンが出ないこと。
2. 設定を ON にし、メインのマスを1つタップすると「半を設定」が出ること。最初の1回で押せ、押した直後に元に戻すが押せること。
3. 盤の角バッジと配置図のグリッドの「半」の位置が一致すること。表の「P 半」の欄も合っていること。
4. 元に戻す・やり直すで「半」の位置が行き来すること。
5. 「半を自動に戻す」で下端に戻ること。
6. 「半」を指定したロットをドラッグで移動すると、指定が消えて自動の位置に戻ること。
7. 設定を OFF にすると自動の位置になり、ON に戻すと指定位置が復活すること。
8. 配置図の書き足しが、「半」の指定で消えないこと。
9. 操作バーの幅: 375px・412px・PC 幅 × 「半を設定」「半を自動に戻す」× 選択中・運搬中 の組み合わせで、2行表示が崩れず、元に戻す・やり直すの位置が動かないこと。

### 9-3. 実機での確認（Pixel 9a）

実行計画に、配布経路（サーバーの起動コマンド、Mac の LAN IP の調べ方、スマホで開く URL、同一 Wi-Fi とファイアウォールの前提）をコマンド付きで書く（教訓 2026-09-16）。確認項目は 9-2 の 2・3・9 を指で行う。
