## 1. 背景と目的

現場のレイアウトを見直した結果、いまアプリが知らない置き場が 4 つ見つかりました。
これらを配置マスの定義に加え、盤（配置編集）と紙（配置図）の両方に反映します。

| 追加するもの | 使い方 |
|---|---|
| メイン中央 9 列の下端に 1 マス | 緊急用。自動配置では使わない |
| メイン 4 / 5 / 6 / 8 列の上に 1 マス | 普通の置き場 |
| PC横の 8 マス列の左に、1 マス空けて 2 マス | 普通の置き場 |
| EV横の 5 マス列の左に、1 マス空けて 2 マス | 普通の置き場 |

「普通の置き場」は自動配置でも使い、収容能力にも数えます。
緊急用の 1 マスだけが例外で、人が手で運んだときにしか入りません。

## 2. スペース定義の変更

変更はすべて `DEFAULT_SPACES`（`files/index.html:827`）に直接書きます。
設定タブのテキストには通路マスの印も上方向の伸びも出しません。
描画位置の `row` / `off` と同じ扱いで、設定テキストから列の高さを編集すると失われます
（「初期値に戻す」で復活します）。

### 2-1. メイン

現状（`files/index.html:836`）:

```js
{name:"メイン", zone:"near", orient:"v", block:3, align:"top", sheet:"bottom", cols:[
   {h:6,aisle:true},{h:7},{h:7},{h:7},{h:7},{h:7},{h:7},{h:7},{h:7},{h:7},{h:5,aisle:true}]},
```

変更後:

```js
cols:[
  {h:6,aisle:true},                       // 0 通路列（変更なし）
  {h:8, aisleRows:[7]},                   // 1
  {h:8, aisleRows:[7]},                   // 2
  {h:8, aisleRows:[7]},                   // 3
  {h:9, up:1, aisleRows:[8]},             // 4  上に 1 マス
  {h:9, up:1, aisleRows:[8]},             // 5  上に 1 マス
  {h:9, up:1, aisleRows:[8]},             // 6  上に 1 マス
  {h:8, aisleRows:[7]},                   // 7
  {h:9, up:1, aisleRows:[8]},             // 8  上に 1 マス
  {h:8, aisleRows:[7]},                   // 9
  {h:5,aisle:true}]                       // 10 通路列（変更なし）
```

- 列の番号は紙の列番号と同じ（`SHEET_GRID_ORDER` の `c`、`files/index.html:4428`）
- `aisleRows` は「その列の何行目が緊急用の通路マスか」を持つ行番号の配列。
  列の下端を指します
- `up` は「その列が上に何マス飛び出すか」

### 2-2. PC横

PC横は `FLOOR_POS` で `flip:true`（`files/index.html:878`）なので、
行の中の並びが右起点になり、`off` も右からのオフセットとして効きます。

```js
{name:"PC横", zone:"near", orient:"h", block:99, sheet:"bottom", cols:[
   {h:4, row:0},            // 1-4
   {h:8, row:2},            // 5-12
   {h:2, row:2, off:9}]},   // 追加。8 マスの左に 1 マス空ける
```

エリアの幅は `max(off + h)`（`files/index.html:2370`）で決まるので、4 → 11 になります。
8 マス列が右から 0〜7、空きが 8、追加の 2 マスが 9〜10 です。

### 2-3. EV横

EV横は `flip` が無く左起点です。左に足すので、既存 4 列の `off` を 3 ずつ後ろへずらします。

```js
{name:"EV横", zone:"near", orient:"h", block:99, sheet:"bottom", cols:[
   {h:5, row:2, off:3},     // 1-5
   {h:1, row:3, off:7},     // 6
   {h:2, row:1, off:9},     // 7-8
   {h:2, row:0, off:9},     // 9-10
   {h:2, row:2, off:0}]},   // 追加。5 マスの左に 1 マス空ける
```

飛び地を配列の末尾に置くのは §2-4 のとおり、既存の列を使い切ってから使わせるためです。
描画の位置は `off` が決めるので、配列の順序とは独立しています。

### 2-4. 配列の順序

`cols` の並び順は自動配置で試す順でもあります（`files/index.html:828`）。
PC横・EV横に足した飛び地は端の置き場なので、**既存の列を使い切ってから使う**のが自然です。
EV横は左に足す都合で描画上の順序が変わりますが、配列の順序は
「既存の列 → 飛び地」を保ちます。描画位置は `off` が決めるので、配列の順序とは独立です。

## 3. 緊急用の通路マス

### 3-1. なぜ「上から詰める」だけで成立するか

`cellsOf()`（`files/index.html:2336`）は列の中身を上から詰めて並べるだけで、
**荷物がどの行にあるかというデータは持っていません**。`fills` は `{id, count}` の並びです。

つまり列の下端のマスには、その上が全部埋まったときにしか荷物が来ません。
これは現場の実態とも合っています（下端は他が埋まってから使う場所）。

したがって次の 2 つだけで緊急用マスになります。

- 自動配置は列の容量を 1 マス少なく見る（通路マスを引く）
- 手動移動は引かない

`cellsOf()` は変更しません。`aisleRows` を blocked と同じスキップ対象にすると、
通路マスに一生荷物が来なくなるためです。

### 3-2. 作業用のコピーに属性を通す

`buildWork()`（`files/index.html:2036`）が `SPACES` から作業用の配列 `lastSp` を作ります。
盤・紙・自動配置・知らせのすべてがこの `lastSp` を見るので、
**ここで `aisleRows` と `up` をコピーしなければ、他をいくら直しても何も起きません。**

```js
cols:s.cols.map((c,ci)=>({
  h:c.h, aisle:!!c.aisle, row:c.row, off:c.off, fills:[],
  blockedRows:blockedRowsFor(s.name,ci,blocked)
}))
```

現状はこの形で `aisleRows` / `up` を落とします。ここに 2 つを足します。

### 3-3. 容量計算の分岐

`validateMove()`（`files/index.html:2652`）が自動配置と同じ `columnFreeCount()` を
使っているため、`usableCount()` を書き換えると手動でも置けなくなります。
`usableCount()` は現状のまま（blocked だけ引く）にして、自動配置用の容量を別に足します。

呼び出し箇所ごとの扱い:

- `findRun()`（`files/index.html:2023`, `2030`）── 引く
- `placeLot()` / `fillMix()`（`files/index.html:2105`, `2117`, `2135`）── 引く
- `validateMove()`（`files/index.html:2652`）── 引かない
- 整合チェック（`files/index.html:2059`）── 引かない。
  手で通路マスに置いた状態を不正と見なさないため
- 列キャップ表示（`files/index.html:2398`）── 引かない。
  分母は物理のマス数のままにし、通路マスがある列にも `通` の印を付ける

**配置不可と重なった通路マスは二重に引かない。** `usableCount()` が配置不可の行を
既に引いているので、緊急用マスの数を数えるときは配置不可に塗られた行を除きます。
除かないと、下端を配置不可に塗った列で同じ 1 マスを 2 回引いてしまいます。

### 3-4. 触る場所

- **退避から倉庫へ戻す**（`returnSelToWarehouse()`, `files/index.html:3497`）
  いま `if(c.aisle) return;` で通路列を避けています。通路マスも同じく避けます
- **収容能力の表示**（`showCapacity()`, `files/index.html:3844`）
  通路マスは数えません。上方向に伸びた分と飛び地は数えます
- **通路を使っている知らせ**（`usedAisle`, `files/index.html:2214`）
  いまは通路「列」しか見ていません。通路マスに荷物があるときも同じ知らせに含めます。
  既存の文言のままで、列かマスかは区別しません

## 4. 上方向に伸びる列

### 4-1. いまの作りでは表せない

`cellsOf()` は行を 0..h−1 で作り、`.col.top`（`files/index.html:124`）で上揃えに描きます。
`h` を増やすと**下に伸びます**。また位置指定モード（`row` / `off`）は
横向きのエリアにしか効きません（`files/index.html:2366` の `horizontal &&`）。

そこで縦向きの列に `up`（上に飛び出すマス数）を足します。

### 4-2. 盤（配置編集）

エリアの中で `up` の最大値を取り、`up` がそれに満たない列は上に空きを作ります。
列の中身（`cellsOf()` の結果）は変えず、列を置く位置だけをずらします。

- `.col.top` は `flex-direction:column` なので、
  `margin-top: (maxUp - up) * 1マス` を列に与えるのが素直です
- マスの大きさは `--cell` で持っているので、その変数を使って計算します

### 4-3. 紙（配置図）

**上に飛び出したマスに荷物がある日だけ 8 行にします。** 荷物が無い日は
いままでと同じ 7 行の紙になります。

`gridRows()`（`files/index.html:4533`）の `for(let ri=0;ri<7;ri++)` を、
次の計算から決まる行数に変えます。

- `maxUp` ── エリアの中で `up` の最大値（今回は 1）
- `upUsed` ── `up` を持つ列の、飛び出した行（0 〜 up−1）に荷物があるか
- 列ごとの `shift` ── `upUsed` なら `maxUp − up`、そうでなければ 0
- 列ごとの `start` ── `upUsed` なら 0、そうでなければ `up`（飛び出した空きを飛ばす）
- 列ごとの `end` ── `h − 緊急用マスの数`（下端の通路マスは §5 の列番号行が受け持つ）
- 行数 ── すべての列での `shift + (end − start)` の最大値

紙の行 `ri` が指す列の中の行は `ri − shift + start` です。
負になる行（＝上に伸びない列の 0 行目）は空セル（`none`）にします。

今回の値で確かめると、

- 荷物がある日 ── 上に伸びる列は 0 ＋ (8−0) ＝ 8、他の列は 1 ＋ (7−0) ＝ 8 → **8 行**
- 荷物が無い日 ── 上に伸びる列は 0 ＋ (8−1) ＝ 7、他の列は 0 ＋ (7−0) ＝ 7 → **7 行**

**このずらしの計算は 1 か所にまとめ、`gridRows()` と `sheetGridAnchors()` の
両方が同じものを使います。** 別々に計算すると引き出し線が 1 行ずれます（§4-5）。

`at(ci, ri)` は `sp.cols[ci]` が無いときに `null` を返すこと。
太枠の左右を見る `at(o.c-1, ri)` / `at(o.c+1, ri)`（`files/index.html:4554`）が
端の列で存在しない添字を渡すため、ずらしの計算で例外になります。

### 4-4. 紙の高さ

**上の行に荷物がある日だけ 8 行にします。** 荷物が無い日は 7 行 × 30px のままで、
いまの紙と同じ見た目になります。

8 行になる日は、○を縮めて行高を詰めます。

- いまのグリッドは 7 行 × 30px ＝ 210px（`.sheet td.g`, `files/index.html:503`）
- いまの○は実寸 26px（`width:22px` ＋ border 2px × 2、`files/index.html:512`）
- 8 行の日は**○を実寸 23px**（`width:19px` ＋ border 2px × 2）にし、行高を 26px にする
- 8 行 × 26px ＝ **208px**。7 行のときの 210px に収まるので、**紙の高さは増えません**

○の中の文字（列番号・段番号・「半」）は `font-size:11px` です。
○が 3px 小さくなるので、入りきるかを実測し、必要なら 10px に落とします。

## 4-5. 8 行になる日に一緒に動くもの

行が 1 つ増えると、行番号を前提にしている箇所が 3 つ道連れになります。
どれも紙の読み方に直接効くので、同じ回で直します。

### 段番号（①〜⑦）

`circled=["①",…,"⑦"]` は 7 要素の固定配列です（`files/index.html:4531`）。

**上に飛び出したマスには段番号を振りません。** 既存の①〜⑦が指す段を変えないためです。
現場が毎日その番号で場所を呼んでいるので、番号がずれると会話が変わります。
段番号は `ri − (upUsed ? maxUp : 0)` で引き、負になる行は空欄にします。

### 引き出し線

`sheetGridAnchors()`（`files/index.html:4451`）は自前の `at` で `colCells` の
生の行番号を返し、`drawLeaders()`（`files/index.html:4636`）がその行番号で
`tr.grow` を直接引きます。§4-3 のずらしを知らないままだと、
上に伸びない列（メインの 1/2/3/7/9）のロットで線が 1 行上を指します。

`sheetGridAnchors()` にも §4-3 と同じずらしを通し、紙の行番号を返させます。
同じ関数の中の `bridged` 判定（隣の列の同じ行で太枠をつなぐ）も、
ずらし後の行で比べます。

### 追記欄の rowspan

`sideCell()`（`files/index.html:4493`）が `rowspan="8"` を直書きしています。
これは「グリッド 7 行 ＋ 列番号行 1 行」の 8 です。
グリッドが 8 行になる日は 9 になるので、行数から計算する形に変えます。

## 5. 紙での通路マス（列番号行の兼用）

下端の通路マスは、新しい行を足さずに**既存の列番号行**を兼用します。

- 列番号行は `.sheet td.colno{border:0;font-size:11px;height:20px}`（`files/index.html:536`）
- 荷物があるマスにだけ○を出す。○の中にその列の番号を書く
- 半パレットがそのマスに来た日は、番号ではなく「半」を出す（半を優先）
- セルの背景は既存の通路列と同じ灰色 `#d9d9d9` にし、
  印刷で背景色を強制出力する指定（`files/index.html:506`）も同じものを付ける
- ○の大きさは §4-4 と同じ規則に従う。7 行の日は実寸 26px、8 行の日は 23px
- 荷物があると行が 20px から押し広げられる（26px の日は ＋6px、23px の日は ＋3px）

独立した行を足すより紙に収まります。

- 列番号行の兼用: 495 ＋ 6 ＝ 501px → 印刷 1.4 倍で 701px（上限 718.5px 以内）
- 独立した行を足す場合: 行高を 20px、○を 16px に縮めても 515 × 1.4 ＝ 721px で超過

いちばん重い日（8 行 ＋ 通路マスに荷物あり）でも、
グリッドが 208px（7 行のときより 2px 少ない）、列番号行が ＋3px なので、
いまの紙より 1px 増えるだけの計算になります。着手時に実測して確かめます。

- 緊急用の通路マスは**グレー**で表示します。マス単位です。

- 配置不可セルの斜線（`.cell.blocked`）とは別の見た目にします。

- 列キャップは `used/usable` のまま。通路マスがある列にも `通` の印を付けます

## 7. 保存と互換性

- `aisleRows` と `up` は `DEFAULT_SPACES` に書く固定値です。
  設定テキスト（`spacesToText()` / `applyConfig()`, `files/index.html:3675`, `3680`）には出しません
- 設定テキストから列の高さを変えると、`row` / `off` と同じく失われます
  （`files/index.html:3702` の引き継ぎ条件に合わせる）
- `saveData(STORE_KEY.spaces, ...)` で保存される `SPACES` には含めます
  （`normalizeSpaces()` の保存形、`files/index.html:3831` を広げる）
- **`SPACES_SAVE_VERSION` を 3 から 4 に上げます**（`files/index.html:962`）。
  端末に古い設定が保存されたままだと、`DEFAULT_SPACES` を更新しても新しい置き場が
  反映されません。バージョンを上げると保存を捨てて既定値に戻し、
  「配置マスを現場の実測に合わせて更新したので、スペース設定と手動調整を
  初期値に戻しました。」と知らせる仕組みが既にあります（`files/index.html:4681`）。
  今回はまさにその場合にあたります
- `normalizeSpaces()` は `aisleRows` / `up` が無ければ「通路マス無し・上に伸びない」として
  扱います。バージョンを上げるので実際にその経路を通るのは
  手で保存を書き換えた場合だけですが、既定値の形を保ちます
- **保存済みの配置不可セルは、この更新に合わせて一括で解除します。**
  配置不可セルは「エリア名｜列｜行番号」で覚えているので（`files/index.html:1117`）、
  上に 1 マス伸びる 4/5/6/8 列では、行番号 0 が指す場所が
  「いままでの 1 段目」から「新しく増えた上のマス」に変わります。
  `pruneBlockedForSpaces()`（`files/index.html:1134`）は列の高さを超えた行しか落とさないので、
  高さが増える今回は何も落ちず、黙ってずれます。
  2026-09-15 時点で現場はこの機能を使っていないため、移行はせず解除します。
  スペース設定を初期値に戻す知らせと同じ場面で伝えます

## 8. 検証

1. **盤**: メイン 4/5/6/8 が上に 1 マス出て、他の列と上端が揃わないこと
2. **盤**: 各列の下端がグレーの通路マスになっていること
3. **盤**: PC横・EV横の飛び地が、1 マス空けて左に描かれること
4. **自動配置**: 通路マスに荷物が入らないこと（満杯時に混載を許可した日も含む）
5. **手動移動**: 列が埋まった状態で 1 マス足すと、通路マスに入ること
6. **知らせ**: 通路マスに荷物があるとき、通路を使っている知らせが出ること
7. **収容能力**: 通路マスが数に入らず、上方向の 1 マスと飛び地は数に入ること
8. **紙**: 上の行に荷物がある日に 8 行になり、無い日は 7 行のままであること
9. **紙**: 列番号行に○が出て、中に列番号が入ること。半の日は「半」が出ること
10. **紙**: 段番号の①が、いままでと同じ段を指していること。
    上に飛び出したマスの段番号が空欄であること
11. **紙**: 引き出し線が正しいマスを指していること。
    上に伸びる列（4/5/6/8）と伸びない列（1/2/3/7/9）の両方にロットがある日で見る
12. **紙**: 追記欄が出る日（欄数が足りない日）に、8 行の紙でも表が崩れないこと
13. **印刷**: 8 行になった日と、通路マスに荷物がある日の両方で 1 ページに収まること。
    目視だけでなく、溢れの見積もり（`PRINT_H_PX` / `PRINT_H_LIMIT`,
    `files/index.html:4262`）が出す「用紙の高さの N%」を読むこと
14. **実機**: Pixel 9a / Android Chrome で 1〜12 を確認すること。
    PC横・EV横はエリアの幅が 4 マスから 11 マスに広がる（`max(off+h)`,
    `files/index.html:2370`）ので、スマホの幅で崩れないことを特に見る

検証 5 は「結果が無い状態が作れない」教訓（`~/claude-lessons/lessons.md` の 2026-08-31）に
あたるので、列を埋めた状態を作る手順を先に用意します。

検証の前に Service Worker のキャッシュを解除します。
このアプリは PWA で、アセットを更新しても古い版が出ることがあります
（`~/claude-lessons/lessons.md` の 2026-07-09）。

## 9. 前提と制約

この設計が置いている前提です。外れると作り直しになるので、変えるときは設計から見直します。

- **緊急用の通路マスは列の下端 1 マスだけ**。紙では列番号行が 1 マスぶんしか受け持てません。
  2 マス以上や列の途中を指定すると、グリッド本体からも列番号行からも消えます。
  保存の検証で「下端の 1 マスであること」を確かめます
- **`up` が効くのは `align:"top"` の縦向きエリアだけ**。既定の `.grid` は下揃え
  （`files/index.html:106`）なので、上から下げる指定が見た目に出ません。
  今回の対象はメインだけで、メインは `align:"top"` です
- **設定テキストで列の高さを変えると `aisleRows` が失われる**（`row` / `off` と同じ、
  `files/index.html:3702`）。失われると緊急用マスが普通のマスに戻り、
  自動配置がそこに荷物を置くようになります。安全と逆向きの劣化なので、
  高さの編集で通路マスが消えたときは設定タブに知らせを出します

## 10. 範囲外

- 設定テキストへの記法追加（通路マス・上方向の伸びを現場が編集できるようにすること）
- 配置編集の画面から通路マスを塗って設定すること
- 通路マスを収容能力に含めること
- メイン以外のエリアに通路マスを設けること
- 保存済みの配置不可セルを新しい行番号へ移行すること（§7 のとおり一括で解除する）
