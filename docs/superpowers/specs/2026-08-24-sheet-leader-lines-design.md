# 配置図の表の引き出し線（矢印）

作成日: 2026-08-24
対象: `files/index.html`, `files/sw.js`

## 背景

手書きの配置図の表では、下段の各欄（品名・ロット・パレット数）から、
メイン配置図で対応するスペースへ実線の矢印を引いている。
アプリの作成開始時には実装が難しいと判断して見送り、代わりに
グリッドの先頭マス左上へ小さな番号（9px）を出す方式を採用した。

しかしこの番号は下段の欄には振られておらず、片側だけに数字がある状態のため、
表とスペースの対応が読み取れない。番号自体も小さすぎて視認性が低い。

矢印以外の方式（両側番号・色分け・グリッドへのロット名直書き・欄幅を列に合わせる・
対応列番号の併記）も検討したが、次の理由で見送った。

- 印刷はモノクロのため色分けは使えない
- 1列のみのロットではグリッドにロット名を書くスペースがない
- 列に混載が発生した場合にロット名の表示位置が競合する

## 現状の実装

```js
// renderSheet(): 下段の欄順で番号を作り、グリッド側にだけ表示する
const bottom = sheetEntries(SHEET_BOTTOM, "メイン");
const numOf = {}; bottom.forEach((e,i)=>{ numOf[e.lot.id] = i+1; });
...
// gridRows(): ロットの先頭マスにだけ番号を出す
const showNum = id!=null && at(o.c,ri-1)!==id && numOf[id];
tds += `<td class="${cls.join(" ")}">`
     + (showNum ? `<span class="num">${numOf[id]}</span>` : "")
     + ...
```

対応関係のデータ（下段の欄 → ロットid → グリッドの列）は既に `numOf` として存在する。
不足しているのは表示だけであり、矢印はこの既存の対応関係をそのまま描画するものになる。

## 技術的な前提

実装前に以下を実測して確認した。

1. **下段の欄順とグリッドの左右順は既に一致している** —
   `sheetEntries()` はメインの列を左から順に走査するため、
   n番目の欄は n番目に現れるロットに対応する。矢印同士は交差しない。

2. **矢印を描く縦スペースは既に存在する** —
   下段とグリッドの間には注記行 24px と gap 行 11px があり、どちらも `border:0` の透明行。
   合計 35px を矢印帯として使えるため、表の高さは変わらず印刷レイアウトに影響しない。

3. **1列1ロット専有が原則** —
   `placeLot()` は `if(col.fills.length>0) continue;` により空き列のみを使う。
   列の途中から始まるロットは `fillMix()`（満杯時の最終手段）でのみ発生する。

4. **CSS `zoom` は要素全体に掛かる** —
   `.sheet` は `zoom:var(--sheet-zoom)` で拡大される。
   SVG を `.sheet` の内側に置けば矢印も一緒に拡大されるため、
   倍率変更時に座標を再計算する必要はない。
   また `renderSheet()` が `.sheet` ごと作り直すため、描画時点では常に倍率1になる。

5. **`offsetLeft` は使えない** — 実測の結果、起点と終点で `offsetParent` が異なる。

   | 要素 | position | offsetParent |
   |---|---|---|
   | `td.slot`（起点） | static | `TABLE` |
   | `td.g`（終点） | relative（`files/index.html:203`） | `BODY` |

   `td.g` だけが `position:relative` を持つため、`offsetParent` を決めるときの
   「最も近い table 祖先」ルールから外れ、非 static の祖先（無いので body）まで遡る。
   両者を混ぜると座標が10px以上ずれる。`getBoundingClientRect()` で基準を統一する。

## 設計

### 1. 混載の向きを判定する

`fillMix()` が押し込むパレットを、原則として列の上に置く。
ただし既にその列を使っているロットが**他の列を持たない**場合は下に足す。

```js
const holder = c.fills.length ? c.fills[0].id : null;
const alone  = holder!=null && !cols.some(o=>o!==c && o.fills.some(f=>f.id===holder));
if(alone) c.fills.push({id:lot.id, count:put, mix:true});
else      c.fills.unshift({id:lot.id, count:put, mix:true});
```

混載列で下に回るロットは、通常は先行する列に上端から入っている大口である。
そのロットの矢印の終点は先行列の上端になるため、下に回っても干渉しない。

一方、既存ロットがその列にしか置かれていない場合に下へ回すと、
そのロットの矢印が途中開始になってしまう。この場合だけ従来どおり下に足し、
既存ロットを上端に残す。

全エリア満杯（134P投入）の実データで検証した結果は次のとおり。

| | 変更前 | 変更後 |
|---|---|---|
| メイン列5 | 部品E 2P ＋ 製品Z 5P | 製品Z 5P ＋ 部品E 2P |
| メイン列8 | 部品A 6P ＋ 製品Z 1P | 製品Z 1P ＋ 部品A 6P |
| 途中から始まるロット | 製品Z | なし |

メイン内の全ロットが上端から始まる配置になり、矢印の貫通・横刺しが不要になる。

#### 残る例外

同じ列に2ロット以上が混載された場合は、どちら向きに置いても途中開始が残る。
発生頻度は低いが起こりうるため、矢印側で貫通のフォールバックを用意する（後述）。

#### 副作用として確認が必要な点

- **「半」の位置** — `isHalf` の算出は `norm[id]` / `aisle[id]` のマス一覧の末尾 n 個を使う。
  `fills` の順序が変わるとマス順も変わるため、半マークの位置が変化する可能性がある。
- **下段の欄順** — `sheetEntries()` は `fills` 順に走査するため、混載列を含むエリアで欄順が変わる。
  実測では PC横の2ロット（部品D・製品X）が入れ替わった。仕様上の問題はない。

### 2. 矢印の描画

#### 配置

`<table>` を `position:relative` のラッパで包み、その中に SVG を絶対配置で重ねる。
`.sheet` 自身ではなくラッパを使うのは、`.sheet` の `padding:10px` が
印刷時に `0` になる（`@media print` の `.sheet{padding:0}`）ためで、
`.sheet` を基準にすると画面と印刷で座標が10pxずれる。

```html
<div class="sheet"><div class="sheetbox"><table>…</table></div></div>
```

```css
.sheet .sheetbox{position:relative;width:max-content}
.sheet .leaders{position:absolute;left:0;top:0;pointer-events:none;overflow:visible}
```

座標は `getBoundingClientRect()` を使い、`<table>` の矩形からの相対で求める。
`offsetLeft` は使わない（「技術的な前提」5 のとおり基準が要素ごとに違う）。
倍率が掛かった状態で測る事故を防ぐため、`.sheet` の実効 `zoom` で割って正規化する。

```js
const z = parseFloat(getComputedStyle(sheet).zoom) || 1;
const base = table.getBoundingClientRect();
const at = el => {
  const r = el.getBoundingClientRect();
  return {x:(r.left-base.left)/z, y:(r.top-base.top)/z, w:r.width/z, h:r.height/z};
};
```

`renderSheet()` が DOM を差し込んだ直後に測定して描画する。
配置図タブが非表示のときは全ての矩形が 0 になるため、描画せずに戻る
（既存の `autoSheetZoom()` と同じ扱い）。`renderSheet()` は
`onHeadChange()` や `setTiming()` から `sheetMode` を見ずに呼ばれることがある。

#### 起点

下段のパレット数セル（`slotCells(bottom, ..., "pallet")` で作られる td）の下辺中心。

#### 終点

そのロットが**上端から始まる最初の連続ブロック**の中央列の上辺中心。

- ブロックは表示上の14列（`order` 配列）を左から走査して求める
- 段番号列（`lab`）は、左右のレーンが同じロットなら連続とみなすが、刺す先の候補には含めない
- 中央は `list[Math.floor((list.length-1)/2)]`（偶数個なら左寄り）

飛び地は最初のブロックのみを見る。
例えば部品Cが列0（通路）と列9〜10に分かれている場合、全体の中心を取ると
矢印が表を横断する長大な斜線になるため、列0を終点にする。

#### 形状

起点から終点への直線1本と、線の傾きに合わせて回転させた矢頭。

```
d   = "M x0 y0 L x1 y1"
ang = -Math.atan2(x1-x0, y1-y0) * 180 / Math.PI    // 真下が0度
```

かぎ線・曲線は使わない。○を灰色にしたことで斜線の視認性が確保できるため、
閾値による分岐は不要と判断した。

#### 矢印を引かないロット

メインに1パレットも配置されていないロット（PC横・EV横のみ）には矢印を引かない。
メイングリッドは「メイン」しか描画していないため終点が存在しない。
これらは従来どおり注記（「※PC横」等）だけで表現する。

#### 例外時のフォールバック

「1. 混載を上詰めにする」の例外により、ロットが列の途中から始まる場合は、
終点の Y 座標を「その列の上端」ではなく「そのロットの開始マスの上辺」にする。
引くのは同じく直線1本で、結果として上のロットの太枠と○を斜めに横切る。
線の位置が常に明確であることを優先する。

### 3. 番号の廃止

グリッドの `<span class="num">` と CSS `.sheet td.g .num` を削除する。
`numOf` の算出も不要になる。

手書きの用紙にロット番号は存在せず、マス内の丸数字は段番号（列番号）である。
矢印で対応が取れるため番号は冗長になる。

### 4. ○の灰色化

`.sheet td.g .mk` の枠色を `#000` から `#999` に変更する。
矢印が前面に出て、線がどのマスに向かっているか追いやすくなる。

### 5. 矢頭の on/off

表示倍率のコントロール（`zoomCtl`）の隣にトグルボタンを置く。

- 既定は「矢頭あり」
- off のときは矢頭を描かず実線のみにする
- `STORE_KEY.arrow` を追加し、他の設定と同じく localStorage に保存する

## 既知の割り切り

### 注記と矢印の重なり

注記は `e.areas.filter(n=>n!=="メイン")` で作られるため、
**メインに入りきらず PC横へ溢れたロットは、矢印と注記の両方を持つ**。
両者は同じ 35px の帯を通る。

完全に避けるのは難しいため、注記行のテキストを中央揃えから左寄せに変え、
矢印が通る欄の中心とぶつかりにくくする。それでも注記が長い場合は重なるが、許容する。

### ロットが少ない日の浅い線

下段の欄は左から詰めて置かれるのに対し、終点はメイン配置図の実際の位置になる。
ロットが少ないと1ロットあたりの占有列が増え、終点が右へ広がるため、線が水平に近づく。

実測（部品A 40P・部品B 25P の2ロットのみ）では、部品B の矢印が横に 360px 動き、
35px の帯では角度84度になった。

対策として「浅い線だけかぎ線にする」「下段の欄を終点の真上に配置する」を検討したが、
前者は矢印の形状が2種類混在し、後者は表のレイアウトが手書き用紙から離れるため、
どちらも採らない。読み取れる範囲であるため直線のまま許容する。

## 確認項目

自動テストの基盤がないため、手動で確認する。

1. 標準サンプルで、メインに配置された全ロットに矢印が引かれ、正しい列を指している
2. 満杯データ（全エリア134P）で混載が上詰めになり、全矢印が列の上端に刺さる
3. 満杯データで「半」の位置が配置内容と一致している
4. メイン外のロット（PC横・EV横のみ）に矢印が引かれていない
5. 矢頭 off で実線のみになり、再読み込み後も設定が保持される
6. 表示倍率 100% / 150% / 200% / 自動 のいずれでも矢印が表に追随する
7. 印刷プレビューで1ページに収まり、**矢印が画面と同じ位置に**出力される
8. ロットが1つもない状態、およびメインが空の状態でエラーが出ない
9. 設定でエリア名を変更し「メイン」という名前のエリアが存在しない状態でエラーが出ない
10. 下段が7欄を超える（あふれ警告が出る）状態で、8件目以降に矢印が出ず既存の警告と矛盾しない
11. `fillMix` の向き判定が、既存ロットの列数に応じて上下を切り替えている
12. ロットが少ない日（2ロット程度）でも矢印が読み取れる
13. 入力タブを開いたまま搬入日や あさ/ひる を変えてもエラーが出ず、表を開くと矢印が正しく出る
