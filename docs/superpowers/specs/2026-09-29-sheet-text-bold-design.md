## 1. 目的

現場では、品名やロットの一部を太字にして違いを強調することがある（例: ロット `ABC123` と `ABC128` の末尾だけを太くする）。
配置図のテキスト編集で、1文字単位で太字を付けられるようにする。

### 決定事項（ブレストでの合意）

| 項目 | 決定 |
|---|---|
| 太字の単位 | 1文字単位 |
| 対象の欄 | 書き足しできる欄すべて（品名・ロット・P数・注釈・上段の見出し・追記欄） |
| 操作 | 範囲選択＋「B」ボタン（Ctrl+B も同じ動き） |
| 編集できる端末 | PC（601px 以上、Windows ＋ Chrome）だけ。スマホは表示だけ |
| 太さ | `font-weight:700` 固定 |
| 欄の太字設定が ON の欄 | 見た目は変わらない。これを仕様とする。強調したいときは、表示設定でその欄の太字を OFF にしてから使ってもらう |
| 「B」ボタンの位置 | 編集中の欄のすぐ上に浮かべる |
| スマホで太字付きの欄を直したとき | 文字が変わらなければ太字を残す。変わったら太字を全部外す |
| Ctrl+Z | Chrome に任せる。実害が出たら、そのとき考える（§6-3） |
| セル内の改行 | 見送り（今回の範囲外）。縦積みの欄で既にある改行は、今までどおり扱う |

### 範囲外

- 1行の欄で改行を入れられるようにすること
- 太字以外の装飾（下線・色）
- スマホでの太字の編集
- マニュアル（`manual/`）の更新

## 2. 現状

### 2-1. 書き足しの保存

- `activeShift().sheetEdits` に `{sig, marks}` を持つ。`marks` は「欄キー → 文字列」のみ。
- `normalizeSheetEdits`（`files/index.html:1456`）は、読み込み時に文字列以外の値を捨てる（`:1462`）。
- `normalizeMarkValue`（`:3790`）は、行ごとに前後の空白を削り、空行を捨てる。
- `saveSheetMark`（`:6080`）は、空文字か「自動計算の値と同じ」ならキーを消す。これが「欄ごとの取り消し」になっている。

### 2-2. 描画

書き足しの値を読むのは次の3か所だけ（`grep -nE 'marks\[|mk\['` で確認済み）。

| 場所 | 行 | 組み立て |
|---|---|---|
| 上段の見出し（`renderSheet` 内） | `:6256` | `<span class="fit">${esc(label)}</span>` |
| 上下段の欄 `slotCells` | `:6407` | `markSpan(mv)`（`:6371`） |
| 追記欄 `overflowTable` | `:6486` | `markSpan(mv)`（`:6437`） |

いずれも `const edited=(mv!=null&&mv!=="")` で書き足しの有無を判定し、値を文字列として `esc()` に渡している。
値がオブジェクトになると `"[object Object]"` が紙に出るので、3か所とも必ず直す。

`slotCells` と `overflowTable` の `markSpan` には「ここで別の関数を呼ばないこと」という注意書きがある。
テストが `new Function(依存名..., src)` で関数の本体だけを評価するためで、依存名に無い名前は `ReferenceError` になる。

### 2-3. 編集欄

- 600px を境に入力面を切り替える（`compactInputMq`）。
  - PC: `openInlineEditor`（`:6095`）。欄の中身を `input`（1行）か `textarea`（縦積み）に差し替える。
  - スマホ: `openBarEditor`（`:6126`）。表の外の `#sheetEditBar` で編集する。
- 最初に入れる文字は `sheetCellText(td)`（`:6071`）で画面から読む。太字の情報は画面から取れない。
- 確定は `flushSheetEdit`（`:5950`）で、`el.value` を `saveSheetMark` に渡す。
- 編集中の `input`/`textarea` の見た目は CSS（`:699-713` 付近）で、行の高さを1pxも変えないように調整してある。

## 3. 設計

### 3-1. 保存形式

- 太字が無い欄は、今までどおり文字列で保存する（`"ABC123"`）。既存のデータは変換しない。
- 太字がある欄だけ、次の形で保存する。

```js
{ text: "ABC123", bold: [[3, 6]] }
```

- `bold` は `[開始, 終了)` の配列。位置は JavaScript の文字列の添字（UTF-16 のコード単位）で数える。
- 範囲は昇順に並べ、重なる範囲・隣り合う範囲は1つにまとめる。0文字の範囲は持たない。
- 縦積みの欄では、改行 `\n` も1文字として数える。

### 3-2. 正規化 `normalizeMark(raw)`

`normalizeMarkValue` の代わりに使う新しい関数。入力は文字列か `{text, bold}` のどちらか。戻り値は正規化した値（文字列か `{text, bold}`）。

1. 文字列なら `{text: raw, bold: []}` として扱う。
2. 1文字ずつ「太字か」の配列を作る。
3. 行ごとに、前後の空白を捨てる。空行も捨てる。捨てた文字は、太字の配列からも同じ位置を消す（今の `normalizeMarkValue` と同じ結果の文字列になることが条件）。
4. 太字の配列から範囲を作り直す（これで、まとめと0文字範囲の除去が一度に済む）。
5. 範囲が空なら、文字列だけを返す。空でなければ `{text, bold}` を返す。

- `normalizeMarkValue` は残す。呼び出し元は `saveSheetMark`（`:6082-6083`）だけで、`tests/sheet-placement.test.js:2617`・`:3028` がこの関数を直接取り出してテストしている。
  - `saveSheetMark` は `normalizeMark` を使うように変える。`tests/sheet-placement.test.js:3033` で `saveSheetMark` を評価するときの依存名の並びに `normalizeMark` を足す。
  - 自動計算の値（`autoText`）は常に文字列なので、比較用には今までどおり `normalizeMarkValue` を使ってよい。
- 範囲の値が壊れているとき（数値でない、`開始 >= 終了`、文字数を超える）は、その範囲を捨てる。

### 3-3. 読み込み時の検査 `normalizeSheetEdits`

- 文字列に加えて、`{text: 文字列, bold: 配列}` の形も受け付け、`normalizeMark` を通して保存する。
- それ以外の形のものは捨てる。`text` が文字列で `bold` だけ壊れているものは、太字を捨てて文字だけ残す。
- 正規化の結果、文字が空になったものはキーごと捨てる（今の「空文字は捨てる」と同じ）。

### 3-4. 保存 `saveSheetMark(key, raw, autoText)`

- `raw` は文字列か `{text, bold}`。`normalizeMark` を通す。
- 削除するのは、次のどちらかのときだけ。
  - 文字が空
  - 文字が自動計算の値と同じ、かつ太字が無い
- 文字が自動計算の値と同じでも、太字があれば保存する。

### 3-5. 描画

- 3か所（§2-2）で、書き足しの値が `{text, bold}` のときは、文字を「太字の区間」と「普通の区間」に分け、太字の区間だけを `<b>` で包む。各区間はそれぞれ `esc()` を通す。
- 縦積みの欄は、改行の位置で行を分け、行ごとの `.fit` の中で同じように組み立てる。行を分けたあとも、太字の位置は通し番号で合わせる（改行の分を1つ進める）。
- 太字が無い値（文字列）は、今までと同じ HTML を出す。既存のテストの期待値は変えない。
- `slotCells` と `overflowTable` の `markSpan` は、外の関数を呼ばずに中に直接書く（§2-2 の制約）。3か所で同じ処理が重複するが、既存の方針に従う。重複した3か所が同じ HTML を出すことはテストで確かめる（§5-1）。
- `edited` の判定は「値が文字列で空でない、または `{text, bold}` の形」とする。
- CSS: `.sheet .fit b{font-weight:700}`。

`fitSheetText`（`:5768`）は `.fit` の外側の幅を測るので変更しない。太字にした文字の分だけ幅が広がり、縮み率が上がる。40% を割れば、既存の「入りきらない」案内に出る。

### 3-6. PC の編集欄（`openInlineEditor`）

**要素**
- `input`/`textarea` を、`<div contenteditable="plaintext-only">` に置き換える。
- 1行の欄は `white-space:nowrap`、縦積みの欄は `white-space:pre`。
- 既存の CSS（行の高さを変えない、`outline:none`、`font-size:max(13px,1em)`、`line-height:inherit`、中央寄せ）を、この `div` にも当てる。
- 太さは欄のもの（`td.c-name` などの `--fw-*`）を受け継ぐ。`<b>` の部分は 700 になる。

**最初の中身**
- 保存済みの書き足しがあれば、`activeSheetMarks()` から `key` で引いて、`<b>` 付きで組み立てる。
- 無ければ `data-auto`（自動計算の値）を文字として入れる。
- 組み立ては §3-5 と同じ規則。この関数は `new Function` の制約を受けないので、共通の関数を呼んでよい。
- 開いたら全文を選択する（今の `el.select()` と同じ）。

**編集中の画面を `{text, bold}` に読み取る処理**
- `div` の中を先頭から `TreeWalker` でたどる。
  - テキストノードは、その文字を足す。祖先（`div` まで）に `<b>` があれば太字とする。
  - `<br>` は `\n` を足す。
- 1行の欄では、読み取った文字から `\n` を取り除く。貼り付けで改行が紛れ込んでも1行に収まる。
- 最後に `normalizeMark` を通す。

**キー操作（`keydown`）**

| キー | 動き |
|---|---|
| Enter（1行の欄） | 確定（`blur`）。`isComposing` が true のときは何もしない |
| Enter（縦積みの欄） | `preventDefault` し、選択位置に `\n` のテキストを入れてカーソルをその後ろに置く。`isComposing` が true のときは何もしない |
| Esc | 取り消し（今と同じ `cancelSheetEdit`） |
| Ctrl+B | `preventDefault` し、「B」ボタンと同じ処理 |
| Ctrl+Z / Ctrl+Y | 何もしない（Chrome の既定の動き） |

**確定**
- `sheetEditing` に、`el.value` の代わりに「読み取り関数」を持たせる。`flushSheetEdit` はそれを呼んで `saveSheetMark` に渡す。
- blur で確定するのは今と同じ。

### 3-7. 「B」ボタン

**置き場所**
- PC の編集欄を開いたときに、`.sheetbox`（`:597`、`position:relative`）の中へ `<button class="sheet-bold-btn">B</button>` を1つ入れる。
- 位置は、編集中の `td` の左上から上へずらした場所にする。`td` と `.sheetbox` の `getBoundingClientRect()` の差を、`.sheet` の `zoom` で割って求める（既存の `drawLeaders` と同じ考え方）。
- `.sheetbox` の中なので、横スクロールや表示倍率が変わってもボタンは欄と一緒に動く。
- 印刷の CSS で非表示にする。

**押したとき**
- `mousedown` で `preventDefault` する。フォーカスと選択範囲を残すため（blur で確定が走らないように）。
- 表の `mousedown` の処理（欄を開く処理）は `td[data-ek]` にしか反応しないので、ボタンを押しても欄は開かない。
- 処理は `click` で行う。

**太字の切り替え `toggleBold(model, start, end)`**
- `start === end`（カーソルだけ）のときは何もしない。
- 範囲の文字がすべて太字なら、太字を外す。1文字でも太字でない文字があれば、範囲をすべて太字にする。
- 結果は `normalizeMark` と同じ規則で範囲をまとめる。
- 画面とは切り離した純粋な関数にして、テストする。

**処理の流れ**
1. 画面を `{text, bold}` に読み取る（§3-6）。
2. 選択範囲を文字位置 `[start, end)` に変える（`Selection` の `anchor`/`focus` を、読み取りと同じ順番でたどって数える）。
3. `toggleBold` をかける。
4. `div` の中身を組み直す。
5. 選択範囲を、同じ文字位置で元に戻す。

**消すとき**
- 欄を閉じるとき（確定、取り消し、別の欄への移動、タブの移動、600px を跨いだとき）に、ボタンも消す。
- `renderSheet()` は `#sheetView` を丸ごと入れ替えるので、描き直しのときにはボタンも自然に消える。ボタンの有無を別の状態として持たない。

### 3-8. スマホの編集バー（`openBarEditor`）

- `input`/`textarea` のままにする。太字は付けられない。
- 開いたときに、保存済みの書き足し（`activeSheetMarks()` の `key`）を `sheetEditing.orig` に控えておく。
- 確定時の処理
  - 入力された文字を `normalizeMark` した結果が、`orig` の文字と同じなら、`orig` の太字をそのまま付けて保存する。
  - 違えば、文字列だけで保存する（太字は全部外れる）。
- 表の上での太字の表示は PC と同じ（§3-5）。

### 3-9. 変えないもの

- 署名（`sig`）の仕組み。配置が変わったら、書き足しと一緒に太字も捨てる。
- 「テキスト編集を戻す（N件）」などの件数。キーの数で数えるので、太字の有無で変わらない。
- 印刷の経路で `confirm()` を出さない規則（`flushSheetEdit` の注意書き）。

## 4. 技術制約（調査済み・2026-09-29）

| 項目 | 内容 | 判断 |
|---|---|---|
| `contenteditable="plaintext-only"` | Chrome 51 以降で対応（MDN）。Firefox は 136 以降。書式コマンドと、貼り付けの HTML が効かない | 対象の Windows Chrome で使える |
| `Selection` / `Range` / `TreeWalker` | 全ブラウザで対応 | 問題なし |
| `document.execCommand` | 非推奨。欄の太字設定が ON のとき、Chrome は `<span style="font-weight:normal">` を差し込むなど、結果が読めない | 使わない |
| フォント | Windows の Chrome は font-family から Yu Gothic を選ぶ。Yu Gothic には Bold があるので 700 は本物の太字になる | 700 固定で決定 |
| IME（MS-IME）の変換中 | 変換中の文字が `<b>` の中に入るか外に入るかは、Chrome がカーソルの位置で決める。事前に断定できない | 実機で確認する（§6-2） |
| Ctrl+Z | アプリが中身を組み直すと、Chrome の取り消し履歴が中身と合わなくなる。何も起きない、または予想外の文字が消える可能性がある | Chrome に任せ、実機で挙動を記録する（§6-3） |
| 保存容量 | `{text, bold}` は数十バイト。書き足しは多くても数十件なので、localStorage の容量には影響しない | 問題なし |
| 旧版との互換 | Service Worker の更新前の古い版がこのデータを読むと、太字付きの欄は §2-1 の検査で捨てられる | 使う端末がそれぞれ1台で、更新は自動なので許容する |
| 印刷 | `font-weight` は背景色と違い、印刷ダイアログの「背景のグラフィック」に左右されない | 問題なし |

### 過去の教訓（`~/claude-lessons/lessons.md`）から反映するもの

- **幅で排他表示される2つの入力面（2026-08-27）**：PC とスマホで入力面が別。「B」ボタンと読み取り処理は PC 側（`openInlineEditor`）にだけ置き、スマホ側に `focus()` などを向けない。
- **非表示タブでは `getBoundingClientRect()` が 0 を返す（2026-08-23）**：「B」ボタンの位置は、欄を開いた時点（配置図タブが表示されているとき）に測る。`renderSheet()` の中では測らない。
- **印刷1ページの高さ予算（2026-09-18）**：今回の変更は横幅だけに効き、高さは変えない。新しく見積もる項目は無い。
- **寸法ばかり測り、機能が動く最初の1回を試していなかった（2026-09-21）**：確認は本物の入口（欄のクリック、ボタンのクリック）から行い、「何も書き足していない欄に、最初の1回の太字を付ける」を必ず試す（§5-2）。

## 5. テスト

### 5-1. 単体テスト（`node --test tests/`、新規 `tests/sheet-bold.test.js`）

既存のテストと同じく、`files/index.html` から関数の本体を取り出して評価する。

- `normalizeMark`
  - 行頭・行末の空白や空行を削ったとき、太字の範囲が正しくずれる
  - 0文字になった太字の範囲を捨てる
  - 重なる範囲・隣り合う範囲を1つにまとめる
  - 太字が無くなったら文字列の形に戻る
  - 壊れた範囲（数値でない、`開始 >= 終了`、文字数を超える）を捨てる
  - 文字列を渡したときの結果が、旧 `normalizeMarkValue` と同じ
- `normalizeSheetEdits`
  - 文字列の形と `{text, bold}` の形の両方を読める
  - `bold` が壊れたものは、太字を捨てて文字だけ残す
  - `text` が文字列でないものは捨てる
- `saveSheetMark`
  - 文字が自動計算の値と同じでも、太字があれば残る
  - 太字が無く、文字が自動計算の値と同じなら削除される
- `toggleBold`
  - 範囲がすべて太字なら外れる
  - 一部でも太字でなければ全部が太字になる
  - 範囲が0文字なら何もしない
- 描画
  - 見出し・`slotCells`・`overflowTable` の3か所で、同じ `{text, bold}` から同じ `<b>` 付きの中身が出る
  - 太字の区間にも `esc()` が効いている（`<` などが HTML にならない）
  - 縦積みの欄で、改行をまたいで太字の位置が合う
  - 文字列の値は今までと同じ HTML になる
- スマホの確定
  - 文字が同じなら太字を残す
  - 文字が変われば太字を外す
- 既存のテストがすべて通る

### 5-2. ブラウザでの確認（PC 幅 `width:1280, height:900`）

`python3 -m http.server 8765 --directory files` で起動し、`http://localhost:8765` を開く。
入力タブでサンプルを入れて「自動配置を作成」を押し、配置図タブで「✏ テキスト編集」を押す。

1. **最初の1回**：何も書き足していない欄を開く → 範囲を選ぶ → 「B」を押す → 確定 → 太字が残る。リロードしても残る。
2. 書き足した欄で、太字の一部を外す。全部外して文字も自動計算の値に戻すと、書き足しの印（黄色い背景）が消える。
3. 縦積みの欄、上段の見出し、追記欄で、1 と同じ操作をする。
4. Ctrl+B、Esc、欄の外のクリック、別の欄のクリック、タブの移動、印刷プレビュー。
5. 表示倍率を 150% にしたとき、横スクロールしたときに「B」ボタンが欄のすぐ上にある。
6. 太字にした欄の横縮みが、確定後に掛かり直している。
7. Ctrl+Z の挙動を記録する（直すかどうかは結果を見てから決める）。

手動確認の限界: 合成イベントでは、IME の変換や、Chrome の既定の編集動作（文字の入力、貼り付け、Ctrl+Z）は再現できない。
「B」ボタンの処理と読み取り処理はスクリプトから選択範囲を作って確かめられるが、文字の入力を伴う確認は §6 の実機に回す。

## 6. 実機での確認

### 6-1. 起動

```bash
python3 -m http.server 8765 --directory files
```

同じ LAN の Windows PC からは `http://<Mac の IP>:8765` を開く。本番に出したあとは、本番の URL で確認する。

### 6-2. Windows ＋ Chrome（MS-IME）

1. 太字にした範囲のすぐ後ろにカーソルを置き、日本語を変換して確定する。太字が続くか、切れるかを記録する。
2. 太字の範囲の途中で変換して確定する。文字が壊れないこと。
3. 別のアプリからコピーした書式付きの文字を貼り付ける。書式が付かず、文字だけが入ること。
4. 印刷プレビューと実際の印刷で、太字が出ること。

### 6-3. Ctrl+Z

1. 文字を打つ → 範囲を選んで「B」 → Ctrl+Z。
2. 「B」の後に文字を打つ → Ctrl+Z を数回。

結果を記録する。文字が壊れるなど実害があれば、その時点で対策（自前の取り消し履歴、「B」の後は Ctrl+Z を無効にする、など）を相談する。

### 6-4. Pixel 9a（Android Chrome）

1. PC で太字を付けた欄が、スマホでも太字で表示される。
2. 編集バーで文字を変えずに確定すると、太字が残る。
3. 文字を変えて確定すると、太字が外れる。
