## 1. 目的

Codex で制作していた10ページ版マニュアル（`outputs/manual-20260922/`）は、9/22時点のアプリ画面で作られている。その後のアプリ更新（配置図の8欄様式、列内の詰め方、「半」の位置指定、分割確認設定）が反映されておらず、本文にも誤りがある。

これを11ページ版として作り直す。あわせて、本文の原本を1か所にまとめ、再撮影・再組版をコマンド1本ずつで行えるようにする。

## 2. 方針

- 図はすべてアプリの実画面とする。現場と対応しない模式図（Codex版 P2 の「●2×3」のロット図、P6 の「AAA/BBB」の前後図）は使わない。
- 配置の図は、ユーザーが手動で調整した配置（9/25 あさ・100P）を使う。自動配置の図は、P6 の前後比較の「前」にだけ使う。
- 本文の原本はページ別HTML（`manual/pages/p01.html`〜`p11.html`）。`docs/manual-*.md` は Codex 版の記録として残し、更新しない。
- 見出しの番号は普通の数字（`4.2`）、図と対応する操作手順だけ丸数字（①②③）を使う。
- 本文の文字を縮小してページに収めることはしない。収まらなければ図の範囲を絞るか、相談する。
- 対象読者は導入前の現場メンバー。PC（マウス・キーボード）での操作を説明する。
- 用紙はA4縦。アプリが出力する配置図はA4横で、本文でも区別して書く。

## 4. デモデータ

### 4-1. 出典

ユーザーがブラウザから書き出した `palletApp.*` の保存データ（リポジトリ直下の `pallet-state-manual.json`）。内容は次のとおり。

- 搬入日 2026-09-25（金）、あさ、10ロット、合計100P
- 自動配置の結果（`result`）と、ユーザーが手動で調整した配置（`manual`）の両方を持つ
- 品目・ロット・SNP・個数は `outputs/demo-20260922/デモデータ_100P.xlsx`（予定表）と一致する

### 4-2. 伝票の分け方

書き出しデータは FAX 1枚に10品目が入っている。マニュアルの入力ページでは、次の5枚に分ける。品目の並び順は書き出しデータのまま変えない（4-4）。

| 伝票 | 品目 |
|---|---|
| FAX① | 製品1 111 |
| FAX② | 製品2 222 |
| FAX③ | 仕掛品1 111-1111、111-1112、111-1113（1枚に複数ロットがある例） |
| FAX④ | 仕掛品2 222-2222、222-2223、仕掛品3 333-3333 |
| FAX⑤ | 仕掛品3 333-3334、仕掛品4 444-4444（未着 → 仮伝票 → 受領） |

仕掛品4 は予定表で 28,500 個（15P）、届いた FAX で 27,000 個（14P、表示は「13P 半」）。合計は仮伝票の段階で 101P、受領後に 100P になる。

### 4-3. 状態ファイル

| ファイル | 中身 | 使うページ |
|---|---|---|
| `manual/state/s1-planned.json` | FAX①〜④＋仮伝票（FAX⑤、仕掛品4 は 28,500）。配置結果・手動配置なし | P3、P4 |
| `manual/state/s2-final.json` | FAX①〜⑤（受領済み）、自動配置の結果と手動配置を含む | P1、P2、P5〜P11 |

どちらも `pallet-state-manual.json` から生成する。生成手順はスクリプト（`manual/make-states.cjs`）にして、手で JSON を書き換えない。`pallet-state-manual.json` は `manual/state/source-export.json` へ移す。

設定は状態ファイルで固定する。

- `palletApp.frac`（入力画面で「半」表示）: ON
- `palletApp.splitConfirm`（分割の確認）: 既定の ON（P5 でダイアログを撮るため。書き出し時の OFF は使わない）
- `palletApp.halfManual`（「半」の手動設定）: OFF。P7 の撮影時だけ ON にする

### 4-4. 手動配置が復元される条件（実測済み）

アプリは、保存した手動配置を、入力内容の指紋（品目ID・種別・品名・ロット・SNP・個数の並び）と列構成が一致するときだけ復元する。伝票の分け方は指紋に含まれない。

2026-09-24 に、書き出しデータの伝票を 4-2 の5枚に分けて読み込み、次のとおり確認した。

- 画面上部の表示は「FAX伝票 5枚 ／ 仮 0件」
- メインの各列の中身が書き出しデータの `manual.sp` と同じ
- 配置図の見た目がユーザーのスクリーンショットと同じ

品目の並び順を変えるとロットIDの割り当てが変わり、復元されない。Codex版の FAX の分け方（FAX③ に 111-1111・111-1112・222-2222）は並び順が変わるため使わない。

- 4.1 選択: Codex版の表を踏襲（クリック、Shift＋クリック、矩形で囲む、荷物のない位置をクリックで全解除）。「選択・移動はロットごと」を太字で残す。

### P6 4. 配置編集（2）配置を整える

- 4.3（差し替え）: 配置編集の盤全体（倉庫外・壁・倉庫内。退避スペースは除く）を、自動配置と手動配置で並べる。画像は小さくてもよく、編集している様子が伝わることを優先する（ユーザー指示）。自動側は s2 から手動配置を外して撮る。本文は実データで手動で変えた3点で説明する：製品1・製品2 を軒下①へ集めた／仕掛品3 を軒下①からメインへ入れた／仕掛品2 の2ロットを境目の列で混載した。ページに収まらなければメインだけに絞る。
- 4.4 退避: 自動配置で置き場がない荷物は退避スペースへ入る。ロット全体を選んで退避できる。退避に残った荷物は配置図に「※未定」として載る。図は s2 に条件（配置不可エリアの追加など）を加えた別の場面で撮り、そのことを本文に書く。
- 4.5 配置不可: 「配置不可エリアを設定」でマスを指定し、「自動配置を実行」。必須ではない。図は別の場面。

### P7 4. 配置編集（3）「半」の位置（新規）

- 4.6 初期位置: 「半」はロットのまとまりの下側に付く。配置編集の盤でも、「半」のマスの右上に「半」の印が出る。図は s2 の盤の該当列（列4、111-1113 の最下段）の切り出し。
- 4.7 位置を指定する:
  1. 設定の表示設定で「配置編集で『半』の位置を手動で設定する」を ON にする（初期値 OFF）。
  2. 配置編集で、メインの「半」を付けたいマスを1つだけ選ぶ。
  3. 帯に出る「半を設定」を押す。「半」がそのマスへ移る。
  - 図は、設定のチェック、「半を設定」ボタン、指定前後の盤または配置図の「半」の位置。
- 注意:
  - 指定できるのはメインだけ。ほかのエリアは表の「○P 半」表記で表す。

  - そのロットを移動すると、指定は消えて自動の位置に戻る。自動配置をやり直したときも消える。
  - 「半を設定」も戻す・進むの対象になる。

## 6. ファイル構成と制作の流れ

```
manual/
  README.md             ビルド手順
  package.json          devDependencies: playwright-core（導入済み）
  make-states.cjs       state/source-export.json → s1-planned.json / s2-final.json
  capture.cjs           状態を読み込んで撮影 → assets/*.png、dist/verification.json
  capture/              撮影の場面（input.cjs / edit.cjs / sheet.cjs）
  lib/                  共通処理（paths / scene / verify / states / build-lib）
  test/                 node:test の単体テスト（状態の生成、組版の部品）
  build.cjs             pages/*.html ＋ style.css → dist/操作マニュアル.html
  render.cjs            dist/操作マニュアル.html → dist/操作マニュアル.pdf、layout-check.json
  style.css
  pages/p01.html … p11.html
  state/source-export.json, s1-planned.json, s2-final.json
  assets/               撮影した画像（コミットする）
  dist/                 HTML・PDF・検証結果・ページのプレビュー画像 preview/pNN.png（コミットする）
```

- 実行順は `make-states` → `capture` → `build` → `render`。`package.json` の scripts に1本ずつ登録し、`npm run all` で通しで実行できるようにする。
- `pages/pNN.html` はページの本文だけを持つ断片。見出し・リード文・タブ表示などの共通部分は `build.cjs` が付ける。図は `<img src="assets/○○.png">` で参照する。
- `dist/操作マニュアル.html` は画像を data URI で埋め込み、1ファイルで開けるようにする（Codex版と同じ）。
- 組版は Node にまとめ、Codex版の Python スクリプト（`build-manual.py`）は使わない。
- `.gitignore` に `manual/node_modules/` を追加する。
- 作業はブランチ `feat/manual-11pages` で行う。`manual/dist/` は最後に1回だけコミットし、途中のレビューでは PDF をファイルで直接渡す（リポジトリの肥大と、main への push ごとの Pages デプロイを避ける）。
- `dist/verification.json` に撮影時のアプリ版（`files/sw.js` の `CACHE_VERSION` と `files/` の最終コミット）を記録し、フッターにもアプリ版を入れる。
- Codex版の `outputs/manual-20260922/`、`outputs/manual-prototype/`、`docs/manual-*.md` は記録として残し、変更しない。

## 7. 検証

### 7-1. 撮影時（`capture.cjs`）

各場面で次を確かめ、食い違えば例外で止める。結果は `dist/verification.json` に書く。

- 合計パレット数（s1: 101、受領後と s2: 100）
- 画面上部の伝票枚数（s1: 「FAX伝票 4枚 ／ 仮 1件」、受領後と s2: 「FAX伝票 5枚 ／ 仮 0件」）
- s1 から受領操作をした後の入力内容の指紋が、s2 の指紋と一致すること
- s2 を読み込んだとき、メインの各列の中身が `source-export.json` の `manual.sp` と一致すること（手動配置が復元されていること）
- P5 の移動: 空きが足りない列へのドラッグで配置が変わらないこと、空きに入る枚数では移動が成立し、選択が解除されること
- P7: 「半を設定」の前後で「半」のマスが変わること

### 7-2. 組版（`render.cjs`）

- `dist/layout-check.json` に、ページごとの「本文下端からフッターまでの余白」と「画像がすべて読み込めたか」を書く。
- 全11ページで余白が0以上、画像がすべて読み込めていること。

### 7-3. 目視

- PDF を画像にして全ページを確認する。
- 途中段階（数ページ組めた時点）でユーザーにレビューを依頼する。

## 8. 技術制約

外部 API に新しく依存する機能は無い。撮影・組版に使う Chrome と Playwright の制約、および過去の教訓（`~/claude-lessons/lessons.md`）から、次を守る。

- **ブラウザ**: `playwright-core` 1.x と、インストール済みの Google Chrome（2026-09-24 時点 153.0.8010.53）を `executablePath` で使う。ブラウザ本体はダウンロードしない。Chrome の更新で Playwright と合わなくなった場合は、`playwright-core` を更新する。
- **Service Worker**: アプリは cache-first の Service Worker を持つ。撮影ではブラウザコンテキストを `serviceWorkers:'block'` で作り、常に最新の `files/index.html` を読む（教訓 2026-07-09、2026-08-31）。
- **非表示タブ**: 非表示のタブでは寸法が0になり、配置図の引き出し線が描かれない。撮影・計測の前に、ユーザーと同じくタブのボタンを押して表示を切り替える（教訓 2026-08-23、2026-08-30）。
- **確認ダイアログ**: 「入力をクリア」、未登録品目の登録確認（`files/index.html:3849`）、ロット分割の確認（`applyMove()`）はブラウザ標準の `confirm()` で、スクリーンショットに写らない。撮影ではダイアログを自動で承諾し、承諾する前に文言を `verification.json` に記録する。P4 の登録確認と P5 の分割確認は、`build.cjs` が記録済みの文言から「画面例：確認ダイアログ（見た目はブラウザによって異なります）」と明記した再現図を組む。文言を手で書き写さない。
- **トップレベル変数**: `lastLots`・`lastSp` は `window` のプロパティにならない。ページ内では `eval('lastSp')` で読む（教訓 2026-08-31 追記）。
- **起動時の自動読込**: 保存データが無いとアプリはサンプルを自動で読み込む。状態は `addInitScript` で、ページの最初の読み込み前に `localStorage` へ入れる。2回目以降の読み込みで上書きしないよう、`sessionStorage` の印で1回だけ入れる。
- **印刷の背景色**: PDF 化は `printBackground:true`。配置図の灰色（通路・緊急用マス）が画像として写っていることを目視でも確認する（教訓 2026-08-23）。
- **ページの高さ予算**: A4縦で、本文がフッターにかからないことを `layout-check.json` で機械的に確かめる。図を追加する P5〜P8 は、組んだ時点で余白を測ってから次のページへ進む（教訓 2026-09-18）。
- **フォント**: 本文はヒラギノ角ゴシック。PDF にはフォントが埋め込まれるが、別の Mac で `build` すると字形が変わる可能性がある。制作はこの Mac で行う。

### 改行の方針

本文は、段落中に文が2つ以上続く箇所は、文の終わり（「。」の後）で `<br>` を入れて1文ごとに改行する。ページの余白に収まる範囲でのみ入れ、はみ出す場合は改行を減らす。箇条書き・表中・図説明（figcaption）も、1文が長く2文以上のときは同様にする。

### 小さい画像の扱い

撮影範囲が広すぎて画像が小さくなる図は、伝えたい部分（ボタン・チェックボックスの行・該当ロットのマスなど）だけに撮影範囲を切り詰める。ページの `.h9`〜`.h115` クラスで表示の最大高さも調整する。
