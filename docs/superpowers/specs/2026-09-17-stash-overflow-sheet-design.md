## 1. 背景と目的

倉庫にも「あふれ受け（出庫口横・5棟壁際）」にも入りきらなかった荷物は、
いま `lot.rem` に残るだけで、盤にも配置図（紙）にも現れない。
画面に出るのは入力タブの合計（`files/index.html:2343`）と警告文（同 2322）だけである。

現場の実態を確認したところ、あふれた荷物は次のように扱われている。

- 通路や空きに無理やり置く。どの荷物がいつ来るか分からないため、
  先に来た荷物を入庫するとそのスペースが空き、そこへ置くこともある
- **紙の配置図には欄外に押し込んででも記載し、存在を必ずチームに知らせる**

つまりあふれ荷物の要件は「置き場所を決めること」ではなく、
**「置き場所が決まらないまま、紙に必ず載せること」** である。

退避スペース（`zone:"stash"`）はすでに「倉庫に実在しない、位置に意味を持たない置き場」
として実装されている（`docs/superpowers/specs/2026-09-03-stash-space-and-sweep-select-design.md`）。
あふれ荷物の性質と一致するので、これを受け皿として使う。

この変更で次の2つを入れる。

- 自動配置で倉庫に入りきらなかった分を、退避スペースへ自動で入れる
- 退避スペースの中身を、配置図（紙）に「置き場未定」として載せる

## 2. 決めたこと

2026-09-17 のブレストで決めた。後半の4件は、設計の穴を洗い出したあと（§12）に決めた。

| 論点 | 決定 |
|---|---|
| 紙の出し先 | 追記欄を共用する。**欄数超過を先に載せ**、余った枠にあふれを載せる |
| 空き欄を埋める順 | **上段 → 下段 → 追記欄**。それでも入らなければ警告 |
| 退避の中身の区別 | **区別しない**。由来（自分で逃がした／あふれた）を問わず、退避に残っている分は全部紙に出す |
| 自動配置のやり直し | **区別せず全部残す**（現状の仕様のまま）。倉庫に空きができても自動では戻さず、手で戻す |
| 注釈の文言 | **「置き場未定」** |
| 紙の様式 | あふれの欄も欄数の判定に**数える**。あふれのために normal → wide になってよい |
| タブ移動 | 退避に荷物が残ったまま配置編集タブを離れるとき、**確認ダイアログで止めて聞く** |
| 項目単位の枠線 | **今回は入れない**（別件としてメモに残す） |
| 追記欄に入りきらない日 | **最後の枠を「まとめ欄」にし、残り全部の品名とパレット数を縦積みする**（§4-5） |
| 確認ダイアログの座 | **タブボタンの `onclick` 側**に置く。`switchTab()` には入れない（§5） |
| 端数の「半」 | **今回は `tailAreaOf()` を触らない**。結果として「半」は置き場未定の欄に出る（§7(f)） |
| 退避から戻す手段 | **既存の「倉庫に戻す」ボタンだけ**。新しい手段は足さない |

## 3. あふれ荷物を退避へ入れる

### 3-1. 入れる場所

`run()`（`files/index.html:2357`）の中。現状の流れは次のとおり。

```js
const keepStash=stashCounts(...);          // 保存配置から前回の退避を引き当て
lots.forEach(l=>{ ... l.pallets-=l.stashed; });   // 倉庫へ置く分だけにする
lastSp=place(lots,allowMix,activeShift().blocked); // lot.rem にあふれが出る
lots.forEach(l=>{ if(l.stashed){ putToStash(lastSp,l.id,l.stashed); l.pallets+=l.stashed; } });
```

この末尾に1手を足す。

```js
lots.forEach(l=>{ if(l.rem>0) putToStash(lastSp,l.id,l.rem); });
```

前回の退避を積み戻した**あと**に置く。逆にすると、前回分が入る前に容量を食って
前回の退避が押し出される。

### 3-2. `lot.rem` は消さない

`lot.rem` は「その日あふれた枚数」の記録として残す。入力タブの
`合計 N個 → NP ／ 配置済 NP ／ あふれ NP`（`files/index.html:2343`）と
警告文（同 2322）がこの値を読むため。

**帰結として、翌回の `run()` では「あふれ NP」の表示が 0 になる。**
退避に入った分は `stashCounts()` に拾われて `l.pallets` から引かれ、
`place()` に渡らないので `rem` が立たないためである。
荷物は退避に居て紙にも載るので実害はないが、
「あふれ表示は自動配置を押した直後の日だけ出る」ことになる。この挙動は仕様とする。

### 3-3. 退避の実効容量は 56P（定数から計算しないこと）

数え方を誤りやすいので、根拠を残す。

- `DEFAULT_SPACES` の退避は **`cols:[{h:7},{h:7},{h:7}]`**（`files/index.html:887`）。
  `STASH_COL_H`(4) ではない
- `putToStash()`（同 3300）は空きのある列から詰め、足りなければ
  `h:STASH_COL_H`(4) の列を `STASH_MAX_COLS`(14) まで足す。
  ここまでなら **21 + 44 = 65P** 入る
- しかし `renderResult()` が描画の前に呼ぶ `ensureStashRoom()`（同 3364）は
  `repackStash()`（同 3340）を通す。これは **すべての列を `h:4` で積み直す**。
  **列数の上限を見ない**ので、65P を入れた日は 17 列に再梱包され、
  `STASH_MAX_COLS` を超えて隅の小さな盤の描画が崩れる
- したがって**実効の上限は `STASH_MAX_COLS × STASH_COL_H` = 56P**

投入の前に「いまの退避の合計 + 投入量 ≤ 56P」を確かめ、次のように扱う。

- 入る分だけ `putToStash()` で入れる
- 入らなかった分は `lot.rem` に残したまま、専用の警告を出す

```
⚠ 退避スペースに入りきらない荷物があります：部品A(001) NP。配置図にも出ません。
```

56P を超える日は現実にはまず無いが、**黙って荷物が消える経路は残さない**。

`repackStash()` が列数の上限を見ないこと自体は既存の作りである。
自動投入を 56P で頭打ちにすれば今回の経路では表面化しないので、
`repackStash()` には手を入れない（手で 56P 超を積む経路は既存のまま。§11 参照）。

## 4. 退避の欄を紙に出す

### 4-1. 既存の階段に流す

`sheetPlacement()`（`files/index.html:4494`）はすでに次の階段を持っている。

```
上段の欄 → 溢れたら下段の空きへ回す（moved） → それでも溢れたら追記欄2項目（overflow）
         → 入りきらない分は警告（unlisted）
```

決めた仕様はこの階段そのものなので、**退避の欄を上段の欄の末尾に連結する**。

```js
const top=sheetSlots("top").concat(stashSlots());
```

これで以下が既存のロジックのまま成立する。

- エリアの欄が先、退避の欄が後 → 「欄数超過を先に載せる」
- 上段の空き → 下段の空き → 追記欄 → 警告 → 「上段 → 下段 → 追記欄」
- 連結後の件数を `sheetLayout()`（同 923）が見る → あふれた日は wide になる
- 下段へ回った退避の欄には `fromTop:true` が付き、`renderSheet()`（同 4676）が
  引き出し線の id を落とす → **退避の欄からは線が引かれない**

最後の点は偶然ではなく正しい。退避は盤のグリッドに対応するマスを持たないので、
線を引く先がそもそも無い。

### 4-2. `stashSlots()`

`sheetEntries()`（`files/index.html:4347`）と同じ形の欄を、退避エリアの `fills` から作る。

```js
function stashSlots(){
  // 退避エリアの fills を id ごとに合算し、
  // {lot, pallets, half, areas:["退避"], note:"※置き場未定", stash:true} を返す
}
```

- `note` は `※置き場未定` で固定する。エリア名（「退避」）は現場にとって場所情報ではない
- `stash:true` は 4-3・4-5 の分岐に使う目印
- 通常の欄と同じく `mergeEntries()`（同 4388）を通す。同じ品名・SNP・種別の荷物を
  1つの欄にまとめ、欄を節約する。`baseArea` には下段の基準エリアを渡さない
  （退避の欄はメインに乗っていないので、まとめてよい）。
  入力タブの「同じ品名をまとめる」が切られている日は `sheetSlots()` と同じく
  `mergeLots`（同 1623）に従い、まとめずに1件ずつ欄を作る
- 「半」は `sheetEntries()` と同じ式で持たせる。実際にどの欄へ付くかは §7(f) を参照

### 4-3. 注釈を作り直す箇所の手当て

`sheetPlacement()` は下段へ回す欄の注釈を作り直す（`files/index.html:4501`）。

```js
.map(e=>({...e, fromTop:true, note:slotAreaNote(e.areas)}));
```

`slotAreaNote()`（同 4427）はエリア名を並べるだけなので、
退避の欄がここを通ると注釈が `※退避` に化ける。`stash` の欄は元の注釈を保つ。

```js
.map(e=>({...e, fromTop:true, note: e.stash ? e.note : slotAreaNote(e.areas)}));
```

### 4-4. 追記欄に入る順（実装の手当てが要る）

決定は「欄数超過を先に載せ、余った枠にあふれを載せる」だが、
いまの `sheetPlacement()`（`files/index.html:4507`）の並びはそうならない。

```js
const overflowed=arrangeOverflowSlots(omittedTop.concat(arranged.dropped));
```

`omittedTop` は上段から溢れて下段にも回れなかった欄で、**退避の欄はこの末尾に居る**。
`arranged.dropped`（下段の欄数超過）はその後ろに連結されるので、
このままでは **退避の欄が下段の欄数超過を押し出す**。

追記欄へ渡す前に、`stash` の欄を末尾へ寄せる。

```js
const rest=omittedTop.concat(arranged.dropped);
const ordered=rest.filter(e=>!e.stash).concat(rest.filter(e=>e.stash));
const overflowed=arrangeOverflowSlots(ordered);
```

エリアの欄どうしの相対順（上段の溢れ → 下段の溢れ）は変えない。

### 4-5. 追記欄にも入りきらない日 —— まとめ欄

追記欄は2項目しかない（`arrangeOverflowSlots`、`files/index.html:4480`）。
あふれが起きる日は下段の欄も埋まっている日なので、
現実の着地点は追記欄の2枠になりやすい。
**3件以上あふれた日に紙から消えるのでは、§1 の要件を満たさない。**

`arrangeOverflowSlots()` を次のように変える。

- 項目が2件以内 … 従来どおり1項目ずつ記載する
- 項目が3件以上 … 1枠目は従来どおり。**2枠目を「まとめ欄」にし、
  残り全部の品名・ロット・パレット数を縦積みで記載する**

縦積みは既存の `.fitcol`（`files/index.html:483`、`overflowTable()` 同 4742）と同じ仕組みを使う。
`overflowTable()` の各セルが、まとめ欄のときは1件ではなく複数件を縦に並べる。
注記は `※置き場未定` と `※エリア名` が混ざりうるので、各件の行に付ける。

`unlisted`（紙に出ない項目）は**原則として空になる**。
まとめ欄に何件でも積めるためで、警告は「文字が小さくなりすぎた」ことを知らせる側に変わる。

**紙の高さに注意する。** 追記欄は wide 様式の右端2列で、外側のセルが
グリッドの行をまたぐ（`files/index.html:495` のコメント、`gridRows(pad, overflow)` 同 4850）。
縦積みが増えて内側の表がグリッドより高くなると、紙が1ページに収まらなくなる。
件数の多い日を作って印刷プレビューで実測する（§10）。

**2026-09-17 追記（Task 5b、計画外）**: 上の懸念は実際に起きた。
まとめ欄が3件以上の日、ブラウザでの印刷プレビューで1ページに収まらないことが判明し、
§10 検証の実測でこのゲートに当たった。まとめ欄は件数の上限を持たない設計
（`unlisted` が空になる）にしていたため、件数が伸びるほど縦積みの高さがそのまま増える。

ユーザー判断で、まとめ欄の `td` だけ文字を詰める対応を追加した。

- `overflowTable()` がまとめ欄のセルにだけ `roll` クラスを付ける（`files/index.html` 内）
- `.sheet .overflow-table td.roll{padding:0}`
- `.sheet .overflow-table td.roll .fit{font-size:55%;line-height:1.05}`（`files/index.html:507-508`）

実測で**まとめ欄5件までは1ページに収まる**（5件で用紙の99%）。
6件以上は縮小しても収まらず、その場合は既存の「表が縦に伸びて印刷が
1ページに収まりません」警告（§10-3）が歯止めとして出る。**件数の上限そのものは
設けていない**（警告を出すだけで、6件以上の入力自体は止めない）。

**2026-09-17 追記（最終レビューの修正）: 縦積みは値が空でも1行を残す。**
まとめ欄は品名・ロット・P数・注記が別々の `td` に縦積みされ、
**行の位置だけで件が対応している**。値が空の件を落とすとその列だけ行が繰り上がり、
品名と別の件のロット番号が横に並ぶ。ロット番号や品名が空の荷物は実在する
（`mergeEntries()` の `solo` 規則がそのために在る）。
よって空欄は `—` を置いて1行を残す。**重複と空欄を畳むのは注記の列だけ**
（`※置き場未定` が件数ぶん並ぶのを避けるため）。

**まとめ欄になった側は読みにくい。** 2つの追記欄は見た目が等価ではなくなった。
1枠目は通常の文字サイズ、2枠目のまとめ欄は 55%（`td.roll`）で描かれる。
§4-4 で決めた「欄数超過が先・退避が後」は、
結果としてどちらが読みやすい枠に載るかも決めていることになる。
決定を変えるものではなく、そういう副作用があるという記録である。

### 4-6. 追記欄に2種類が混ざることの読み分け

追記欄には「欄数が足りなくて回された欄」と「置き場未定の荷物」が混ざりうる。
現場が紙の上で区別できるのは**注釈だけ**である。

- 欄数超過で回された欄 … 注釈はエリア名（`※メイン`、`※PC横` など）
- 置き場未定の荷物 … 注釈は `※置き場未定`

注釈は `overflowTable()`（`files/index.html:4733`）が必ず描くので、
どちらであるかは常に読める。追記欄そのものに見出しは足さない
（右端2列しかなく、見出しを入れると記載できる項目が減るため）。

## 5. 配置編集タブを離れるときの確認

### 5-1. `switchTab()` には入れない

`switchTab()`（`files/index.html:2549`）の先頭に `confirm()` を置くと、印刷が壊れる。

- `printSheet()`（同 4192）は `switchTab('sheet')` → `window.print()` の順に呼ぶ。
  ここでキャンセルするとタブが切り替わらないまま印刷が走り、
  印刷CSSが `#tab-edit` を隠すので**白紙が出る**
- `beforeprint` のハンドラ（同 4202）は Ctrl/Cmd+P 経由で `switchTab('sheet')` を呼び、
  `#sheetView` を埋めてから紙に出す。**ハンドラ内の `confirm()` はブラウザによって抑止される**ので、
  ここでも白紙になりうる

### 5-2. タブボタンの `onclick` に置く

人がタブを押したときだけ確認する。印刷経路は `switchTab()` を直接呼ぶので影響を受けない。

```html
<button class="tab" id="tabbtn-input" onclick="leaveEdit('input')">入力</button>
```

`leaveEdit(name)` は次のことをする。

```
いま配置編集タブに居る かつ name!=="edit" かつ stashTotal(lastSp) > 0
  → confirm。キャンセルなら何もしない
それ以外 → switchTab(name)
```

文言:

```
退避スペースに NP 残っています。
置き場未定として配置図に載ります。このまま移動しますか？
```

- 「配置編集タブに居るか」は `#tab-edit` の表示状態から判定する
- 止めたときはタブが変わらないので `clearSel()` も走らない
- `stashTotal()`（同 3294）は `lastSp` が無い日も 0 を返すので、結果が無い日は素通りする

## 6. 文言と用語の改名

### 6-1. 書き分けの規則（要件メモ §用語 の決定）

- **あふれ** … 倉庫に置き場所が無い荷物のこと。**荷物の話にだけ使う**
- **追記欄** … 配置図の欄が足りない日に使う欄のこと（旧「あふれブロック」）

改名するのは画面に出る文言とコード内のコメントで、保存形式の属性値 `over` は変えない。

### 6-2. 「あふれブロック」→「追記欄」

実測した11箇所。

| 行 | 種別 | 内容 |
|---|---|---|
| 495 | コメント | `.sheet` の CSS 説明 |
| 774 | 画面 | 設定タブの掲載先の説明文（6-3 も参照） |
| 843 | コメント | `DEFAULT_SPACES` の `sheet` 属性の説明 |
| 911 | コメント | `SHEET_LAYOUTS` の wide の説明（「後日あふれブロックが入る用地」→ 実装済みに直す） |
| 2134 | コメント | `areaCandidates()` の説明 |
| 2291 | 画面 | `⚠ 配置図のあふれブロックにも記載できない項目があります` |
| 2294 | コメント | `over` は追記欄とは別物である旨の注意書き |
| 2300 | 画面 | `⚠ 掲載先を「あふれブロック」にした次のエリアには…` |
| 4478 | コメント | `arrangeOverflowSlots()` の説明 |
| 4732 | コメント | `overflowTable()` の説明 |
| 4849 | コメント | グリッド右2列の使い道の説明 |

関数名（`arrangeOverflowSlots` / `overflowTable`）と CSS クラス（`.overflow-table` など）は
変えない。英語の `overflow` は「欄からあふれた項目」の意味で一貫しており、
日本語の書き分けとは別の層にあるため。

「あふれ受け（出庫口横・5棟壁際）」（`files/index.html:615`, `880`）は
荷物の側の語なので**そのまま残す**。

### 6-3. 掲載先 `over` のラベル（要件メモの決定を上書きする）

要件メモ §用語 は「掲載先の属性値 `over` のラベルも『追記欄』に合わせる」としていた。
これを**取り消す**。

`over` の実態は「配置の対象から外し（`areaCandidates()`）、配置図の表にも出さない」であり、
追記欄とは別物である（`files/index.html:2294` のコメントが現にその注意書きになっている）。
`over` を「追記欄」と呼ぶと、実装済みの追記欄と混同する。

ラベルを実態に合わせて **`over＝掲載しない`** に変える。保存形式の値 `over` は変えない。
あわせて警告文も実態の言い方に直す。

- 2300 `⚠ 掲載先を「掲載しない」にした次のエリアには、新しく荷物を置きません：…`
- 4032 のバリデーションのメッセージは `top / bottom / over` のままでよい（値の話のため）

### 6-4. 退避に関する既存の文言

### 6-5. 「✅ すべてのパレットを配置しました」の条件


## 7. 技術制約

**(a) 退避の欄には引き出し線が引けない。**
線はグリッド（下段の基準エリア）のマスへ引くもので、退避にはそのマスが無い。
§4-1 のとおり `fromTop:true` が付くことで自然に落ちる。
上段に残った場合も上段には元から線が無いので問題にならない。

**(b) 紙の1ページ判定。**
あふれた日は様式が wide になる（`SHEET_LAYOUTS.wide`、`files/index.html:918`）。
wide は既存の様式で、欄数が増えても表の総幅 672px と行数は変わらない。
新しい高さの要因は §4-5 のまとめ欄だけなので、そこを実測する。

**(c) 保存形式は変えない。**
退避の中身はすでに `sp` の一部として保存されている。
`SPACES_SAVE_VERSION` は据え置き、既存端末の保存データはそのまま読める。

**(d) `sheet:"none"` の前提が変わる。**
退避スペースの設計書（2026-09-03）§2-4「紙に出ないことを知らせる」と
§2-5「設定テキストから外す」はこの前提の上に立っている。

- §2-4 は**前提が変わる**。警告の趣旨を「出ないから戻せ」から
  「置き場未定として出る」に改める（§6-4）。2026-09-03 の設計書にも追記する
- §2-5 は**変わらない**。`applyConfig()` は区分を `near` / `far` しか受け付けないので、
  退避スペースを設定テキストに出せないことに変わりはない。`withStash()` の仕組みもそのまま

`sheet:"none"` という属性値自体は残す。`sheetAreas()`（`files/index.html:906`）が
拾わないままにし、退避の欄は `stashSlots()` という別経路で作る。
`sheet:"top"` に変えて既存経路に乗せる案もあるが、そうすると
`sheetEntries()` がエリア名を注釈に出し、`mergeEntries()` の `baseArea` 判定にも
退避が混ざるため、分岐がかえって増える。

**(e) 自動配置をやり直しても倉庫へは戻らない。**
退避の中身は `stashCounts()` → `l.pallets` から減算 → `place()` の順で
配置の対象から外れる。倉庫に空きができた日でも自動では戻らない。
これは決定どおりの挙動で、戻すのは「倉庫に戻す」ボタン
（`returnSelToWarehouse`、`files/index.html:3765`）か手動移動による。

ボタンは「選んだマス数がまとめて入る列」を探し、無ければ
`Nマスがまとめて入る列が倉庫にありません。少しずつ選ぶか、列を選んでドラッグしてください。`
と案内する。少しずつ選べば戻せるので、あふれ由来の荷物にもそのまま使える。
新しい手段は足さない（決定どおり）。

**(f) 端数の「半」は置き場未定の欄に出る。**
`tailAreaOf(id)`（`files/index.html:4337`）は「ロットの末尾のマス」ではなく、
**`lastSp` の配列順で最後にそのロットを含むスペース名**を返す。
`DEFAULT_SPACES` は退避が最後（同 886）なので、
**退避に1枚でもあるロットは `tailAreaOf` が必ず「退避」を返す**。

- 現状（変更前）… 退避には紙の欄が無いので `e.areas.includes(tail)` が常に false になり、
  **そのロットの「半」が紙から消える**（既存のバグ）
- 変更後 … 倉庫側の欄ではなく「置き場未定」の欄に「半」が付く

`tailAreaOf()` は**今回は触らない**（決定）。既存のバグは変更後に自然に解消し、
「半」が出る欄が倉庫側から置き場未定側へ移る。紙の上では
「このロットには端数がある」ことが読めるので、実害は小さいと判断した。
倉庫側の欄に付け直すのは別件とする。

## 8. エッジケース

- **あふれが 56P を超える日**: §3-3 のとおり、入る分だけ入れて残りは警告に出す
- **ロットが入力から消えた日**: 既存どおり次の `run()` で引き当てに失敗し、その分の退避は消える
  （退避スペースの設計書 §7）
- **退避に入れた荷物を手で倉庫へ戻した日**: 次の `run()` で `stashCounts()` に拾われず、
  通常の配置対象に戻る。あふれなければ紙の欄も通常のエリア欄になる
- **1ロットがメインと退避に分かれた日**: 下段に「メインの欄（引き出し線あり）」と
  「退避から回ってきた欄（`fromTop`・線なし）」が並ぶ。`drawLeaders()` は `fromTop` 側に
  `null` を渡すので線は1本だけだが、`mergeEntries()` は
  「欄とロットの 1:1 対応が引き出し線の前提」だと明記している（同 4388 付近）。
  検証項目に入れる
- **退避が空の日**: `stashSlots()` が空配列を返し、`concat` は何もしない。
  様式の判定も従来どおりになり、**紙の形は今までと1ミリも変わらない**
- **タブ移動の確認をキャンセルした日**: タブは変わらず、選択も帯も維持される
- **品名もロット番号も空のロットが退避にある日**: `mergeEntries()` がまとめずに
  1件ずつ欄を作る（既存の規則のまま）。欄を食うが、紙に出ることを優先する
- **印刷（Ctrl/Cmd+P）**: §5-1 のとおり確認を挟まない。退避が非空でも紙は出る
