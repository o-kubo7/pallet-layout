## 1. 背景と目的

倉庫にも「あふれ受け（出庫口横・5棟壁際）」にも入りきらなかった荷物は、
いま `lot.rem` に残るだけで、盤にも配置図（紙）にも現れない。
画面に出るのは入力タブの合計（`files/index.html:2343`）と警告文（同 2322）だけである。

現場の実態を確認したところ、あふれた荷物は次のように扱われている。

- 通路や空きに無理やり置く。どの荷物がいつ来るか分からないため、
  先に来た荷物を入庫するとそのスペースが空き、そこへ置くこともある
- **紙の配置図には欄外に押し込んででも記載し、存在を必ずチームに知らせる**

つまりあふれ荷物の要件は「置き場所を決めること」ではなく、
**「置き場所が決まらないまま、紙に必ず載せること」** である。

退避スペース（`zone:"stash"`）はすでに「倉庫に実在しない、位置に意味を持たない置き場」
として実装されている（`docs/superpowers/specs/2026-09-03-stash-space-and-sweep-select-design.md`）。
あふれ荷物の性質と一致するので、これを受け皿として使う。

この変更で次の2つを入れる。

- 自動配置で倉庫に入りきらなかった分を、退避スペースへ自動で入れる
- 退避スペースの中身を、配置図（紙）に「置き場未定」として載せる

## 2. ブレストで決めたこと（2026-09-17）

| 論点 | 決定 |
|---|---|
| 紙の出し先 | 追記欄を共用する。**欄数超過を先に載せ**、余った枠にあふれを載せる |
| 空き欄を埋める順 | **上段 → 下段 → 追記欄**。それでも入らなければ警告 |
| 退避の中身の区別 | **区別しない**。由来（自分で逃がした／あふれた）を問わず、退避に残っている分は全部紙に出す |
| 自動配置のやり直し | **区別せず全部残す**（現状の仕様のまま）。倉庫に空きができても自動では戻さず、手で戻す |
| 注釈の文言 | **「置き場未定」** |
| 紙の様式 | あふれの欄も欄数の判定に**数える**。あふれのために normal → wide になってよい |
| タブ移動 | 退避に荷物が残ったまま配置編集タブを離れるとき、**確認ダイアログで止めて聞く** |
| 項目単位の枠線 | **今回は入れない**（別件としてメモに残す） |

## 3. あふれ荷物を退避へ入れる

### 3-1. 入れる場所

`run()`（`files/index.html:2357`）の中。現状の流れは次のとおり。

```js
const keepStash=stashCounts(...);          // 保存配置から前回の退避を引き当て
lots.forEach(l=>{ ... l.pallets-=l.stashed; });   // 倉庫へ置く分だけにする
lastSp=place(lots,allowMix,activeShift().blocked); // lot.rem にあふれが出る
lots.forEach(l=>{ if(l.stashed){ putToStash(lastSp,l.id,l.stashed); l.pallets+=l.stashed; } });
```

この末尾に1手を足す。

```js
lots.forEach(l=>{ if(l.rem>0) putToStash(lastSp,l.id,l.rem); });
```

前回の退避を積み戻した**あと**に置く。逆にすると、前回分が入る前に容量を食って
前回の退避が押し出される。

### 3-2. `lot.rem` は消さない

`lot.rem` は「その日あふれた枚数」の記録として残す。入力タブの
`合計 N個 → NP ／ 配置済 NP ／ あふれ NP`（`files/index.html:2343`）と
警告文（同 2322）がこの値を読むため。

**帰結として、翌回の `run()` では「あふれ NP」の表示が 0 になる。**
退避に入った分は `stashCounts()` に拾われて `l.pallets` から引かれ、
`place()` に渡らないので `rem` が立たないためである。
荷物は退避に居て紙にも載るので実害はないが、
「あふれ表示は自動配置を押した直後の日だけ出る」ことになる。この挙動は仕様とする。

### 3-3. 退避の容量と、入りきらない分

退避の上限は `STASH_MAX_COLS`(14) × `STASH_COL_H`(4) = **56P**
（`files/index.html:3279-3281`）。`putToStash()`（同 3300）は
列数が上限に達すると **黙って `return` する**。いまは手で運び込む経路しか無く、
`validateMove()` が先に弾くので表面化していないが、自動投入では表面化する。

投入の前に空き容量を数え、入りきらない分は次のように扱う。

- 入る分だけ `putToStash()` で入れる
- 入らなかった分は `lot.rem` に残したまま、専用の警告を出す

```
⚠ 退避スペースに入りきらない荷物があります：部品A(001) NP。配置図にも出ません。
```

56P を超える日は現実にはまず無いが、**黙って荷物が消える経路は残さない**。

## 4. 退避の欄を紙に出す

### 4-1. 既存の階段に流す

`sheetPlacement()`（`files/index.html:4494`）はすでに次の階段を持っている。

```
上段の欄 → 溢れたら下段の空きへ回す（moved） → それでも溢れたら追記欄2項目（overflow）
         → 入りきらない分は警告（unlisted）
```

決めた仕様はこの階段そのものなので、**退避の欄を上段の欄の末尾に連結するだけ**でよい。

```js
const top=sheetSlots("top").concat(stashSlots());
```

これで以下が既存のロジックのまま成立する。

- エリアの欄が先、退避の欄が後 → 「欄数超過を先に載せる」
- 上段の空き → 下段の空き → 追記欄 → 警告 → 「上段 → 下段 → 追記欄」
- 連結後の件数を `sheetLayout()`（同 923）が見る → あふれた日は wide になる
- 下段へ回った退避の欄には `fromTop:true` が付き、`renderSheet()`（同 4676）が
  引き出し線の id を落とす → **退避の欄からは線が引かれない**

最後の点は偶然ではなく正しい。退避は盤のグリッドに対応するマスを持たないので、
線を引く先がそもそも無い。

### 4-2. `stashSlots()`

`sheetEntries()`（`files/index.html:4347`）と同じ形の欄を、退避エリアの `fills` から作る。

```js
function stashSlots(){
  // 退避エリアの fills を id ごとに合算し、
  // {lot, pallets, half, areas:["退避"], note:"※置き場未定", stash:true} を返す
}
```

- `note` は `※置き場未定` で固定する。エリア名（「退避」）は現場にとって場所情報ではない
- `stash:true` は 4-3 の分岐に使う目印
- 通常の欄と同じく `mergeEntries()`（同 4388）を通す。同じ品名・SNP・種別の荷物を
  1つの欄にまとめ、欄を節約する。`baseArea` には下段の基準エリアを渡さない
  （退避の欄はメインに乗っていないので、まとめてよい）。
  入力タブの「同じ品名をまとめる」が切られている日は `sheetSlots()` と同じく `mergeLots`
  （`files/index.html:1623`）に従い、まとめずに1件ずつ欄を作る
- 「半」の扱いは `sheetEntries()` と同じく `tailAreaOf()` で決める。
  ロットの末尾のマスが退避にある日だけ、退避の欄に「半」が付く

### 4-3. 注釈を作り直す箇所の手当て

`sheetPlacement()` は下段へ回す欄の注釈を作り直す（`files/index.html:4501`）。

```js
.map(e=>({...e, fromTop:true, note:slotAreaNote(e.areas)}));
```

`slotAreaNote()`（同 4427）はエリア名を並べるだけなので、
退避の欄がここを通ると注釈が `※退避` に化ける。`stash` の欄は元の注釈を保つ。

```js
.map(e=>({...e, fromTop:true, note: e.stash ? e.note : slotAreaNote(e.areas)}));
```

### 4-4. 追記欄に2種類が混ざることの読み分け

追記欄には「欄数が足りなくて回された欄」と「置き場未定の荷物」が混ざりうる。
現場が紙の上で区別できるのは**注釈だけ**である。

- 欄数超過で回された欄 … 注釈はエリア名（`※メイン`、`※PC横` など）
- 置き場未定の荷物 … 注釈は `※置き場未定`

注釈は `overflowTable()`（`files/index.html:4733`）が4行目のセルに必ず描くので、
どちらであるかは常に読める。追記欄そのものに見出しは足さない
（右端2列しかなく、見出しを入れると記載できる項目が減るため）。

## 6. 文言と用語の改名

### 6-1. 書き分けの規則（要件メモ §用語 の決定）

- **あふれ** … 倉庫に置き場所が無い荷物のこと。**荷物の話にだけ使う**
- **追記欄** … 配置図の欄が足りない日に使う欄のこと（旧「あふれブロック」）

改名するのは画面に出る文言とコード内のコメントで、保存形式の属性値 `over` は変えない。

### 6-2. 「あふれブロック」→「追記欄」

|---|---|---|

| 774 | 画面 | 設定タブの掲載先の説明文（6-3 も参照） |
| 843 | コメント | `DEFAULT_SPACES` の `sheet` 属性の説明 |
| 911 | コメント | `SHEET_LAYOUTS` の wide の説明（「後日あふれブロックが入る用地」→ 実装済みに直す） |
| 2134 | コメント | `areaCandidates()` の説明 |

| 2300 | 画面 | `⚠ 掲載先を「あふれブロック」にした次のエリアには…` |

### 6-3. 掲載先 `over` のラベル

いま設定タブは `over＝あふれブロック` と説明している（`files/index.html:774`）が、
`over` の実態は「配置の対象から外し（`areaCandidates()`）、配置図の表にも出さない」であり、
追記欄とは別物である（2294 のコメントが現にその注意書きになっている）。

ラベルを実態に合わせて **`over＝掲載しない`** に変える。保存形式の値 `over` は変えない。
あわせて次の2つの警告文も実態の言い方に直す。

- 2300 `⚠ 掲載先を「掲載しない」にした次のエリアには、新しく荷物を置きません：…`
- 4032 のバリデーションのメッセージは `top / bottom / over` のままでよい（値の話のため）

## 7. 技術制約

**(a) 退避の欄には引き出し線が引けない。**
線はグリッド（下段の基準エリア）のマスへ引くもので、退避にはそのマスが無い。
4-1 のとおり `fromTop:true` が付くことで自然に落ちるが、
`stashSlots()` が上段に残った場合も上段には元から線が無いので問題にならない。

**(b) 紙の1ページ判定。**
あふれた日は様式が wide になる（`SHEET_LAYOUTS.wide`、`files/index.html:918`）。
wide は既存の様式で、欄数が増えても**表の総幅 672px と行数は変わらない**ので、
`PRINT_H_LIMIT` の判定に新しい超過要因は生まれない。
ただし追記欄が埋まる日の高さは既存どおり実測で確認する。

**(c) 保存形式は変えない。**
退避の中身はすでに `sp` の一部として保存されている。
`SPACES_SAVE_VERSION` は据え置き、既存端末の保存データはそのまま読める。

**(d) `sheet:"none"` の前提が変わる。**
退避スペースの設計書（2026-09-03）§2-4「紙に出ないことを知らせる」と
§2-5「設定テキストから外す」はこの前提の上に立っている。

- §2-4 は**前提が変わる**。警告の趣旨を「出ないから戻せ」から
  「置き場未定として出る」に改める（6-4）。§2-4 に追記する
- §2-5 は**変わらない**。`applyConfig()` は区分を `near` / `far` しか受け付けないので、
  退避スペースを設定テキストに出せないことに変わりはない。`withStash()` の仕組みもそのまま

`sheet:"none"` という属性値自体は残す。`sheetAreas()`（`files/index.html:906`）が
拾わないままにし、退避の欄は `stashSlots()` という別経路で作る。
`sheet:"top"` に変えて既存経路に乗せる案もあるが、そうすると
`sheetEntries()` がエリア名を注釈に出し、`mergeEntries()` の `baseArea` 判定にも
退避が混ざるため、分岐がかえって増える。

**(e) 自動配置をやり直しても倉庫へは戻らない。**
退避の中身は `stashCounts()` → `l.pallets` から減算 → `place()` の順で
配置の対象から外れる。倉庫に空きができた日でも自動では戻らない。
これは決定どおりの挙動で、戻すのは「倉庫に戻す」ボタン
（`returnSelToWarehouse`、`files/index.html:3765`）か手動移動による。

## 8. エッジケース

- **あふれが 56P を超える日**: 3-3 のとおり、入る分だけ入れて残りは警告に出す
- **ロットが入力から消えた日**: 既存どおり次の `run()` で引き当てに失敗し、その分の退避は消える
  （退避スペースの設計書 §7）
- **退避に入れた荷物を手で倉庫へ戻した日**: 次の `run()` で `stashCounts()` に拾われず、
  通常の配置対象に戻る。あふれなければ紙の欄も通常のエリア欄になる
- **退避の欄が追記欄にも入らない日**: `unlisted` の警告
  （`⚠ 配置図の追記欄にも記載できない項目があります`）に合流する。既存の経路のまま
- **退避が空の日**: `stashSlots()` が空配列を返し、`concat` は何もしない。
  様式の判定も従来どおりになり、**紙の形は今までと1ミリも変わらない**
- **タブ移動の確認をキャンセルした日**: タブは変わらず、選択も帯も維持される
- **品名もロット番号も空のロットが退避にある日**: `mergeEntries()` がまとめずに
  1件ずつ欄を作る（既存の規則のまま）。欄を食うが、紙に出ることを優先する

- 項目単位の枠線（今回は範囲外）

## 10. 検証

`file:///.../files/index.html` を直接開き、ヘッドレスブラウザ（Playwright）で実行する。
`file://` では Service Worker が登録されないので、キャッシュの回り道は起きない。

| 観点 | 内容 |
|---|---|
| 自動投入 | 倉庫を超える量を入力 → あふれ分が退避スペースに現れる。合計が合う |
| 紙（上段の空き） | 上段に空きがある日、退避の欄が上段の末尾に出る。注釈が `※置き場未定` |
| 紙（下段へ回る） | 上段が埋まった日、退避の欄が下段の末尾に出る。**引き出し線が引かれない** |
| 紙（追記欄） | 上下段とも埋まった日、退避の欄が追記欄に出る。欄数超過の項目が先に入る |
| 紙（警告） | 追記欄にも入らない日、`unlisted` の警告に出る |
| 様式 | あふれの欄で normal → wide に切り替わる。退避が空の日は従来どおりの様式 |
| 容量 | 56P を超える量を入力 → 入る分だけ入り、残りが警告に出る。荷物が黙って消えない |
| タブ移動 | 退避に残したまま入力／配置図／設定タブへ移ろうとすると確認が出る。キャンセルで留まる |
| 既存機能 | 退避へ手で逃がす・戻す／自動配置し直しで退避が残る／設定テキストに退避が出ない |
| 印刷 | あふれた日の紙が1ページに収まる（印刷プレビューで実測） |
| 文言 | 改名した11箇所に「あふれブロック」が残っていない。`over` のラベルが「掲載しない」 |

実機（Pixel 9a / Android Chrome）で、あふれた日の紙が読めることを確認する。

## 11. 範囲外

- 項目単位の枠線（紙の見た目の改善。要件メモへ別件として残す）
- 退避の中身を由来（あふれ／手動）で区別すること
- 倉庫に空きができたときに退避から自動で戻すこと
- 追記欄の項目数を2から増やすこと
- 掲載先 `over` の機能そのものの実装（ラベルの手直しだけを行う）
