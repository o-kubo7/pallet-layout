# 大きな配置図が出せないことを表の中で知らせる 設計書

- 作成: 2026-08-31
- 対象: `files/index.html`、`files/sw.js`
- 由来: `.superpowers/sdd/progress.md` の積み残し I-3（Important）

---

## 1. 問題

配置図の表の大きなグリッドは `gridRows()`（`files/index.html:2811`）が描く。
この関数は下段の先頭エリア（`sheetAreas("bottom")[0]`）の列を、紙の様式である
14 列の並び（通路｜1-3｜段番号｜4-6｜段番号｜7-9｜通路｜段番号）に流し込む。

```js
const order=[{c:0,aisle:true},{c:1},{c:2},{c:3},{lab:true,l:3,r:4},{c:4},{c:5},{c:6},{lab:true,l:6,r:7},
             {c:7},{c:8},{c:9},{c:10,aisle:true},{lab:true}];
if(order.some(o=>!o.lab && !sp.cols[o.c])) return {html:"", anchors:[]};
```

`order` は `sp.cols[0]` から `sp.cols[10]` までの 11 本を要求する。揃わないと
`sp.cols[o.c]` が `undefined` になって描画全体が落ちるため、`{html:"", anchors:[]}` を
返して**黙って大グリッドを描かない**。`!sp`（下段の先頭が見つからない）のときも同じ。

上段・下段の欄は正常に描かれるので、**グリッドと引き出し線だけが無い紙**が刷れる。
警告は一切出ず、`#messages` は「✅ すべてのパレットを配置しました。」のまま。

## 2. 発生経路（ブラウザで実測）

11 列を持つのは `メイン` だけ。次の 2 経路が現実的に踏まれる。

### 2-1. 行を並べ替えたとき（掲載先を触らない経路）

設定タブのヒント（`files/index.html:527`）は
「**行の順番には意味があります。**上の行から順に自動配置で試します」と案内している。
配置の優先順位を変えるつもりで `PC横` の行を上へ動かすと、下段の先頭が `PC横`（2 列）になり
グリッドが落ちる。

同じヒントの後半に「大きなグリッドは下段の基準エリアを描きます」とあるが、
優先順位を変える目的で操作している人がこの 2 つを結びつけるのは難しい。
**掲載先を触っている意識がないまま紙が壊れる**点で、これが最も踏みやすい。

実測: 並べ替えのみで `下段先頭=PC横 / tr.grow=0 / leaders=0`、警告なし。

### 2-2. メインの列数を 11 本より減らしたとき

通路を 1 本潰すなどして列を 11 → 10 にすると、下段の先頭はメインのままだが
`sp.cols[10]` が `undefined` になりグリッドが落ちる。

実測: `下段先頭=メイン / tr.grow=0`、警告なし。

現場の洗い出しを配置マス設定に反映した直後であり、今後レイアウトが変われば
再び列数を触ることになるため、将来また踏む経路である。

### 2-3. 起きないと確認した経路

- **改名**: グリッドは消えない。`gridRows()` は固定名ではなく「下段の先頭エリア」を
  見るので、改名しても先頭であり続ければ描ける（実測 `tr.grow=7`）。
  progress.md の「メインの改名でしか起きなかった」は `SHEET_BOTTOM` が
  ハードコード配列だった頃の記述で、現在は当てはまらない。
- **メインを `over` / `top` にする**: 機構としては起きるが、
  「現場でメインエリアを使用しないことはない」とユーザーが明言したため、
  実運用では発生しないものとして扱う。ただし機構上は 2-1 と同じ分岐に落ちるので、
  本設計の案内はこの経路もそのままカバーする。

## 3. あわせて直す件（12 列以上の無言の欠落）

同じ 11 列ハードコードに由来する別症状。メインの列を 12 本以上に増やすと
グリッド自体は描けるが、`order` が `sp.cols[11]` 以降を参照しないため
**12 列目以降のパレットが黙って紙から消える**（実測: `tr.grow=7` でグリッドは出る）。

検知も案内も I-3 と同じ場所に書けるため、今回の範囲に含める。

## 4. 方針

グリッドが描けないこと自体は受け入れ、**表の中に案内を出す**。

`#sheetMsg` は印刷 CSS（`files/index.html:330`）で `display:none` になるため、
紙には出ない。「グリッドの無い紙が黙って刷られる」ことを止めるには、
案内が**表そのものの中**にある必要がある。

案内は表の一部なので画面にも出る。設定を変えた本人は配置表タブでその場で気づく。

## 5. 技術制約

`~/claude-lessons/lessons.md` から、この設計に効くものを引く。

- **印刷 CSS は `.note` と `.hint` を `!important` で消す**（`files/index.html:330`）。
  案内行にこの 2 つのクラス名を使ってはいけない。
- **背景色は既定で印刷されない**（2026-08-23 の教訓）。案内を背景色で目立たせる案は
  紙で消える。罫線と文字だけで表現する。`print-color-adjust:exact` を足す選択肢もあるが、
  プリンタドライバ側が優先しうるので採らない。
- **`@media print` の中の宣言は `getComputedStyle()` で読めない**（2026-08-30 の教訓）。
  印刷時の見え方を検証するときは `document.styleSheets` を走査し、
  `CSSRule.MEDIA_RULE` かつ `conditionText` に `print` を含むルールを探す。
- **非表示タブでは `getBoundingClientRect()` が 0 を返す**（2026-08-23 の教訓）。
  高さを測る検証の前に `switchTab('sheet')` を呼ぶ。
- **PWA は cache-first**（2026-07-09 の教訓）。`files/index.html` を変更したら
  `files/sw.js` の `CACHE_VERSION` を `"v23"` から `"v24"` に上げる。
- **`const order=` はファイル内に 2 か所ある。** `gridRows()` の 14 列の並び
  （`files/index.html:2818` 付近）のほかに、ロットの並べ替え（`files/index.html:1566`）にも
  同名の定数がある。実行計画で文字列置換を書くときは、一意に決まる行全体で指定する
  （2026-08-30 の教訓「replace の曖昧一致」）。

### 高さの予算

印刷は `.sheet{zoom:1.4}`。A4 横・余白 8mm の印刷領域は 733.2px、
現在の表は 1.4 倍で用紙の約 90.7% を使う。残りは約 68px（実寸換算 約 49px）。

- 経路 2-1 / 2-2 ではグリッド 8 行が丸ごと無いので、表はむしろ大幅に短い。余裕は十分。
- 12 列以上のケースはグリッドが出るので、案内 2 行ぶん（約 28px 実寸 → 印刷 39px）が加わり
  約 96% になる。`PRINT_H_LIMIT`（98%）の内側。
- 表示設定で文字を大きくしている場合は既存の `fitSheetText()` の警告
  （「文字が大きくて印刷が1ページに収まりません」）がそのまま働く。新たな仕掛けは要らない。

### 幅の制約

表は 672px 固定。10px の全角なら 1 行あたり約 67 文字。
事実＋原因＋直し方を書くと 80 文字を超えるため、**案内は 2 行に折り返す**。
`white-space:normal` と `line-height:1.3` で組む。

## 6. 設計

### 6-1. `gridRows()` は理由をデータで返す

戻り値を `{html, anchors}` から `{html, anchors, warn}` に広げる。
`warn` は文言を持たず、何が起きたかだけを持つ。`warn` が `null` なら案内は出ない。

```js
// 下段の先頭が見つからない（掲載先が bottom のエリアが1つも無い）
{kind:"none"}
// 先頭エリアの列が 11 本に足りない
{kind:"short", area:"PC横", cols:2}
// 先頭エリアの列が 12 本以上ある（グリッドは描ける）
{kind:"extra", area:"メイン", cols:12}
```

`kind:"extra"` のときだけ `html` は空でない。判定を `html` の空判定に寄せてはいけない。

現在ある 2 つの早期 return（`!sp` と `order.some(...)`）にそれぞれ `warn` を足し、
末尾の正常 return では `sp.cols.length>11` を見て `"extra"` か `null` を返す。

**様式が要求する列数はマジックナンバーにしない。** `order` から導く。

```js
const SHEET_GRID_COLS = order.filter(o=>!o.lab).length;   // = 11
```

`order` を将来変えたときに、判定と案内が自動で追随する。

### 6-2. `renderSheet()` が案内行を組む

`gridRows()` の呼び出し直後に、`warn` から `<tr>` を 1 本作って差し込む。

```js
const grid=gridRows();
if(grid.warn && grid.warn.kind!=="extra") rows+=gridNoticeRow(grid.warn);
rows+=grid.html;
if(grid.warn && grid.warn.kind==="extra")  rows+=gridNoticeRow(grid.warn);
```

- `"none"` / `"short"` は**グリッドがあった位置**（下段の下）に置く。
  紙を見た人が「ここに図があるはずだ」と分かる位置に案内が出る。
- `"extra"` はグリッドが描けているので、**グリッドの下**に置く。

文言を組む `gridNoticeRow(warn)` は独立した関数にする。
`renderSheet()` は既に長く、文言を直接埋めると読みにくくなる。

### 6-3. マークアップと CSS

```html
<tr class="gnote"><td colspan="14">※ ……</td></tr>
```

クラス名は `gnote`。既存の `note-row` / `snote` とも、印刷で消される
グローバルの `.note` / `.hint` とも衝突しない。

```css
.sheet tr.gnote td{border:0;background:transparent;
                   text-align:left;white-space:normal;
                   font-size:10px;line-height:1.3;color:#000;padding:4px 2px}
```

- `border:0` — 帳票の罫線を増やさない。案内は枠の外の但し書きとして読ませる
- `color:#000` — `snote` の `#333` ではなく黒。紙で薄くならないようにする
- 背景色は使わない（5 章の制約）

## 7. 文言

### 7-1. `kind:"short"`

> ※ メインエリアの配置図はこの表に出ていません。下段の先頭「PC横」は 2 列で、表の様式（11 列）に足りません。設定タブの「配置マス」で、11 列以上のエリアを下段の先頭行にしてください。

エリア名と実際の列数を埋めるので、「メインを上に動かした」場合も
「メインの列を減らした」場合も、同じ 1 文で原因が分かる。

### 7-2. `kind:"none"`

> ※ メインエリアの配置図はこの表に出ていません。掲載先が「下段」のエリアがありません。設定タブの「配置マス」で、いずれかのエリアの掲載先を bottom にしてください。

### 7-3. `kind:"extra"`

> ※「メイン」の 12 列目以降はこの表に出ていません。表の様式は 11 列です。

`「メイン」` の部分は先頭エリア名を実際の値から埋める。

### 7-4. 「メインエリア」を固定で書くことについて

7-1 と 7-2 は「メインエリア」を文言に固定で持つ。ユーザーの指定による。
将来メインを改名した場合、実在しない名前を指す文になる。
現場でメインの呼び名が変わる見込みは薄いという判断で受け入れる。
7-3 は先頭エリア名を実際の値から埋めるので影響を受けない。

## 8. 今回の範囲外

- **下段の全欄に「※メイン」注釈が付く現象。** 基準エリアが `PC横` に変わると
  メインのロットが「よそ」扱いになるため付く。基準エリアの定義どおりの正しい挙動なので直さない。
- **グリッドの一般化**（11 列ハードコードの撤廃）。段番号列の位置・幅・引き出し線の終点など
  紙の様式そのものを作り直す大改修になる。今回は案内で留める。
- **設定側で反映を拒む案。** 経路 2-2（倉庫のレイアウトが実際に変わって列数を変える）まで
  拒むと設定を更新できなくなるため採らない。
- **通路の位置がずれている場合。** `order` は先頭（`c:0`）と 11 本目（`c:10`）を
  通路として灰色に塗る。先頭エリアがちょうど 11 列でも通路がこの位置に無ければ、
  グリッドは描けるが塗り分けだけが実態と食い違う。同じハードコードに由来する
  無言のずれだが、パレットが消えるわけではないので今回は扱わない。

## 9. 検証の方針

このプロジェクトにはテストランナーが無い。検証は `javascript_tool` で
検証スクリプトを実行し、返り値を確認する形で行う。

2026-08-30 の教訓に従い、**実行計画に埋め込む検証スクリプトは、計画を確定する前に
改修前のコードに対して一度走らせる**。参照する `getElementById` /
`querySelector` の引数は、単独で grep して実在を確かめる。

確認する項目:

1. 経路 2-1（並べ替え）で `tr.gnote` が 1 本出て、文中に `PC横` と `2 列` が入る
2. 経路 2-2（列 11→10）で `tr.gnote` が 1 本出て、文中に `メイン` と `10 列` が入る
3. 掲載先を全部 `top` にして `kind:"none"` の文が出る
4. 列 11→12 で、グリッド（`tr.grow` 7 行）**と** `tr.gnote` の両方が出る
5. 既定設定では `tr.gnote` が 1 本も出ない（恒真でないことの確認）
6. 既定設定の回帰: 改修前後で `.sheet` の `innerHTML.length` と
   `tr.grow` の本数が一致する
7. 印刷で案内が消えないこと。`document.styleSheets` を走査して
   `@media print` に `.gnote` を隠す宣言が無いことを確認する
   （`getComputedStyle` では読めない）
8. 高さ: `switchTab('sheet')` の後に `.sheet table` の高さを測り、
   12 列ケースで `PRINT_H_LIMIT` を超えないこと
