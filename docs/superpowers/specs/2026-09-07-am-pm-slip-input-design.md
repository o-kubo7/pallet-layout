# 朝・昼別の伝票入力と配置管理 — 設計書

- 作成: 2026-09-07
- 対象: `files/index.html`（単一ファイル PWA）、`files/sw.js`（CACHE_VERSION）、`files/README.md`
- 状態: 設計承認済み。未実装

---

## 1. 背景と目的

現在のアプリは、荷物入力・配置結果・手動調整を1組だけ持ち、`あさ／ひる` は配置表に丸を付ける見出し情報にすぎない。実運用では同じ搬入日に朝便と昼便の両方について、入力、配置編集、配置表の作成が必要である。

また、入力元は事前にFAXされる発送伝票である。1枚の伝票に複数品目が記載されるため、現在の平坦な荷物行では伝票単位の入力完了を確認できない。手元のFAX枚数と入力済み枚数を照合し、未入力の伝票を発見できる構造へ変更する。

スマホ版は荷物ごとのカード表示で一覧性が低いため廃止し、PCと同じ1品目1行の表形式に統一する。

## 2. スコープ

### 2-1. 実装するもの

- 入力・配置編集・配置表タブの `あさ／ひる` 切替
- 朝と昼で独立した伝票、配置結果、手動調整
- 1伝票に複数品目行を持つ入力構造
- FAX受領済み伝票と仮伝票の区別
- FAX伝票枚数と仮伝票件数の表示
- スマホのカード表示廃止と、横スクロール不要の表形式
- 既存の平坦な入力・配置保存データから新形式への移行
- 入力変更後の古い配置結果・配置表の誤使用防止

### 2-2. 実装しないもの

- 複数搬入日の履歴管理
- FAX画像のアップロード、OCR、自動照合
- 端末間同期、サーバー保存、バックアップ／復元機能
- 仮伝票と到着FAXの自動マッチング
- 朝と昼の配置表を1回の操作でまとめて印刷する機能

## 3. 採用方式

### 3-1. 単一画面＋朝・昼別状態

既存の表、配置編集、配置表のDOMは1組のまま維持し、内部状態を朝と昼に分ける。選択中の時間帯を `activeTiming` とし、切替時に現在側を保存してから対象側を同じDOMへ描画する。

画面を朝用・昼用に複製する方式は採用しない。単一HTML内で要素IDが重複し、既存の多数の `getElementById`、イベントハンドラ、描画処理を二重化するためである。切替時にページを再読み込みする方式も、フォーカス・スクロール・編集中の状態を失うため採用しない。

### 3-2. 状態の境界

共通状態:

- 搬入日
- 品目マスタ
- 配置マス設定
- 表示設定、配置編集の表示設定

朝・昼別状態:

- 伝票と仮伝票
- 配置結果
- 手動調整
- 配置結果を作った入力の指紋

選択中の時間帯はメインタブ間で共通にする。入力タブで昼を選んで配置編集または配置表へ移動した場合も、昼の結果を表示する。

## 4. データモデル

概念上の保存構造は次のとおりとする。実装時の変数名は既存命名に合わせてよいが、責務の境界は維持する。

```text
schedule
├─ version
├─ date
├─ activeTiming: am | pm
└─ shifts
   ├─ am
   │  ├─ slips[]
   │  ├─ result
   │  ├─ manual
   │  └─ resultFingerprint
   └─ pm
      ├─ slips[]
      ├─ result
      ├─ manual
      └─ resultFingerprint
```

伝票:

```text
slip
├─ id: 固定ID
├─ status: fax | provisional
└─ items[]
   ├─ id: 固定ID
   ├─ type
   ├─ name
   ├─ lot
   ├─ snp
   └─ qty
```

伝票と品目には表示順とは別の固定IDを持たせる。画面の `伝票1、伝票2…` と `仮伝票1、仮伝票2…` は現在の並び順から表示時に採番し、途中削除による内部関連の破損を防ぐ。

固定IDは端末内で一意ならよい。外部連携を行わないため、サーバー採番や伝票番号入力は導入しない。

## 5. 伝票と仮伝票

### 5-1. FAX受領済み伝票

`＋ FAX伝票を追加` で作成する。上部の `FAX伝票 n枚` に含める。1枚の伝票内に複数の品目行を追加できる。

### 5-2. 仮伝票

FAXが前日に届かない場合、事前に得られる納品情報から `＋ 仮伝票を追加` する。入力画面では `仮伝票 n` と `FAX未着` を明示し、上部の `仮 n件` に含める。FAX伝票枚数には含めない。

仮伝票も配置計算に含める。ロット欄は空欄でよく、配置表でも空欄のまま出す。配置表に `FAX未着` 等の注記は加えない。

FAX到着後は、ロットを追記していなくても `FAX受領済みにする` を実行できる。変更するとFAX伝票枚数が1枚増え、仮伝票件数が1件減る。受領状態だけでは配置内容が変わらないため、配置結果を無効化しない。

### 5-3. ロット未入力の統合規則

受領状態にかかわらず、ロットが空欄の品目は他の伝票または他の品目行と統合しない。品名が同じでも別ロットの可能性があるためである。固定の品目IDを一時的な配置単位のキーに使う。

ロットが入力されている品目は、現行どおり同じ `品名＋ロット` を1つの荷物としてまとめる。パレット数は各伝票の品目行ごとに `ceil(個数 / SNP)` してから合計し、分納時の切り上げを維持する。

## 6. 画面設計

### 6-1. 朝・昼切替

入力・配置編集・配置表の各タブ上部に同じ `あさ／ひる` 切替を置く。設定タブには置かない。選択状態は全メインタブで共通である。

配置結果がない側を開いた場合は、`ひるの配置はまだ作成されていません` のように対象時間帯を明示する。

### 6-2. 入力タブ上部

次の順に縦に配置し、すべて左寄せを基本とする。

1. 搬入日
2. `あさ／ひる` 切替
3. `FAX伝票 10枚　仮 2件` の件数表示

FAX伝票枚数は手元のFAX枚数との照合に使うため、仮伝票を加えた総数にはしない。

### 6-3. 伝票ブロック

- 見出し: `伝票 n` または `仮伝票 n`、品目件数、仮伝票の場合は `FAX未着`
- 本体: 1品目1行の入力表
- 下部左: `＋ 品目を追加`
- 下部右端: `伝票を削除`
- 仮伝票のみ: `FAX受領済みにする`
- 各品目行の右端: 行削除の `×`

伝票全体の削除は複数品目をまとめて失うため確認を出す。品目行削除は現在と同じく即時実行する。

### 6-4. スマホ

現行の `.lotcards` とカード同期処理を廃止する。PCと同じ列順の表を表示し、スマホ専用に列幅と表記を詰める。

| PC | スマホ |
|---|---|
| 種別 | 種 |
| 仕掛品／商品 | 仕／商 |
| パレット数 | P数 |
| 削除 | × |

列は `種、品名、ロット、SNP、個数、P数、削除` の7列を `table-layout: fixed` と割合幅で画面内に収める。横スクロールを設けない。編集可能な入力欄はiOS Safariの意図しないフォーカス時ズームを避けるため16pxを維持する。長い品名・ロットは入力欄内で末尾が見切れる可能性があるが、フォーカス中はキャレット移動で確認できるものとする。

320pxおよび360px幅を受入対象とし、列、ボタン、件数表示が画面外へはみ出さないことを確認する。

### 6-5. 配置表と印刷

配置表は選択中の朝または昼だけを描画する。表内の朝／昼表記は選択中の側を示す。印刷も現在表示している時間帯をA4横1枚で行い、朝と昼を一括印刷する機能は追加しない。

## 7. 入力検証と配置結果の鮮度

必須項目は品名、SNP、個数とし、ロットは受領状態にかかわらず任意とする。品名・ロット・個数がすべて空の行は空行として無視する。途中まで入力した行は現在の赤枠・メッセージ方式を引き継ぐ。

次の変更は選択中の時間帯だけ、既存の配置結果を入力に対して古い状態にする。

- 品名、種別、ロット、SNP、個数の変更
- 伝票または品目行の追加・削除

古い配置結果を表示・印刷して現物と食い違うことを防ぐため、入力指紋が配置作成時と一致しない間は、配置編集と印刷を利用不可にして `入力が変更されています。あさの自動配置を作成し直してください` と案内する。入力を元の値へ完全に戻して指紋が一致した場合は、元の結果と手動調整を再利用できる。

仮伝票からFAX受領済みへの状態変更は配置入力を変えないため、入力指紋に含めず結果を無効化しない。ロットを後から入力した場合は統合単位が変わり得るため、入力指紋が変わり再配置を要求する。

朝の入力変更で昼の結果や手動調整を無効化してはならない。

## 8. 保存と旧データ移行

### 8-1. 保存

入力変更時および朝・昼切替前に現在側を保存する。切替後は対象側の伝票、結果、手動調整を同じDOMへ描画する。

現在の `saveData()` / `loadData()` の例外処理とメモリフォールバックを維持する。保存できない環境では `この環境では保存されません` を表示する。

### 8-2. 移行

保存形式にスキーマバージョンを持たせる。新形式がない初回起動時だけ、既存の平坦な荷物行を次の規則で変換する。

- 旧1行を `FAX受領済み伝票1枚＋品目1行` にする
- 旧 `head.timing` が `あさ` なら朝、`ひる` なら昼へ入れる
- 反対側は空で開始する
- 既存の配置結果・手動調整・入力指紋も同じ時間帯へ移す
- 変換成功後に新形式を保存し、以後は旧形式を読み直さない

旧1行を1伝票とするのは、現在のパレット数計算が行ごとに切り上げており、その意味を壊さないためである。

不正または部分的な保存データがある場合はアプリ全体を停止させず、読み取れない側だけを空状態へ戻して画面内に案内を出す。共通設定と反対時間帯の正常データは維持する。

## 9. 技術制約

`~/claude-lessons/lessons.md` を読み、PWAキャッシュ、非表示タブの寸法計測、レスポンシブで複製された入力面へのフォーカス、検証フィクスチャの教訓を反映した。

### 9-1. Web Storage

`localStorage` は主要なPC・スマホブラウザで広く対応する。Web Storageは同期APIであり、一般に `localStorage` は1オリジンあたり約5MiBが上限である。今回の伝票文字データは十分小さいためIndexedDBへ移行せず、小さなJSONを現在と同じ入力イベント単位で保存する。

- MDN: https://developer.mozilla.org/en-US/docs/Web/API/Web_Storage_API
- MDN Storage quotas: https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria
- Can I use: https://caniuse.com/namevalue-storage

保存は既定ではベストエフォートであり、端末の容量不足、ブラウザ設定、ユーザー操作で削除され得る。容量超過・アクセス拒否は例外として扱い、現在の保存失敗表示を維持する。プライベートブラウズでは終了時にデータが消えるため、永続保存を保証しない。

### 9-2. iOS Safari／ホーム画面Webアプリ

iOS 17.2以降でも、Safariからホーム画面Webアプリを作る際にコピーされるのはCookieであり、`localStorage` など他のWebサイトデータはコピーされない。Safariとホーム画面アプリを別の保存領域として扱い、入力を同じ起動方法に統一する運用を前提とする。

- WebKit: https://webkit.org/blog/14787/webkit-features-in-safari-17-2/

ホーム画面WebアプリはWebKitのストレージ割当上、ブラウザアプリと同じオリジン／全体クォータ扱いになるが、保存保証そのものではない。

- WebKit storage policy: https://webkit.org/blog/14403/updates-to-storage-policy/

### 9-3. Android Chrome／WebView

通常のAndroid Chrome PWAはWeb Storageを利用できる。将来ネイティブアプリ内のAndroid WebViewで開く場合、DOM StorageはWebViewホスト側で明示的に有効化する必要があり、`WebSettings.setDomStorageEnabled` の既定値は `false` である。本変更ではWebViewラッパーを作らない。

- Android Developers: https://developer.android.com/reference/android/webkit/WebSettings.html

### 9-4. 権限

カメラ、ファイル、通知、バックグラウンド動作等の新しいAPIは使わないため、権限要求は追加しない。保存は従来どおり同一オリジンのWeb Storageだけを使う。

### 9-5. オフラインとService Worker

既存Service Workerのプリキャッシュを維持する。`files/index.html` を変更するため、リリース時に `files/sw.js` の `CACHE_VERSION` を上げる。ローカル検証では旧キャッシュを見ないようService Workerの登録解除とCache Storage削除を行う。

### 9-6. 非表示タブの寸法計測

配置表は非表示中に `getBoundingClientRect()` を呼ぶと幅0になる。朝・昼切替で非表示側を事前描画せず、配置表タブが可視になった時点と印刷直前に、選択中の側を再描画して倍率と引き出し線を計算する。

### 9-7. 入力面の一本化

現行はPCテーブルとスマホカードの2つのDOMを持ち、可視側を判定してフォーカスしている。本変更でカードを廃止して入力DOMを1組にするため、入力同期と非表示側への誤フォーカス経路を削除する。スマホでも同じ表の入力欄を直接フォーカスする。

## 10. エラー処理

- 保存失敗: メモリ保持へ切り替え、保存されない旨を継続表示する
- 不正な保存データ: 対象時間帯だけ空状態へ戻し、共通設定と正常側を維持する
- 入力不完全: 入力タブに留まり、該当欄を赤枠表示して最初の欄へフォーカスする
- 古い配置結果: 配置編集と印刷を止め、対象時間帯の再配置を案内する
- 配置容量超過・退避残り・配置表の欄不足: 現行の警告を時間帯ごとの結果に対して維持する

## 11. 検証計画

### 11-1. 状態と計算

- 朝と昼の伝票、仮伝票、配置結果、手動調整が相互に混ざらない
- メインタブを移動しても選択中の時間帯が維持される
- 仮伝票をロット空欄のまま受領済みに変更できる
- 受領変更でFAX枚数と仮件数だけが正しく増減し、配置結果が古くならない
- ロット空欄の品目同士が、同じ品名でも統合されない
- ロット入力後は同じ `品名＋ロット` の現行統合規則が働く
- パレット数が伝票品目行ごとに切り上げられてから合計される
- 朝の入力変更で昼の結果・手動調整が破棄されない
- 入力指紋不一致時に古い配置編集と印刷を利用できない
- 入力を元へ戻した場合に一致する保存結果を再利用できる

### 11-2. UI

- 入力タブ上部が `搬入日 → あさ／ひる → FAX伝票枚数・仮件数` の順で左寄せになる
- 伝票削除ボタンが伝票下部の右端にある
- PCとスマホで1品目1行の同じ列順になる
- 320px／360px幅で横スクロールと画面全体の横はみ出しが発生しない
- スマホの入力欄が16pxを維持し、フォーカス時に意図しないページズームが起きない
- 長い品名・ロットでも他列や削除操作を押し出さない
- 入力不完全時の赤枠、スクロール、ソフトウェアキーボード追随が動く

### 11-3. 保存・PWA・印刷

- 旧保存データを保存タイミング側へ一度だけ移行できる
- 旧手動調整を同じ時間帯で復元できる
- リロード後およびオフライン再起動後に朝・昼両方を復元できる
- Service Worker更新後に新しい画面が配信される
- 朝・昼それぞれの配置表がA4横1ページに収まる
- 印刷対象が現在表示中の時間帯だけになる

### 11-4. 対象環境

- デスクトップ Chrome／Edge相当
- iPhone Safariおよびホーム画面Webアプリ
- Android Chromeおよびホーム画面PWA

最終的な指操作、キーボード、印刷は実機で確認する。自動検証ではタブを明示的に可視化してから寸法を測り、存在する要素・セレクタだけを使用する。

## 12. 完了条件

1. 朝・昼それぞれで伝票入力、自動配置、手動編集、配置表印刷が独立して完了できる。
2. 手元のFAX枚数と画面のFAX伝票枚数を照合でき、仮伝票数が混ざらない。
3. FAX未着時も仮伝票で配置を準備し、ロット空欄のまま受領済みに変更できる。
4. スマホでカードを使わず、320px幅でも全入力列を横スクロールなしで操作できる。
5. 旧データを失わず新形式へ移行でき、オフライン再起動後も復元できる。
6. 入力変更後の古い配置編集・配置表を誤使用できない。
