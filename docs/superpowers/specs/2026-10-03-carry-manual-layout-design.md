# 手動調整を残して、伝票の変更分だけ配置し直す 設計書

作成日: 2026-10-03

## 1. 目的

配置を手で調整したあとに FAX 伝票が届き、入力タブで伝票を直すと、
「▶ 自動配置を作成」で手動調整がすべて破棄されていた。
直した荷物以外は手で置いた位置のまま残し、直した荷物だけを扱えるようにする。

## 2. 原因（改修前）

- 手動調整は伝票の指紋（`fingerprintFor()`）付きで `activeShift().manual` に保存される。
- 伝票を1文字でも直すと指紋が変わり、保存した配置は「今の入力と合わない」扱いになる。
- `runFromButton()` は「手動調整を破棄して自動配置し直します」と確認し、
  `run()` が空の盤から全部を置き直して `manual=null` にしていた。
- ただし `manual` 自体は `run()` まで消えずに残っているので、前の配置は取り出せる。

## 3. 決定事項

| 項目 | 決定 |
| --- | --- |
| 確認画面 | 手動調整があるときは3択＋キャンセル（`#carryDlg`）。「変更分だけ自動配置」（既定）／「変更分を退避スペースへ」／「すべて自動配置し直す」 |
| 案A（`place`） | 増えた分・新しい荷物は、まずその荷物だけの列の空きに足し（`topUpLot`）、残りを `place()` で空きへ置く。入りきらない分は今までどおり退避へ |
| 案B（`stash`） | 増えた分・新しい荷物は倉庫に置かず、全部退避スペースへ。人が手で運ぶ |
| 荷物の引き当て | 元の品目行のID（`lot.itemIds`）が重なれば同じ荷物。無ければ品名＋ロット（`lotKey`）。ロット番号を直しても外れない |
| 種別が変わった荷物 | 引き当てない（前の位置は空き、新しい荷物として置く）。置き場所の区分が変わるため |
| 減った分の空け方 | **最後に積んだ所から**。退避にある分→倉庫を自動配置の順（`placementColumns`）の逆にたどる。同じ列では後ろの fill から減らす |
| 削除された荷物 | そのマスを空ける |
| 「半」の手動指定 | ロットIDを付け替える。減らした列の指定は消す（どのマスに付いていたか分からなくなるため） |
| 退避の中身 | 引き当たった荷物の分は引き継ぐ |
| 引き継げないとき | スペース設定が変わった・配置不可のマスと重なる → すべて作り直し、その旨を知らせる |
| 保存 | 引き継いだ盤は手で置いた位置を含むので `manual` として残す（次の伝票修正でも引き継げる） |
| 元に戻す（Undo） | 今までどおり再配置で履歴を捨てる |

## 4. 「上から空ける」にしなかった理由

列の中身は「どの荷物が何枚」（`col.fills=[{id,count}]`）だけを持ち、マスの位置は
描画時に `cellsOf()` が詰める順で決まる。同じ列の中で特定のマスを選んで空けることは
データの形として表せない（手でマスを動かしたときも同じ）。
画面上の位置を正確に指定するにはマスの位置を保存する形への作り替えが要り、
盤・紙・保存データの全部に及ぶ。減った分のパレットはそもそも届かないので、
どのマスが空くかより荷物のかたまりが崩れないことを優先し、「最後に積んだ所から」とした。

## 5. 書き足し（配置図のテキスト編集）

書き足しの署名（`sheetEditSigFrom`）は配置そのものを含むので、配置が変われば今までどおり外れる。
今回の対象外。

## 6. テスト

`tests/carry-layout.test.js`。小さな倉庫で `carryOver()` を動かし、
そのまま残る・減る・増える・新しい荷物・削除・ロット番号変更・古い保存データ・種別変更・
あふれ・退避の引き継ぎ・スペース設定の変更・「半」の付け替えを確かめる。
