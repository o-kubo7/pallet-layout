# パレット配置図 自動作成

翌日搬入するパレットの仮置き配置図を自動作成するWebアプリ（PWA）。
サーバー・データベース不要。すべてブラウザ内で動作します。

## ファイル構成

```
index.html      アプリ本体（これ1つで動きます）
manifest.json   ホーム画面追加用の設定
sw.js           オフライン対応（Service Worker）
icon-192.png    アイコン
icon-512.png    アイコン
```

## 画面

| タブ | 何をするところ |
|---|---|
| 入力 | 搬入日と、朝／昼それぞれの伝票・品目（品名／ロット／SNP／個数）を入れる |
| 配置編集 | 自動配置の結果をブロック図で見て、手で直す |
| 配置表 | 手書き用紙と同じ様式の表。印刷はここから |
| 設定 | 品目マスタ（品名→SNP）、スペース設定、表示設定 |

### 朝／昼の伝票入力と配置

- 入力・配置編集・配置表の朝／昼切替は共通です。伝票と配置・手動調整は時間帯ごとに保存します。
- FAX1枚につき「＋ FAX伝票を追加」で伝票を作り、同じFAXの2品目目以降は伝票内の「＋ 品目を追加」で行を増やします。
- 「FAX伝票 ○枚」は受領済みの伝票数、「仮 ○件」はFAX未着の仮伝票数です。品目行の数とは異なります。
- FAX未着の荷物は「＋ 仮伝票を追加」で入力します。ロット空欄のまま自動配置でき、届いたら「FAX受領済みにする」で件数を切り替えられます。受領操作だけでは配置は変わりません。
- 空ロットの品目は、品名が同じでも別々に配置され、統合されません。
- 「入力をクリア」と印刷は選択中の時間帯だけに作用します。
- 入力変更後は再配置が必要です。変更前の配置は編集・印刷できませんが、入力を元に戻すと保存済みの配置・手動調整を復元できます。

### 配置編集でできること

- **ロットを移動** … 同じロットのマスを選び、別の列へ運ぶ
- **なぞって選ぶ／外す** … マスの上を指でなぞるとまとめて選べる。
  選択の中をなぞると外れ、選択の外へ出すと運ぶ。1つ前のなぞりは1タップで取り消せる
- **退避スペース** … 倉庫に実在しない、画面の中だけの置き場。
  荷物が多い日に一旦逃がして、倉庫の側を空けてから並べ直せる。
  位置は右上／左上／下から選べる（右利き・左利き）
- **通路を編集** … 列を「通路（空きのまま）」に切り替える

退避スペースに荷物が残っていると**配置表には出ません**。残っているあいだは
配置編集タブに警告が出るので、印刷の前に倉庫へ戻してください。

## GitHub Pages で公開する手順

1. GitHubで新しいリポジトリを作る（例: `pallet-layout`）
2. このフォルダの中身をすべてリポジトリの**直下**にアップロード
   （`index.html` がトップに来るようにする。フォルダごと入れると動きません）
3. リポジトリの **Settings** → 左メニューの **Pages** を開く
4. **Source** で `Deploy from a branch` を選ぶ
5. **Branch** を `main`、フォルダを `/ (root)` にして **Save**
6. 1〜2分待つと、Pagesの画面にURLが表示される
   → `https://<ユーザー名>.github.io/pallet-layout/`

## スマホのホーム画面に追加する

- **Android (Chrome)**: 上記URLを開く → メニュー → 「アプリをインストール」
- **iPhone (Safari)**: 上記URLを開く → 共有ボタン → 「ホーム画面に追加」

追加後はオフラインでも起動できます。

## アプリを更新するときの手順（重要）

キャッシュが残って古い版が表示されるのを防ぐため、**必ず2つセットで**行います。

1. `index.html` を修正する
2. `sw.js` の6行目付近にある `CACHE_VERSION` の数字を上げる
   ```js
   const CACHE_VERSION = "v31";   // 次の更新では "v32" に変更
   ```
3. 両方をコミット・プッシュ

次にアプリを開くと画面下部に「新しいバージョンがあります」と表示され、
「更新する」を押すと最新版に切り替わります。

## データの保存について

ブラウザのlocalStorageに自動保存されます（端末ごと）。

- 品目マスタ / 朝・昼それぞれの伝票入力と配置結果 / 共通の搬入日
- スペース設定（画面で変えた内容も保存されます）
- 朝・昼それぞれの配置編集での手動調整
- 表示設定（マスの大きさ、案内の表示、退避スペースの位置 ほか）

保存データはブラウザのサイトデータ（localStorage）を削除すると消えます。またPCとスマホでは別々に保存されます。

荷物の入力や列の構成が変わると、その条件に合わない保存済み配置・手動調整は表示されません。
再配置するか、入力・列の構成を元に戻してください。

`index.html` 内の `DEFAULT_SPACES` を変更したときは、`SPACES_SAVE_VERSION` を
上げてください。保存済みの設定と手動調整が初期値に戻り、更新した既定値が
既存の端末にも届きます。

## 倉庫レイアウトを恒久的に変更する場合

`index.html` 内の `DEFAULT_SPACES` を編集します。

```js
{name:"メイン", zone:"near", orient:"v", block:3, align:"top", sheet:"bottom", cols:[
   {h:6,aisle:true},{h:7},{h:7}, ...]}
```

| 項目 | 意味 |
|---|---|
| `name` | エリア名。配置図の表の欄にも出ます |
| `zone` | `near`=倉庫内 / `far`=倉庫外 / `stash`=退避スペース（倉庫には無い置き場） |
| `orient` | `v`=縦列 / `h`=横行 |
| `block` | 1品目が使える最大列数（メインは3列で1ブロック） |
| `align` | `top`=上詰め |
| `sheet` | 配置図の表のどこに載せるか。`top`=上段 / `bottom`=下段 / `over`=あふれブロック（未実装のため置きません） / `none`=載せない |
| `cols` | 各列の高さ。`aisle:true` は通路。`row` / `off` は実際の位置に合わせて描くときだけ使います |

`zone:"stash"` のエリアは自動配置では使われず、配置図の表にも載りません。
スペース設定の画面にも出ません（区分が `near` / `far` しか受け付けないため）。
